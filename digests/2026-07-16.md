## Executive summary

Three entries cleared today’s evidence bar. The strongest is the [DAD Design OSCAR + PENDA ecosystem](https://github.com/DADDesign-Projects/OSCAR_P01A01): a current product-family architecture spanning a custom STM32H743 processor board, separate PCM3060/PGA2310 audio board, FreeCAD mechanics, firmware/flashing infrastructure and a simpler Daisy Seed carrier. ### 1) [DAD Design OSCAR + PENDA ecosystem](https://github.com/DADDesign-Projects/OSCAR_P01A01) — **STRONG_PASS**

**Lane:** Standalone multi-board effects-pedal platform family

#### Technical summary

The ecosystem has two complementary product paths:

- [OSCAR P01A01](https://github.com/DADDesign-Projects/OSCAR_P01A01) is the full custom platform. Its [processor board](https://github.com/DADDesign-Projects/OSCAR_PROC_01) uses an STM32H743 at 480 MHz, 64 MB SDRAM, 32 MB dual-QSPI flash, USB, TRS/USB MIDI, a 2.4-inch TFT, four encoders and two switches. Its separate [audio board](https://github.com/DADDesign-Projects/OSCAR_AUDIO_01) uses a PCM3060 24-bit stereo codec and PGA2310-controlled analogue dry path, with separate analogue/digital supplies from 12 V.
- [PENDA](https://github.com/DADDesign-Projects/PENDA-Hardware) is the lower-risk Daisy Seed carrier: mono audio I/O, two footswitches, four push encoders, three pots, ST7789 display, MIDI input and a fully analogue dry path. Its [software](https://github.com/DADDesign-Projects/PENDA-Software) runs current FORGE effects on the Daisy STM32H750/PCM3060 module.

OSCAR version 1.0 was released on 2026-07-13. Both branches share the FORGE software approach and dedicated flashing/boot infrastructure.

#### Why it matters

This is not merely two pedal PCBs. It is a reusable product family: PENDA covers fast module-based development, while OSCAR supplies the migration path to a controlled processor/audio architecture with more memory, explicit board partitioning and modifiable mechanics. That makes it unusually useful for developing a compact pedal first, then reducing module dependence without throwing away the software model.

#### Implementation highlights

- Separate high-speed processor and low-noise audio boards on OSCAR.
- PCM3060 stereo codec, PGA2310 analogue wet/dry control and multiple low-noise supply domains.
- STM32H743 with external SDRAM and dual QSPI rather than a soldered compute module.
- USB audio/MIDI and TRS MIDI, display, encoders, footswitches and preset/UI infrastructure.
- FORGE modular DSP framework with delay, reverb, chorus, flanger, tremolo, vibrato and phaser examples.
- Bootloader/server workflow that stores ELF/resources in QSPI and copies applications to RAM at startup.
- PENDA provides a smaller, buildable Daisy carrier with a mature active software package.

#### Hardware and electronics notes

**Hardware modifiability:** OSCAR processor and audio boards contain editable KiCad 9 schematic/PCB projects, hierarchical sheets, PDF schematics and STEP models. The root project contains FreeCAD mechanical material and hardware/firmware submodules. PENDA contains editable KiCad 8 schematic/PCB source and Gerber/drill fabrication outputs. Hardware repositories use MIT; OSCAR/PENDA software uses Apache-2.0. A clean revision-locked BOM, placement package and production-test/calibration document were not independently verified.

The highest engineering risk is the OSCAR board-to-board partition. The 200 MHz SDRAM and 120 MHz QSPI interfaces need stackup, length, return-path and connector analysis. On the audio board, verify codec clocking, analogue/digital current return, PGA2310 mute behaviour, dry/wet gain matching and 12 V conversion noise. The stated isolated domains should not be assumed galvanically isolated without tracing the power architecture. PENDA’s analogue dry path and shared Daisy module reduce digital risk but still need input protection, guitar-level impedance, relay/bypass transient and codec headroom measurements.

#### Platform relevance

- **Very high:** reusable standalone pedal product family.
- **Very high:** multi-board hardware adaptation and product-tier migration.
- **High:** user-interface, preset, flashing and resource-management reuse.
- **High:** commercial derivative potential under permissive licences.

#### Adaptation ideas

1. Use PENDA for algorithm/UI prototyping, then port unchanged FORGE modules to OSCAR.
2. Define a versioned electrical/mechanical interface between processor, audio and future control boards.
3. Add balanced line, high-impedance guitar and synthesizer-level audio-board variants.
4. Publish automated factory tests for SDRAM/QSPI, controls, MIDI, codec gain/phase, THD+N and dry/wet muting.
5. Repackage OSCAR into compact, extended and desktop multi-effect products using the FreeCAD source.

#### Quick engineering assessment

**Promote as the ecosystem.** It offers rare architectural depth and genuinely editable electronics. Before fabrication, freeze an exact repository/submodule revision, regenerate all BOM/PnP outputs and validate the high-speed memory and mixed-signal partitions against the real stackup.

#### Caveats / verification gaps

- The current OSCAR release is very recent and has limited independent build history.
- Prototype/gallery evidence exists, but no independent production run was found.
- Complete BOM/PnP and factory-test outputs were not verified at repository root.
- Audio performance, EMI and high-speed timing margins are project claims or unresolved engineering work, not reproduced measurements.

### 2) [bkshepherd/DaisySeedProjects hardware family](https://github.com/bkshepherd/DaisySeedProjects) — **PASS**

**Lane:** Standalone Daisy Seed pedal hardware family

#### Technical summary

This maintained repository combines one software abstraction layer with three physical pedal targets: a feature-rich 125B SMD board, a compact 1590B SMD board and a hand-buildable 1590B through-hole board. The 125B revision provides buffered stereo input/output, relay true bypass with anti-pop hardware mute, TRS MIDI in/out, OLED, encoder, six pots, two footswitches, two LEDs and standard centre-negative 9 V power.

The repository has 601 commits and 16 releases; version 1.6.0 was published on 2026-06-10, after its earlier 2026-05-22 mine entry. Today’s promotion is specifically the separately verified hardware family rather than another firmware-only feature recap.

#### Why it matters

The project supplies product-size choices without fragmenting the firmware. It is directly useful for Denys’s compact/full multi-delay pedal work: one can test the same DSP on a through-hole prototype, a compact 1590B product and a higher-control-count 125B product.

#### Implementation highlights

- Three enclosure/assembly variants sharing a hardware abstraction layer.
- Editable KiCad schematic and PCB source.
- Gerbers and JLCPCB assembly files for the current 125B revision.
- Tayda drilling template and photographed finished pedals/boards.
- Stereo buffered audio, MIDI, OLED, controls and relay bypass.
- Hardware anti-pop mute added after documented earlier relay-pop behaviour.
- Current effect framework and releases, rather than abandoned example firmware.

#### Hardware and electronics notes

**Hardware modifiability:** editable KiCad projects are documented for the pedal variants; Gerbers and assembly outputs are present; enclosure drilling source/template and build instructions are present. Finished hardware and multiple revisions are documented. Root MIT licensing covers the repository. A parametric enclosure model, formal analogue measurements and production-test fixture were not verified.

The useful analogue details are the buffered stereo path, relay bypass and practical 9 V pedal supply. Audit input impedance, overvoltage/ESD, codec clipping level, rail noise, output drive and bypass-state DC offsets. The anti-pop mute is a welcome revision, but click performance should be measured over power-up, firmware crash, relay timing and asymmetric source/load conditions.

#### Platform relevance

- **Very high:** compact and extended programmable pedals.
- **Very high:** Denys’s Daisy-based multi-delay hardware planning.
- **High:** low-volume JLC assembly and enclosure adaptation.
- **Medium-high:** industrial redesign; Daisy Seed remains a module dependency.

#### Adaptation ideas

1. Start the compact delay in the 1590B architecture and the extended version in 125B/1590BB2.
2. Replace the OLED/encoder menu with four encoders and the restrained display hierarchy already planned.
3. Add expression input, isolated MIDI/USB protection and stereo-safe bypass choices.
4. Create revision-locked KiBot outputs and a functional production-test jig.
5. Measure input/output noise, headroom, THD+N and bypass transient before changing the analogue front end.

#### Quick engineering assessment

**Promote as a hardware-family update.** This is one of the most directly actionable finds for the existing multi-delay project. Use the latest maintained repository, not the archived GuitarML fork, and select the enclosure variant before modifying controls or I/O.

#### Caveats / verification gaps

- This repository was published previously on 2026-05-22; the 30-day window has expired and v1.6.0 is newer, but it should not be repeated again before 2026-08-15.
- The Daisy module constrains codec, memory and supply choices.
- No formal EMC or audio-performance report was found.
- Mechanical support is primarily drilling/fabrication guidance rather than a complete parametric enclosure.

### 3) [matoslav/MicroGroove](https://github.com/matoslav/MicroGroove) — **REF_PASS**

**Lane:** Pocket groovebox, sampler and acid synth

#### Technical summary

MicroGroove turns an M5Stack Cardputer-ADV into a four-track groovebox: three mono/poly 303-style synth tracks, eight switchable 808/909/sample drum lanes, microphone sampling, master resampling, user wavetables, eight projects, eight patterns and a 64-slot song chain. It runs dual-core ESP32-S3 audio at 22.05 kHz with 256-sample buffers and stores projects/samples on microSD.

The July 2026 repository includes source, binary/source flashing routes, a detailed manual, factory SD content and MIT licensing. The interface deliberately maps one function per keyboard key.

#### Why it matters

It is an unusually low-cost, immediately playable reference for squeezing a coherent groovebox into commodity hardware. The strongest reusable material is the interaction and software partition: sequencer/UI on one core, per-sample audio rendering on the other, direct microphone capture and transparent project-version migration.

#### Implementation highlights

- Three 303-style mono/poly synth tracks with slide, accent, SVF and wavetables.
- Eight 808/909/sample lanes with choking, tuning and decay.
- Live microphone sampling and master resampling.
- Versioned project format, SD content and prebuilt binary.
- Printable shell/key-label concept and current user manual.
- Explicit MIT lineage from Cardputer-Adv-Tracker; factory samples are CC0.

#### Hardware and electronics notes

**Hardware modifiability:** no editable board-level EDA is provided because the electronics are the commercial M5Stack Cardputer-ADV. The repository hardware directory currently contains documentation placeholders and explicitly says shell STL/SVG files still need to be copied in; the external MakerWorld page was blocked by the research tool. The key-label preview is present. Therefore this is a firmware/mechanical reference, not modifiable source hardware.

The 22.05 kHz sample rate limits audio bandwidth, and the small RAM pool limits sampling/polyphony. Product adaptation would need a new audio/power carrier or complete custom board. Measure microphone noise, speaker/output distortion, SD-write interference and CPU headroom under maximum synth/drum load.

#### Platform relevance

- **High:** interaction and sequencing reference for a pocket groovebox.
- **High:** fast ESP32-S3 firmware experiment.
- **Low:** reusable source electronics.
- **Medium:** custom product adaptation after a new hardware design.

#### Adaptation ideas

1. Port the UI/sequencer to RP2350, STM32H7 or Daisy with 44.1/48 kHz stereo audio.
2. Design a custom carrier with codec, MIDI, protected audio I/O, battery management and larger controls.
3. Preserve one-function-per-key operation on a purpose-built mechanical keyboard matrix.
4. Add load instrumentation and gracefully reduce voices before audio underruns.

#### Quick engineering assessment

**Reference, do not copy as hardware.** It is a fresh, well-packaged instrument and a useful software/UI study. The commercial compute device and missing in-repository shell assets prevent PASS.

#### Caveats / verification gaps

- Board-level source hardware is absent.
- External printable/assembly assets could not be independently fetched.
- Only a short public commit history exists so far.
- No independent long-session, battery, noise or full-load measurements were found.
