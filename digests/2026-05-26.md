## Published picks

### 1) `SloeComputers/picoX7` — STRONG_PASS

**Technical summary:** Raspberry Pi Pico / Pico 2 DX7-style FM synthesizer simulation with USB and physical MIDI, PIO-based 16-bit stereo I2S DAC output, 16 voices split across both Cortex-M cores, SYSEX support, YM21280 OPS simulation, YM21290 EGS simulation, DX7 patch compatibility work, and multiple UF2 build targets. fileciteturn61file0

**Why it matters:** This is a dense RP2040/RP2350 embedded synth architecture reference: dual-core voice distribution, PIO I2S, overclocking for deterministic sample rate, and a non-trivial legacy synth engine rather than another simple subtractive demo.

**Implementation highlights:**

- 8 voices per core, 16 total voices.
- PIO I2S DAC at 49096 Hz.
- UART and USB MIDI including SYSEX.
- RP2040 and RP2350 support.
- Build outputs include UF2 images for Pico, Pico 2, PWM DAC, I2S DAC, Pimoroni Pico Audio, Waveshare, and native targets.

**Platform relevance:** RP2040/RP2350, Pico SDK/CMake, PIO audio, embedded synth firmware.

**Adaptation ideas:**

- Study core partitioning for a Daisy/Teensy-style voice allocator.
- Reuse the hardware abstraction idea for multiple DAC/output boards.
- Treat the PIO I2S + overclock tradeoff as a reference for Pico audio experiments.

**Quick engineering assessment:** High novelty and high architecture value. More immediately useful as a firmware architecture reference than as a general-purpose instrument unless you want DX7-compatible FM specifically.

### 2) `risgk/digital-synth-pra32-u2` — STRONG_PASS

**Technical summary:** Raspberry Pi Pico 2 / RP2350 4-voice polyphonic MIDI sound module with chorus/delay, user programs, flash parameter storage, optional multi-timbral edition, optional panel edition, prebuilt UF2 files, USB MIDI, UART MIDI, I2S DAC support, and detailed hardware configuration notes. fileciteturn62file0

**Why it matters:** This is close to ready-to-use firmware for Pico 2 audio: practical MIDI sound module behavior, documented I2S pin mappings, flash-write click mitigation via DAC mute control, and multiple physical deployment modes.

**Implementation highlights:**

- Version shown in README: v2.14.1 dated 2026-05-13.
- Built for Pico 2/RP2350 with Arduino-Pico 5.6.0.
- Prebuilt UF2 files for Pimoroni Pico Audio Pack.
- USB MIDI and UART MIDI modes.
- I2S output with PCM510x DAC recommendations.
- PWM fallback explicitly documented as not recommended, with known click issue around 80 ms.
- Browser-based Web MIDI editor with localStorage presets and JSON import/export.

**Platform relevance:** RP2350/Pico 2, Arduino-Pico, I2S DAC boards, MIDI sound modules.

**Adaptation ideas:**

- Borrow its parameter persistence and editor workflow for small embedded synths.
- Use the I2S hardware matrix as a practical Pico 2 audio board reference.
- Study the mute-off pin strategy for flash-write click suppression.

**Quick engineering assessment:** Very high utility. Less low-level than `picoX7`, but more immediately usable and better documented for builders.

### 3) `polykit/pico-dco` — PASS

**Technical summary:** Raspberry Pi Pico digitally controlled analog oscillator with source code, schematic, PCB, up to six voices, PIO-generated accurate frequency, USB/serial MIDI, Juno-106-inspired saw/square analog oscillator core, PWM amplitude compensation, voice stacking, detune, FM, separate gate, pitch bend, and portamento. fileciteturn60file0

**Why it matters:** This is exactly the mixed analog/digital audio hardware lane the updated rules were meant to catch: not a pure DSP project, but highly relevant to embedded audio hardware and firmware co-design.

**Implementation highlights:**

- Pico PIO handles DCO timing.
- Analog oscillator produces 10 Vpp sawtooth and square signals.
- Gerbers are included.
- UF2-style install flow is documented.
- ADC inputs can modulate stacking, detune, and FM.

**Platform relevance:** RP2040, PIO timing, analog synth voice cards, MIDI-to-DCO firmware.

**Adaptation ideas:**

- Use as a reference for hybrid digital timing + analog waveform voice boards.
- Reuse PIO timing concepts for pitch-stable oscillator/control generation.
- Compare analog amplitude compensation with fully digital oscillator paths.

**Quick engineering assessment:** Strong hardware/firmware integration value. Lower direct “flash and use” value unless you build the PCB, but high architecture value for synth hardware work.

### 4) `dwhinham/mt32-pi` — PASS

**Technical summary:** Bare-metal Raspberry Pi MIDI synthesizer system based on Munt, FluidSynth, and Circle. It targets Raspberry Pi Zero 2 W, Pi 3, Pi 4, and CM4; supports I2S DACs, USB/GPIO/serial MIDI, configuration files, LCD/OLED display support, simple button/encoder control surface, MiSTer FPGA integration, RTP-MIDI, raw UDP MIDI, and embedded FTP. fileciteturn59file0

**Why it matters:** It is a strong embedded Linux alternative reference precisely because it avoids Linux: a bare-metal audio appliance with practical boot/config/control/network behavior.

**Implementation highlights:**

- Cold-boot dedicated synth appliance model.
- I2S DAC recommended for best audio quality.
- Multiple MIDI ingress routes: USB, GPIO, serial, RTP-MIDI, UDP MIDI.
- Display and simple control surface support.
- Embedded FTP for remote file access.

**Platform relevance:** Raspberry Pi bare-metal audio, MIDI appliances, headless synth systems, embedded UI/control.

**Adaptation ideas:**

- Study configuration-file and appliance boot UX.
- Reuse network MIDI/control concepts for a Pi + MCU hybrid instrument.
- Treat its hardware support matrix as a reference for robust non-desktop synth appliances.

**Quick engineering assessment:** Technically mature and architecturally valuable, but the README states further releases are unlikely, so this is a PASS/architecture reference rather than a growth project. fileciteturn59file0

### 5) `habuenav/samplerSynth` — PASS

**Technical summary:** ESP32 sample-synth library using WAV samples, polyphony, channels, velocity-style dynamic volume, I2S output via MAX98357, LittleFS sample storage, optional MIDI library integration, included compact instrument samples, and simple function-based API. fileciteturn63file0

**Why it matters:** This is not a high-end DSP engine, but it is a useful ESP32 embedded-instrument building block: small, understandable, I2S-based, and explicitly designed to avoid external sample modules such as VS1053b/SAM2695/Wav Trigger-style boards.

**Implementation highlights:**

- ESP32 I2S output through MAX98357.
- Included samples around 30–65 KB each, 32 kHz / 16-bit.
- Flash storage workflow via ESP32 Sketch Data Upload.
- Recommended maximum polyphony around 16 notes.
- Function API: `initSynth`, note on/off, volume, pitch alteration, pause/resume.
- Effects and filters are listed as development targets.

**Platform relevance:** ESP32 audio, I2S, sample instruments, maker synths, MIDI-triggered sample playback.

**Adaptation ideas:**

- Use as a minimal ESP32 sample playback baseline.
- Compare its flash/sample approach against RP2040/Pico or Daisy SDRAM/QSPI approaches.
- Borrow simple note/channel/sample API ideas for fast prototyping.

**Quick engineering assessment:** Good utility as a lightweight ESP32 sampler baseline. Not selected as STRONG_PASS because the design is intentionally beginner-accessible and effects/filter sections are still under development.
