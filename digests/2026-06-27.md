## 1) [BenjaminPoilve/minichord](https://github.com/BenjaminPoilve/minichord) — **STRONG_PASS**

**Technical summary:**

`minichord` is a standalone battery-powered chord/harp instrument in the Omnichord lineage. The repository explicitly contains both the source files and documentation, with linked PCB manufacturing files, full BOM, 3D enclosure files, keycap routing files, a prebuilt firmware HEX, a full PlatformIO firmware project, and the `minicontrol` preset/configuration tool. The user manual confirms the playable interface: chord buttons, a vertical harp touch bar, 12 presets, three potentiometers, rhythm/arpeggiator behavior, WebMIDI/SysEx preset editing, and a documented synthesis schematic.

**Why it matters:**

This is the strongest standalone-instrument find today. Unlike many synth repos, it is not only a code sketch or PCB dump: it combines a physical instrument concept, enclosure/keycap production assets, firmware, preset tooling, and user-facing documentation.

```text
21 chord buttons + sharp modifier
→ 12-zone harp touch strip
→ chord/harp synthesis paths
→ preset memory + WebMIDI minicontrol
→ battery-powered standalone enclosure
```

For your embedded-audio direction, the main value is the product completeness pattern: controls are not generic knobs; they are mapped to a specific performance grammar.

**Implementation highlights:**

- Hardware package includes PCB manufacturing files, full BOM, 3D enclosure files, and keycap routing files.
- Firmware package includes a prebuilt HEX, a full PlatformIO project, and minicontrol software.
- Software is BSD-3-Clause; hardware is CC BY-NC 4.0.
- The manual documents 21 main chord buttons plus a sharp modifier, a 12-section touch harp zone, 12 preset slots, three pots, arpeggiator/tap-tempo behavior, and WebMIDI/SysEx preset management.
- The synthesis section documents separate harp/chord paths with modulation, filtering, waveshaping, delay, reverb, envelopes, and preset-level parameters.

**Hardware/electronics notes:**

The available evidence points to a serious small-instrument hardware package: battery operation, micro-USB charging, audio via the headphone/output jack, mechanical chord buttons, a touch strum zone, LEDs, three pots, custom enclosure, and keycap manufacturing assets. I did not open PCB CAD or inspect schematics in detail, so analog/audio-front-end quality remains unreviewed.

**Platform relevance:**

Standalone embedded synth, battery instrument, chord/harp UI, touch strip performance control, PlatformIO firmware, WebMIDI/SysEx configuration, custom enclosure/keycaps, preset editor workflow.

**Adaptation ideas:**

- Reuse the chord-button + strum-strip grammar for a MIDI/CV controller or compact synth companion for Hydrasynth/OXI-style workflows.
- Mine the WebMIDI/minicontrol approach for browser-based preset management on a custom embedded instrument.
- Treat the physical production package as a benchmark for “small device, real enclosure, usable docs”.
- Study the synthesis schematic and map the architecture to Daisy, Teensy, or RP2350 with a cleaner audio codec path.

**Quick engineering assessment:**

**STRONG_PASS.** It has source, firmware binary, PlatformIO project, production hardware files, enclosure assets, and real user documentation. It is the most complete standalone product-style find today.

**Caveats / verification gaps:**

- Hardware license is CC BY-NC 4.0, so commercial derivative use is restricted unless relicensed or independently reimplemented.
- PCB/schematic details were not deeply reviewed.
- Firmware was not built or flashed.
- Audio output topology and noise/performance were not bench-verified.

**Sources:**

- Repository: [BenjaminPoilve/minichord](https://github.com/BenjaminPoilve/minichord)
- Manual: [minichord user manual](https://minichord.com/user_manual/)
- Assembly docs: [minichord assembly guide](https://minichord.com/assembly/)

## 2) [positionhigh/MicroDexed-touch](https://codeberg.org/positionhigh/MicroDexed-touch) — **STRONG_PASS**

**Technical summary:**

`MicroDexed-touch` is a Teensy 4.1 standalone synth workstation built around MicroDexed with a TFT touch UI, PCM5102A audio board, ILI9341 display, capacitive touch option, and PSRAM for samples. The accessible GitHub mirror documents FM synthesis, external MIDI over USB/TRS/DIN, two global delays, PSRAM-backed sample workflows, two VA monosynth instances, an 8-voice poly oscillator based on Mutable Instruments Braids code, an 8-track sequencer, a 12-track live sequencer, mixer, multiband compressor, touch mute matrix, tracker view, and a WIP remote web UI.

**Why it matters:**

This is a high-density embedded music workstation rather than a single effect or synth voice. It is especially useful as a reference for how far Teensy 4.1 can be pushed when UI, sequencing, sample management, and synthesis engines are integrated into one device.

```text
Teensy 4.1 + PCM5102A + ILI9341 touch + PSRAM
→ MicroDexed FM
→ samples + VA + Braids-derived oscillator
→ sequencer/live sequencer
→ mixer + global FX + web-control experiments
```

**Implementation highlights:**

- Required hardware is stated as Teensy 4.1, PCM5102A audio board, 320×240 ILI9341 SPI display with capacitive touchscreen, and PSRAM for custom samples.
- PlatformIO configuration targets Teensy 4.1 with Arduino framework and multiple build environments for PROGMEM/PSRAM, capacitive/resistive touch, APC variants, MIDI activity lights, RGB encoders, button LEDs, MCP23017, and related options.
- Documented firmware version in `platformio.ini` is `1.9.9.2`.
- Feature set includes FM engines, VA monosynths, Braids-derived 8-voice oscillator, sample loading/editing from SD/PSRAM, sequencer/live-sequencer modes, mixer, delays, compressor, and remote web UI work.
- PCBWay project pages and a Codeberg wiki/build guide are linked from the README, though not fully inspected in this run.

**Hardware/electronics notes:**

The hardware stack is pragmatic: Teensy 4.1 for compute, PCM5102A for audio output, ILI9341 touch display for UI, optional PSRAM for samples, USB/TRS/DIN MIDI, and optional expanded controls. The design looks more like a complete desktop module than a bare firmware experiment. The unresolved piece is hardware reproducibility: the README points to PCBWay and wiki resources, but I did not verify all manufacturing files or BOM depth.

**Platform relevance:**

Teensy 4.1, PCM5102A, ILI9341 capacitive/resistive touch, PSRAM, SD samples, FM synthesis, Braids-derived oscillator, sequencer/live sequencer, USB MIDI, TRS/DIN MIDI, PlatformIO.

**Adaptation ideas:**

- Use as a reference for a Teensy or Daisy “small workstation” with synth engines + sample engine + sequencer.
- Study build flags and configuration variants as a model for hardware-option scaling.
- Extract UI sequencing patterns: mixer view, live sequencer, mute matrix, preset/sample management.
- Compare Teensy 4.1 PSRAM/sample workflow against RP2350/Daisy SDRAM approaches.

**Quick engineering assessment:**

**STRONG_PASS.** Strong firmware/build evidence and a deep musical feature set. It ranks high even though the primary Codeberg page was not fully crawlable in this runtime, because the accessible mirror exposes enough README and PlatformIO evidence.

**Caveats / verification gaps:**

- Primary source is Codeberg; direct Codeberg content access was limited by the runtime, so README/build evidence was verified through the GitHub mirror.
- PCBWay/wiki/build-guide details were not deeply inspected.
- README explicitly warns that sample pitch shifting with polyphony is early/WIP and not currently stable.
- Firmware was not built or flashed.
- License is GPLv3 for MicroDexed; derivative distribution needs copyleft handling.

**Sources:**

- Primary project: [positionhigh/MicroDexed-touch](https://codeberg.org/positionhigh/MicroDexed-touch)

## 3) [ksoloti/ksoloti-gills](https://github.com/ksoloti/ksoloti-gills) — **STRONG_PASS**

**Technical summary:**

Ksoloti is an Axoloti-derived environment for generating and processing digital audio on standalone hardware. The Gills project turns the Ksoloti Core into a desktop synth/effect box with a proper control surface and open hardware package. The Gills repo provides KiCad 9 CAD, Gerbers, BOM/CPL production files, schematics, enclosure-panel Gerbers, and a CV expander. The official Gills page documents OLED, encoder, 10 pots, buttons, LEDs, line/headphone I/O, MIDI, rear SD/USB access, optional PDM mic, and optional CV expander.

**Why it matters:**

This is less about a single synth algorithm and more about a complete patchable embedded-audio ecosystem:

```text
Patcher on computer
→ Ksoloti Core standalone patch runtime
→ Gills desktop hardware shell
→ tactile controls + audio/MIDI/CV expansion
→ reusable instrument/effect platform
```

For product thinking, it is a strong example of separating the DSP core from the performance/control enclosure.

**Implementation highlights:**

- Ksoloti site describes the platform as usable for virtual modular synthesis, polysynths, drone boxes, sequencers, effects, sample players, loopers, granular samplers, MIDI/CV/trigger generation and processing.
- Patches can be uploaded to internal memory or SD card and played without a computer connected.
- Gills is documented as a standalone desktop unit for Ksoloti Core.
- Gills hardware includes a 1.3 inch 128×64 OLED, encoder with switch, 10 pots, 4 buttons, 4 assignable LEDs, 2 line inputs, 2 line outputs, headphone output, MIDI in/out, SD/USB access, and optional PDM microphone.
- Optional CV expander provides two synth-level CV outputs with ±5 V or 0–10 V jumper options, trimmers, and V/oct precision target.
- Gills repository includes KiCad 9 CAD, Gerbers, BOM, CPL, schematics, panel Gerbers, and CV expander production files.

**Hardware/electronics notes:**

The hardware package is unusually complete for a community desktop synth/effect box. The controls are not just breakout-board wiring: the design provides a real front panel/enclosure set, production files, MIDI, audio jacks, headphone out, power input, SD/USB access, optional microphone, and CV expander. The main dependency is the Ksoloti Core, so Gills is not standalone without the core board.

**Platform relevance:**

Ksoloti/Axoloti-style patcher, standalone embedded DSP, STM32-class patch runtime, desktop synth/effect enclosure, MIDI, line/headphone I/O, OLED/encoder/pots/buttons, CV expander, KiCad 9, Gerbers/BOM/CPL.

**Adaptation ideas:**

- Use the core-plus-control-shell architecture as a template for Daisy/Teensy/RP2350 instrument variants.
- Reuse the Gills control density as a benchmark for desktop synth/effect UX.
- Study the CV expander scaling/calibration concept for adding modular outputs to a desktop device.
- Compare patcher-based workflow against compiled firmware workflows such as Daisy, Faust, or Gen~.

**Quick engineering assessment:**

**STRONG_PASS.** Strong open hardware evidence, official ecosystem documentation, practical standalone use, and a mature patcher/runtime concept. It is not a simple flash-and-go microcontroller sketch, but the adaptation value is high.

**Caveats / verification gaps:**

- Gills requires a Ksoloti Core; it is not functional alone.
- Ksoloti firmware/software is GPLv3; check distribution obligations before derivative products.
- Hardware source license for Gills is CC BY 4.0, which allows commercial reuse with attribution, but the core ecosystem licenses still matter.
- No patcher build, firmware build, or hardware test was run.

**Sources:**

- Ksoloti site: [ksoloti.github.io](https://ksoloti.github.io/)
- Gills project page: [Ksoloti Gills](https://ksoloti.github.io/6-gills.html)
- Gills hardware repo: [ksoloti/ksoloti-gills](https://github.com/ksoloti/ksoloti-gills)
- Core repo: [ksoloti/ksoloti](https://github.com/ksoloti/ksoloti)

## 4) [Allen-Synthesis/EuroPi](https://github.com/Allen-Synthesis/EuroPi) — **PASS**

**Technical summary:**

EuroPi is an OSHWA-certified Raspberry Pi Pico Eurorack module for programmable CV/gate generation and processing using MicroPython. It has six 0–10 V CV outputs with LEDs, two 12-bit knobs, two buttons, one 0–12 V CV input, one digital input, a 128×32 OLED, and an I²C expansion header. The repository includes software, firmware, API documentation, programming/calibration instructions, contributed scripts, and multiple hardware variants with build guides and BOMs.

**Why it matters:**

EuroPi is not audio-rate DSP, but it is a strong open hardware control platform. It belongs in the digest because embedded audio devices usually fail at the control layer before the DSP layer: calibration, protection, output scaling, scriptability, and front-panel usability matter.

```text
Raspberry Pi Pico + MicroPython
→ protected Eurorack CV/digital I/O
→ six 0–10 V outputs
→ OLED + knobs + buttons
→ user scripts / calibration / API docs
```

**Implementation highlights:**

- Hardware variants include through-hole, surface-mount, and stripboard builds.
- Hardware docs include build guides and BOMs.
- Output specs include 1 kΩ output impedance, RC-filter-smoothed PWM, 0–10 V range, and about 1.5 kHz maximum usable frequency without changing RC values.
- Analog input is 100 kΩ, readable over 0–12 V, and protected for ±12 V.
- Main repository documents Apache 2.0 software, CERN-OHL-S v2 hardware, and CC0 documentation.
- OSHWA certification page confirms UID `UK000048`, certification date August 22, 2023, and the same high-level module description.

**Hardware/electronics notes:**

The useful hardware lesson is protection and range adaptation around a low-cost Pico. The design improves on the older prototype with full 0–10 V outputs, Eurorack power handling, diode protection, and overvoltage-protected jacks. The output path is PWM-filtered CV, not an audio DAC; that is acceptable for modulation/sequencing but not for high-quality audio output.

**Platform relevance:**

Raspberry Pi Pico, MicroPython, Eurorack CV/gate, OLED UI, scriptable modulation, calibration flow, hardware variants, OSHWA certification, CERN-OHL-S hardware.

**Adaptation ideas:**

- Use as a reference for a safe CV expander/front-panel controller for Daisy/Teensy audio hardware.
- Borrow its MicroPython scripting model for fast user-programmable control utilities.
- Study its input protection and 0–10 V output approach before designing Eurorack-adjacent controller hardware.
- Treat its documentation/API style as a benchmark for user-extensible embedded music tools.

**Quick engineering assessment:**

**PASS.** Very strong open-source/build evidence, but ranked below the audio-generating projects because it is primarily CV/gate control rather than audio synthesis or processing.

**Caveats / verification gaps:**

- Not suitable as an audio output path: CV outputs are PWM-filtered and documented around control-rate use.
- No hardware test or calibration procedure was run.
- Script quality varies across contributed apps; only platform-level evidence was inspected.

**Sources:**

- Repository: [Allen-Synthesis/EuroPi](https://github.com/Allen-Synthesis/EuroPi)
- Hardware overview: [EuroPi hardware README](https://github.com/Allen-Synthesis/EuroPi/blob/main/hardware/README.md)
- OSHWA certification: [UK000048](https://certification.oshwa.org/uk000048.html)
