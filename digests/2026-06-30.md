### 1) [relic-se / PicoSynth_Sandbox-hardware](https://github.com/relic-se/PicoSynth_Sandbox-hardware) — **STRONG_PASS**

**Technical summary:**

PicoSynth Sandbox is a Raspberry Pi Pico digital synthesizer hardware platform intended for CircuitPython and `synthio`. The board combines stereo I2S audio input/output, stereo MEMS microphones, MIDI I/O, a 16-key capacitive keybed, 1602 display, two rotary encoders, microSD, and LiPo charging/power distribution.

**Why it matters:**

This is the best hardware-first hit in this run because it is neither a bare Pico audio example nor a firmware-only synth. It is a compact instrument/dev-board hybrid with a useful I/O envelope:

```text
RP2040 / Pico
→ PCM5102 I2S DAC line out
→ PCM1860 I2S ADC line/mic in
→ MEMS microphones
→ PAM8019 headphone/speaker amp
→ MIDI TRS I/O
→ TTP229 16-key capacitive keybed
→ LCD + 2 encoders + pots + microSD + LiPo
```

That makes it a practical reference for a standalone Pico-class synth/sampler/drum-machine board rather than only a toy synth sketch.

**Implementation highlights:**

- README explicitly positions it as a Raspberry Pi Pico digital synthesizer board with stereo I2S ADC/DAC, MEMS mics, MIDI I/O, capacitive keybed, LCD, two encoders, and LiPo power.
- Feature list confirms PCM5102 I2S DAC, PCM1860 I2S ADC, PAM8019 headphone/speaker amplifier, TRS-A MIDI I/O, input/amplifier pots, TTP229-BSF keybed, 16x2 LCD, two push encoders, and microSD.
- Repository root exposes project structure beyond a single PCB: `3dmodels`, `_static`, `carrier`, `case`, `libraries`, `module`, `stencil-jig`, `tests`, and `v2` folders.
- Repo file list includes subsystem KiCad schematics for audio out, battery, I2S ADC, I2S DAC, keyboard, MIDI, plus top-level `.kicad_sch`, `.kicad_pcb`, and `.kicad_pro` files.
- Hardware tests are documented as available under `./tests`; software path is CircuitPython + synthio, with library/docs linked from the README.
- Official docs include examples for drum machine, monophonic bass, microphone sampler, polyphonic synth, and MIDI-controller behavior.

**Hardware/electronics notes:**

**Hardware modifiability: strong but verify board-file content before fab.** Editable KiCad schematic files are directly present; the GitHub repository page lists `.kicad_pcb` and `.kicad_pro` files, and the repo has case/3D/test support. The connector could fetch the `.kicad_pcb` path by SHA but returned no readable text content for that file, so I treat PCB-source existence as page-verified but not connector-inspected internally.

Electronics value is the complete audio/control/power partition: codec-class ADC, separate DAC, MEMS input, headphone/speaker output, MIDI, SD storage, cap-touch note entry, and battery power. This is a better adaptation target than most Pico synth examples because the board already answers most product-I/O questions.

**Platform relevance:**

RP2040, Raspberry Pi Pico, CircuitPython, `synthio`, I2S ADC/DAC, PCM5102, PCM1860, PAM8019, MEMS microphone input, TRS MIDI, TTP229 capacitive keyboard, LCD, encoder UI, microSD, LiPo portable audio hardware.

**Adaptation ideas:**

- Use as a reference partition for a small Pico 2 / RP2350 sampler or drum machine with real audio input.
- Replace the 16-key capacitive keyboard with a silicone button matrix or touch-strip while keeping the codec/power/storage backbone.
- Port the concept to a Daisy Seed or STM32H7 design if higher DSP headroom is needed, using the same UI/audio/power block allocation.
- Reuse the `tests`/library-abstraction style for bring-up validation on custom audio boards.

**Quick engineering assessment:**

**STRONG_PASS.** This is the strongest daily find because it has a complete source-hardware/instrument envelope, not only a firmware idea. The only reason to be cautious is that I did not internally parse the PCB file content, despite the repo page exposing the `.kicad_pcb` file.

**Caveats / verification gaps:**

- No build, flash, or audio test was run.
- The firmware repository linked by the README was not readable through the GitHub connector in this run; the official docs/library path was verified separately.
- `.kicad_pcb` file existence was verified from the repository page and fetch path, but the connector returned no readable board text.
- GPLv3 applies; check suitability before commercial derivative work.

**Sources:**

- [PicoSynth Sandbox hardware repository](https://github.com/relic-se/PicoSynth_Sandbox-hardware)
- [PicoSynth Sandbox project/docs](https://pico-synth-sandbox.dcdalrymple.com/)

### 2) [tebl / BulkyMIDI-32](https://github.com/tebl/BulkyMIDI-32) — **PASS**

**Technical summary:**

BulkyMIDI-32 is a hardware ecosystem for building a desktop MIDI module around `mt32-pi`, with additional related modules for audio switching, MIDI channel monitoring, MiniDexed-oriented use, WaveBlaster-style modules, MIDI input switching, SD-card MIDI playback, power switching, and visual metering.

**Why it matters:**

This is valuable because it is a complete hardware/product ecosystem rather than a one-off carrier board. It shows how to turn Pi/firmware synth appliances into physical desktop instruments with repeatable styling, panels, faceplates, BOMs, assembly notes, and support modules.

```text
Raspberry Pi + mt32-pi / MiniDexed-class firmware
→ PCM5102-style I2S DAC module
→ OLED/buttons/encoder/front panel
→ passive audio/RS-232 extras
→ MIDI/audio switch and playback modules
→ consistent faceplate/case-by-PCB system
```

**Implementation highlights:**

- Main README describes multiple same-form-factor modules that can stack into a “MIDI-mountain” and also work independently over standard MIDI.
- Module set includes main BulkyMIDI-32, Audio Switch, Channel Monitor, Channel Monitor 2, Dexed variant, ExModule, Input Switch, Internal drive-bay variant, Play, Power Switch, and VU SIDi.
- Main module documentation includes build instructions, BOM links, setup/getting-started docs, PCM5102-style I2S DAC handling, display/button/encoder UI paths, and front-panel options.
- ExModule documentation covers external WaveTable-module usage, 5 V power limitation, MIDI DIN input/thru, audio sockets, build sequence, and mechanical panel alignment.
- Repository page exposes a large set of module folders, common assets, documentation, faceplates, gallery, and Arduino software.

**Hardware/electronics notes:**

**Hardware modifiability: medium-to-strong.** The repo provides extensive module folders, BOM/build docs, KiCad project evidence for at least some modules/panels, and CC BY-SA 4.0 licensing. The main module source-CAD depth was not exhaustively parsed in this run, so I do not rate it as cleanly as PicoSynth Sandbox. It is still much more reusable than a Gerber-only build dump.

The engineering value is the productization pattern: panel-as-PCB construction, consistent module dimensions, user-facing assembly docs, power/switching/support modules, and practical caveats around display orientation, DAC configuration, MIDI connectors, and cheap/available parts. It is less about novel DSP and more about making Pi-class synth firmware into a buildable object.

**Platform relevance:**

Raspberry Pi, mt32-pi, MiniDexed, PCM5102 I2S DAC modules, DIN MIDI, TRS/audio routing, SD-card MIDI playback, WaveBlaster/DB50XG-style modules, retro MIDI hardware, desktop synth module packaging.

**Adaptation ideas:**

- Use the multi-module ecosystem structure for a custom Raspberry Pi / RP2350 desktop synth appliance.
- Reuse the PCB-faceplate construction method for low-volume enclosures without printed/mechanized cases.
- Study the Input Switch / Play / ExModule ideas as standalone utility modules for a synth bench.
- Adapt the “same visual language across small utility boxes” approach for a family of audio/MIDI tools.

**Quick engineering assessment:**

**PASS.** Strong enough to publish because the hardware/product ecosystem is large and reusable. It does not outrank PicoSynth Sandbox because its core sound engine is external (`mt32-pi`/MiniDexed lineage) and source-CAD verification was less clean for the main board.

**Caveats / verification gaps:**

- No build/test run was performed.
- Some module documentation is explicitly incomplete or marked working-but-docs-missing.
- Main-module CAD/source completeness was not exhaustively verified; use BOM/docs and project files before ordering.
- This should not be interpreted as re-publishing `mt32-pi`; the ranked value is BulkyMIDI’s physical hardware ecosystem.

**Sources:**

- [BulkyMIDI-32 repository](https://github.com/tebl/BulkyMIDI-32)
- [BulkyMIDI-32 Module documentation](https://github.com/tebl/BulkyMIDI-32/tree/main/BulkyMIDI-32%20Module)

### 3) [DhrBaksteen / ArduinoOPL2 + OPL2 Audio Board](https://github.com/DhrBaksteen/ArduinoOPL2) — **PASS**

**Technical summary:**

ArduinoOPL2 is a library and examples package for the OPL2 Audio Board and OPL3 Duo board. The OPL2 Audio Board is a YM3812/YM3014B retro-FM board designed for Arduino/Raspberry Pi-style hosts, with Fritzing schematic/PCB source and enclosure STLs published on Hackaday. The library supports Arduino, Teensy, Raspberry Pi, and other Arduino-like boards.

**Why it matters:**

This is an older project, but it remains useful because it is one of the few buildable discrete OPL hardware paths with host-library support. It is not a modern codec/DSP design; it is a retro-chip bring-up/reference stack:

```text
Host MCU/SBC
→ SPI / shift-register interface
→ YM3812 OPL2
→ YM3014B external DAC
→ LM358 output stage
→ ArduinoOPL2 library examples
→ MIDI synth / DRO / IMF / VGM / tracker playback
```

**Implementation highlights:**

- Library README states compatibility with Arduino, Teensy, Raspberry Pi and other Arduino-like boards.
- Library use cases include experimenting with YM3812/YMF262 chips, building a synth, playing OPL2 tunes, DRO/IMF/VGM/RAD playback, and using the board as a MIDI synthesizer.
- Current library version is stated as 2.1.4 from 2025-01-19.
- Hackaday project page describes a YM3812 board with external Y3014B DAC and op-amp output path.
- Hackaday files include `OPL2_Arduino_Final.fzz` as Fritzing schematic and PCB layout, plus enclosure STLs.
- The associated OPL3 Duo board extends the same ecosystem to two YMF262 OPL3 chips for much higher FM channel count.

**Hardware/electronics notes:**

**Hardware modifiability: medium.** The hardware source is Fritzing `.fzz`, not KiCad/Eagle/Altium; that is still editable source hardware, but it is less attractive for serious derivative PCB work. Enclosure STLs are present. Library source is strong enough for experimentation; hardware license was not cleanly verified from the GitHub repository during this run.

Electronics value is straightforward but useful: YM3812 register interface via 74HC595/SPI-style host control, external YM3014B DAC, simple LM358 output stage, and tested board reports. It is useful as an OPL-chip bring-up reference, not as an audio-quality benchmark.

**Platform relevance:**

Arduino, Teensy, Raspberry Pi, YM3812, YMF262, YM3014B/Y3014B, OPL2/OPL3 FM synthesis, MIDI synths, DOS/AdLib/SoundBlaster-style playback, DRO/IMF/VGM/RAD asset playback.

**Adaptation ideas:**

- Build a small OPL2/OPL3 desktop module with modern MIDI/USB host control.
- Rework the Fritzing board into KiCad with proper power, ESD, output filtering, and audio connector treatment.
- Combine the library with a modern control panel and patch storage for a retro FM voice card.
- Use the OPL3 Duo concept as a reference for multi-chip retro-FM voice expansion.

**Quick engineering assessment:**

**PASS.** Promoted because hardware source and software/library path exist and the project has distinctive audio value. Demoted below the top two because Fritzing-source hardware and unverified licensing are weaker than a clean KiCad/source-hardware package.

**Caveats / verification gaps:**

- No hardware build/test was run.
- Hardware source is Fritzing, not a professional EDA project.
- Hardware license was not cleanly verified.
- Original board is old; component availability and clone-chip risk need checking before ordering.
- Audio output stage should be reviewed before treating it as product-quality line output.

**Sources:**

- [ArduinoOPL2 repository](https://github.com/DhrBaksteen/ArduinoOPL2)
- [OPL2 Audio Board Hackaday project](https://hackaday.io/project/18995-opl2-audio-board-for-arduino-raspberry-pi)
