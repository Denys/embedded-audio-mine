### 1) [pedalboard/pedalboard-hw + pedalboard ecosystem](https://github.com/pedalboard/pedalboard-hw) — **STRONG_PASS**

**Technical summary**  
Open Pedalboard is a modular mainboard for processing audio and/or MIDI on a pedalboard. The hardware is built around a Raspberry Pi CM4/CM5 for audio processing and an RP2040 for independent MIDI/control firmware, with a maker-friendly flat enclosure target. Related repos include MIDI, audio, OS, case, display, LED ring, bridge/protocol, and soundcard components.

**Why it matters**  
This is closer to a product platform than a one-off pedal board. It has the right architecture split for a serious DIY/low-volume audio appliance: Linux-class audio host, deterministic microcontroller for I/O/control, source hardware, OSHWA certification, release procedure, interactive board/BOM docs, and mechanical ecosystem.

**Implementation highlights**

- Modular audio/MIDI mainboard: MIDI-only or combined MIDI + audio.
- CM4/CM5 target with stated sub-2 ms audio-processing goal.
- RP2040 MIDI controller with independent firmware path.
- Interactive schematic/PCB viewer, iBOM, release downloads, Digi-Key list, PCBWay manufacturing page, and 3D-printable case repo.
- Current changelog includes KiCad 9 upgrade and CM5 testing in the 4.0.1-RC direction.

**Hardware / electronics notes**

- **Modifiability:** editable KiCad project and schematic files verified by repository path search (`pedalboard-hw.kicad_pro`, `pedalboard-hw.kicad_sch`, `audio.kicad_sch`, `pico.kicad_sch`, `psu.kicad_sch`, `connect.kicad_sch`).
- **License:** CERN-OHL-P-2.0 shown in README and in the `audio.kicad_sch` title block; OSHWA certification badge shown in README.
- **Architecture:** direct CM4/CM5 mainboard, RP2040 control/MIDI section, replaceable dedicated soundcard footprint/module path, display/LED ring ecosystem.
- **Manufacturing evidence:** release links, iBOM, PCBWay page, Digi-Key shared list, Git revision embedded into schematics/PCB per changelog.

**Platform relevance**

Good reference for a future standalone pedalboard/groovebox host: Linux audio processing with MCU front-end, low mechanical height, local control surface, separate display and soundcard subsystems.

**Adaptation ideas**

- Use the CM4/CM5 + RP2040 split for a custom synth/groovebox host where Linux handles engines/UI/storage while MCU handles deterministic MIDI/footswitch/encoder scanning.
- Study the RP2040 section and display/LED-ring repos as a source for robust front-panel design.
- Treat the release/iBOM/site pipeline as a template for publishing your own hardware repo.

**Quick engineering assessment**

Very strong hardware/process reference. The main risk is that it is more a pedalboard platform than a compact synth module; software maturity must be inspected separately before treating it as a complete ready-to-use audio product.

**Caveats / verification gaps**

- Audio software and OS were not deeply audited in this run.
- Input-protection and some mechanical/USB/debug items remain on the changelog TODO list.
- The soundcard/display ecosystem deserves a separate future pass before copying the whole stack.

### 2) [newdigate/teensy-eurorack](https://github.com/newdigate/teensy-eurorack) — **PASS**

**Technical summary**  
Open-source Teensy 4.1 Eurorack audio shield for a 30-channel, 14-in/16-out analog interface: 6-in/8-out CS42448 audio, 8 CV inputs and 8 CV outputs with AD7606/AD5754-class converters, MIDI in/out, USB host/device, microSD breakout, knobs, encoders, display, and panel/mechanical files.

**Why it matters**  
This is a rare dense mixed audio/CV hardware reference around Teensy 4.1. Even if Eurorack is lower priority than standalone boxes, the audio/CV front-end, multichannel routing, BOM/build docs, and companion software drivers make it a strong design mine.

**Implementation highlights**

- CS42448 6-in/8-out 24-bit audio codec path.
- AD7606 / AD5754 control-voltage interface: 8 inputs + 8 outputs at ±10 V range.
- ST7735 display, microSD, USB host/device, MIDI in/out, 4 pots, 3 encoders with switches.
- Gerber packages, Mouser BOM links, interactive BOMs, panel assets, FreeCAD/Front Panel Designer assets.
- Related software stack includes Teensy Audio drivers for AD5754/AD7606, sequencer, variable-rate playback, TFT scope, and display/meter components.

**Hardware / electronics notes**

- **Modifiability:** README states schematics and boards are KiCad; mechanical designs FreeCAD. Gerbers and panel files are also provided.
- **Schematic/PCB source:** README explicitly links hardware boards, schematics, panel design, assembly drawings, and KiCad/FreeCAD stack.
- **License:** README says artifacts are MIT unless otherwise specified.
- **Buildability:** status badge says tested; build section provides PCB ordering and BOM guidance.

**Platform relevance**

Strong if you want Teensy 4.x to become a serious audio/CV I/O hub rather than a small stereo synth. Useful for hybrid synths, multichannel effects, CV recorders, modulation routers, and control-voltage instruments.

**Adaptation ideas**

- Repurpose the CS42448 + AD7606/AD5754 architecture for a desktop patch-matrix or audio/CV lab box.
- Lift the ST7735 + encoder/pot + SD + MIDI breakout pattern for a non-Eurorack control surface.
- Revisit newdigate’s companion repos for variable playback, sequencing, display components, and audio/CV drivers.

**Quick engineering assessment**

Electronics value is high. It is not the best product archetype for the current hardware-first standalone scoring because it is 24HP Eurorack and spread across companion repos, but as mixed-signal audio/CV design reference it is very strong.

**Caveats / verification gaps**

- Soft prior selected/reference entry already exists in `data/selected-projects.csv`; ranked here because it was not hard-published in the daily tracker.
- Some README wording references Teensy 4.0 in board/mechanical text while the top-level project badges/specs target Teensy 4.1; verify exact board revision before fabrication.
- Older KiCad version noted in README badge; inspect with current KiCad before edits.

### 3) [CaratacusPotts/Matrix-Sequencer](https://github.com/CaratacusPotts/Matrix-Sequencer) — **PASS**

**Technical summary**  
Standalone Arduino/SAMD21 MIDI sequencer/control surface for immediate visual interaction with hardware synths. It offers loop/song/conductor modes, touch note grid, four TRS MIDI ports on V2, encoders, LED feedback, EEPROM storage, Azoteq touch hardware, and multiple hardware variants including Matrix V2 and inline MIDI looper/controller.

**Why it matters**  
It is not an audio generator, but it is a serious hardware interaction reference: live loop capture, note phasing, transposition-to-scale, mirror/inversion-style transforms, velocity drawing, composer/finger-routing mode, and physical MIDI routing in a buildable standalone controller.

**Implementation highlights**

- Matrix V2 I/O: USB-C for power/programming, four TRS Type-A MIDI jacks, trigger/foot-pedal jack.
- Electronics: Adafruit ItsyBitsy M0 Express / ATSAMD21, I2C EEPROM, two Azoteq QS550 multitouch controllers, two PCAL6524 I/O expanders, CAT4016 LED latches.
- Repository claims PCB schematics, KiCad files, Arduino code, Azoteq touch files, SolidWorks CAD, and mostly Mouser BOMs for each hardware folder.
- MIT license at repo root.

**Hardware / electronics notes**

- **Modifiability:** KiCad schematics/PCB files and CAD/BOM are explicitly documented by the author; Matrix V2 README links KiCad PCB folder, Arduino code, SolidWorks CAD, Atmel programming, and Azoteq programming files.
- **Known issue:** author warns of schematic errors requiring minor board mods and says PCB files were not yet updated.
- **Build style:** intended for home assembly with basic SMD tools and a 3D printer.

**Platform relevance**

Good reference for control surfaces, MIDI/CV companions, groovebox front panels, and non-grid sequencing UX. Particularly relevant if building an OXI-like custom controller or a synth front panel with real-time transformation modes.

**Adaptation ideas**

- Reuse the event-based, non-bar-bound sequence model for hardware synth accompaniment.
- Port the composer/finger-to-MIDI-output mode into a Teensy/RP2040 MIDI router.
- Use the touch/LED/encoder hardware structure as a study reference, not as a direct fabrication target without checking errata.

**Quick engineering assessment**

High interaction-design value and surprisingly complete hardware-source package. It stays at rank 3 because it has no audio path, is explicitly low TRL, and contains known PCB/schematic corrections not yet rolled into the CAD.

**Caveats / verification gaps**

- Low-TRL warning and known PCB errors are explicit.
- Firmware quality caveat is explicit; author mentions bugs/poorly written code.
- Not a synth/pedal/sampler by itself; it is a MIDI hardware control instrument.
