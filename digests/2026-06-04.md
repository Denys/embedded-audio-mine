### 1) [`kencul/STM32F4-AudioSynthesis`](https://github.com/kencul/STM32F4-AudioSynthesis) — **STRONG_PASS**

**Technical summary:** Bare-metal 8-voice polyphonic wavetable synthesizer for STM32F407G-DISC1. It receives MIDI over USB, runs the synth engine on the Cortex-M4 FPU, outputs 48 kHz / 16-bit stereo through I2S3 DMA into the onboard CS43L22 codec, and keeps the architecture interrupt-driven rather than Arduino-loop-driven.

**Why it matters:** This is a strong Cortex-M counterweight to the recent Daisy/Teensy/Pico-heavy finds. The value is not only that it makes sound; it exposes real embedded-audio engineering choices: CCMRAM placement, circular DMA refill, DWT cycle timing, USB MIDI parsing, ADC-muxed controls, OLED status, LED voice metering, and host-side DSP tests.

**Implementation highlights:**

- 8 voices with priority-based stealing: idle → released → oldest.
- Dual-slot wavetable morphing with real-time waveform crossfade.
- Zero-delay-feedback state-variable filter with algebraic loop solving.
- Per-voice ADSR with ~5 ms soft-kill ramp to avoid clicks during voice steal.
- USB MIDI device handling for note on/off, pitch bend, mod wheel, and panic behavior.
- 8 hardware knobs through ADC plus analog multiplexer.
- SSD1306 context UI and PCA9685 per-voice amplitude LEDs.
- `VoiceManager` placed in CCMRAM to reduce audio-path bus contention.
- Host-side `ctest` suite verifies SVF behavior, ladder-filter boundedness, and ADSR timing before flashing.

**Hardware/electronics notes:** Uses the STM32F407G-DISC1 board and its CS43L22 audio codec. This is not a custom synth PCB, but it is useful because the codec/I2S/I2C/DMA path is fully visible and closer to production embedded work than most hobby synth sketches.

**Platform relevance:** STM32F4, Cortex-M4 FPU, STM32CubeMX/HAL, CS43L22, I2S DMA, USB MIDI, wavetable synthesis, embedded audio tests.

**Source links:**

- [repository](https://github.com/kencul/STM32F4-AudioSynthesis)
- [README](https://github.com/kencul/STM32F4-AudioSynthesis/blob/main/README.md)
- [DEVLOG](https://github.com/kencul/STM32F4-AudioSynthesis/blob/main/DEVLOG.md)

**Adaptation ideas:**

- Compare its static DMA-buffer engine against Teensy Audio and Daisy callback models.
- Reuse the host-side DSP tests as a pattern for embedded-audio CI.
- Study CCMRAM placement and DWT timing before porting high-voice-count code to other Cortex-M targets.
- Mine the click-free voice-steal behavior for samplers and polysynths.

**Quick engineering assessment:** Best item today. It is recent, source-visible, build-described, tested, and technically specific. Caveat: it is tied to the F407G-DISC1 hardware and does not provide a polished product enclosure or universal board abstraction.

### 2) [`ledlaux/duna-pico2-drumsynth`](https://github.com/ledlaux/duna-pico2-drumsynth) — **PASS**

**Technical summary:** RP2350 / Raspberry Pi Pico 2 drum synthesizer based on Mutable Instruments Plaits and Grids concepts. It combines multiple Plaits-style drum engines, one FM bank, sample playback, USB MIDI, PCM5102 I2S output, Euclidean sequencing, Grids-style topographic pattern morphing, chaos/randomness, a JS/HTML WebUI dashboard, and JSON preset import/export.

**Why it matters:** Recent Pico-family synth finds have been mostly melodic or FM-oriented. This one is useful because it targets rhythm generation and drum voice control: Grids map navigation, Euclidean loop length/rotation, MIDI clock start/stop/clock parsing, per-engine CC maps, swing delay, and sample-plus-synthesis mixing.

**Implementation highlights:**

- RP2350 target with 300 MHz overclock recommendation.
- PCM5102 I2S output on GPIO 9/10/11.
- USB-MIDI via Adafruit TinyUSB.
- Four Plaits-style voices with per-voice workspaces.
- One sample-based percussion path.
- Atomic shared controls for MIDI/control-to-audio state handoff.
- Euclidean pattern lengths include 4, 5, 7, 8, 11, 16, 24, and 32 steps.
- MIDI realtime handling includes clock `0xF8`, start `0xFA`, and stop `0xFC`.
- Audio loop renders voice blocks, mixes the sample path, clips to int16, and writes stereo I2S.

**Hardware/electronics notes:** Hardware requirement is deliberately simple: Pico 2 / RP2350 plus PCM5102-class I2S DAC. There is no dedicated PCB package in the inspected evidence.

**Platform relevance:** RP2350, Pico 2, Arduino-Pico, TinyUSB MIDI, PCM5102 I2S, Plaits/Braids/STMLIB ports, drum synthesis, algorithmic sequencing.

**Source links:**

- [repository](https://github.com/ledlaux/duna-pico2-drumsynth)
- [README](https://github.com/ledlaux/duna-pico2-drumsynth/blob/main/README.md)
- [DUNA.ino](https://github.com/ledlaux/duna-pico2-drumsynth/blob/main/DUNA.ino)

**Adaptation ideas:**

- Use the Grids/Euclidean split as a starting point for a hardware drum module.
- Borrow the MIDI clock handling and swing-delay pattern for sequencer-controlled Pico instruments.
- Compare performance and audio quality against Daisy drum voices and Teensy sample playback.
- Reuse the WebUI/JSON preset idea for small instruments that lack a full display.

**Quick engineering assessment:** Strong `PASS`, not `STRONG_PASS`. It is technically interesting and current enough, but the README marks it as in development and I did not verify prebuilt firmware, PCB files, or measured CPU headroom.

### 3) [`carstenbund/mac-resonant-AU-plugin` / `daisy-seed`](https://github.com/carstenbund/mac-resonant-AU-plugin/tree/main/daisy-seed) — **PASS**

**Technical summary:** Daisy Seed port of an ESP32 distributed modal-resonator network. The Daisy target is a 4-mode autonomous modal resonator with USB MIDI control, 48 kHz stereo output, 500 Hz modal integration, PlatformIO build flow, and an automated test firmware that simulates MIDI scenarios without an external controller.

**Why it matters:** This is a compact physical-modeling / modal-synthesis reference rather than another subtractive synth. It exposes a useful split: low-rate modal-state integration in the control loop and high-rate stereo synthesis in the Daisy audio callback. The built-in test-scenario firmware is also a good idea for validating sonic behavior without needing a human playing a keyboard.

**Implementation highlights:**

- Four complex modes with independent frequency, damping, and weight.
- MIDI note-on triggers poke excitation; velocity controls strength.
- CC mapping for damping, coupling, resonance, brightness, and individual mode gains.
- Pitch bend affects all modes proportionally.
- Test suite cycles through decay, note sequence, damping sweep, velocity ramp, rapid-fire stress, mode isolation, harmonic series, resonance sweep, brightness sweep, pitch bend sweep, and chaos scenarios.
- Architecture separates `modal_node`, `audio_synth`, and `usb_midi_handler`.
- Main loop handles MIDI and 500 Hz integration; audio callback generates 48 kHz stereo output.
- README documents the ESP32-to-Daisy architectural differences: push I2S versus callback audio, UART/GPIO MIDI versus native USB, TDM/network assumptions versus stereo single-node output.

**Hardware/electronics notes:** Targets stock Daisy Seed audio I/O. The extension notes mention adding Daisy ADC/CV input and an ESP32 UART bridge for distributed-network behavior, but those are extension paths rather than verified hardware in this ranked entry.

**Platform relevance:** Daisy Seed, modal synthesis, USB MIDI, PlatformIO, physical modeling, test-driven embedded audio behavior, ESP32-to-Daisy porting.

**Source links:**

- [Daisy Seed subproject](https://github.com/carstenbund/mac-resonant-AU-plugin/tree/main/daisy-seed)
- [Daisy README](https://github.com/carstenbund/mac-resonant-AU-plugin/blob/main/daisy-seed/README.md)
- [parent repository](https://github.com/carstenbund/mac-resonant-AU-plugin)

**Adaptation ideas:**

- Convert the 4-mode resonator into a Daisy Field touch/keyboard instrument.
- Add CV input for damping or modal-frequency spread.
- Use the automated sonic-scenario firmware style for regression testing embedded FX.
- Combine with DaisySP reverb/delay for a small modal percussion or drone module.

**Quick engineering assessment:** Good `PASS`. It has a build path and a meaningful DSP architecture. Caveat: it is a subproject inside a broader repo with a misleading parent name, and the modal system is currently small rather than a full multi-node instrument.

### 4) [`dduuukk/embedded-audio-sample-player-with-midi-support`](https://github.com/dduuukk/embedded-audio-sample-player-with-midi-support) — **REF_PASS**

**Technical summary:** Bare-metal STM32H7 audio sample player with MIDI triggering. It parses UART MIDI, reads `.wav` files from SD card through SDMMC/FatFS, streams audio through an STM32H750 SAI/I2S-compatible peripheral using DMA, configures an audio codec over I2C, and targets custom hardware informed by Daisy-style audio development.

**Why it matters:** This is a good sampler-infrastructure reference. It focuses on the unglamorous parts that matter in real embedded sample playback: WAV headers, SD card access, FatFS integration, codec configuration, SAI/DMA streaming, UART MIDI event parsing, latency, and custom-board bring-up.

**Implementation highlights:**

- STM32H750 target with codec, SD card reader, UART MIDI, and headphone/line output.
- FatFS filesystem and SDMMC/SDIO path for sample storage.
- WAV parser transforms file data into audio words for playback.
- DMA FIFO feeds the SAI/I2S-compatible audio peripheral.
- I2C configures the codec.
- MIDI handler receives UART data, parses MIDI events, stores events, and triggers sample playback.
- Documentation is split by subsystem: SAI audio driver, SD/FatFS driver, WAV parser, I2C codec driver, UART MIDI driver, experimental results, and lessons learned.
- README reports imperceptible keypress-to-sample-start delay and a 95% similarity index between hardware output and expected output.

**Hardware/electronics notes:** The project explicitly uses an STM32H7 development board plus custom PCB direction. This is not a drop-in Daisy sampler; its value is in bypassing libDaisy to expose the lower-level driver stack.

**Platform relevance:** STM32H7, STM32H750, SAI/I2S, DMA, SDMMC, FatFS, codec bring-up, UART MIDI, sampler engines, custom audio hardware.

**Source links:**

- [repository](https://github.com/dduuukk/embedded-audio-sample-player-with-midi-support)
- [README](https://github.com/dduuukk/embedded-audio-sample-player-with-midi-support/blob/main/README.md)
- [SAI audio driver docs](https://github.com/dduuukk/embedded-audio-sample-player-with-midi-support/tree/main/docs/sai-audio-driver)
- [UART MIDI driver docs](https://github.com/dduuukk/embedded-audio-sample-player-with-midi-support/tree/main/docs/uart-midi-driver)

**Adaptation ideas:**

- Use as a reference before implementing SD-card sample streaming on Daisy or STM32 custom hardware.
- Compare its FatFS/SDMMC/DMA split against Teensy Audio SD playback and Daisy WavPlayer.
- Extract the subsystem-doc pattern for your own embedded-audio board bring-up notes.
- Use the latency and output-comparison methodology as a minimal validation template.

**Quick engineering assessment:** `REF_PASS` because it is older and more project-report-like than product-like, but the driver/documentation depth makes it useful. Main caveat: FreeRTOS/UI/synth expansion remain future work, not delivered features.

### 5) [`DIYSynthMNL/Eurorack-PT2399-Delay`](https://github.com/DIYSynthMNL/Eurorack-PT2399-Delay) — **REF_PASS**

**Technical summary:** Hardware-dominant Eurorack PT2399 delay module. It adds voltage-controllable delay time via a BJT current-source control path on PT2399 pin 6, two wet outputs plus one dry output, an aux input normalled into the feedback path, feedback hard-clipping jumper, anti-latch-up protection, local ±5 V regulation, and a TL431-derived negative reference for CV scaling.

**Why it matters:** This is a good mixed-signal audio hardware reference. The value is in the CV-to-delay-time and feedback-loop implementation, not firmware. It documents the analog scaling around a famously messy lo-fi delay IC, including latch-up risk, pin-6 operating range, calibration order, and a schematic-value mismatch to verify.

**Implementation highlights:**

- Eurorack ±12 V input with local +5 V / −5 V regulation.
- 10 Vpp Eurorack CV scaled toward the PT2399 pin-6 control region.
- Music-Thing-style BJT current-source approach for delay-time control.
- Aux input normalled to Wet Out 2 for default self-feedback or patched external feedback-loop insertion.
- JP1 feedback overdrive path with 1N4148 diode clipping.
- Q2/D5/R23 anti-latch-up timer holds pin 6 safe during power-on.
- Calibration sequence covers −5 V reference trim, wet output unity-gain trim, max-delay trim, and CV-level trim.
- README explicitly flags an R24 value mismatch between revision note and schematic.

**Hardware/electronics notes:** Strong schematic/design-note value, but incomplete production package. The README marks schematic as ready, PCB layout as in progress, and Gerbers/BOM/final panel/license as not ready.

**Platform relevance:** PT2399, Eurorack analog delay, CV scaling, lo-fi feedback design, op-amp conditioning, voltage references, mixed-signal audio hardware.

**Source links:**

- [repository](https://github.com/DIYSynthMNL/Eurorack-PT2399-Delay)
- [README](https://github.com/DIYSynthMNL/Eurorack-PT2399-Delay/blob/main/README.md)
- [KiCad folder](https://github.com/DIYSynthMNL/Eurorack-PT2399-Delay/tree/main/kicad)

**Adaptation ideas:**

- Use the pin-6 CV path as a design study for voltage-controlled PT2399 pedals or modules.
- Combine the feedback-loop normal idea with a Daisy/Teensy digital insert.
- Reuse the calibration checklist style for analog/digital audio front-end bring-up.
- Verify and simulate the R24 mismatch before treating the schematic as final.

**Quick engineering assessment:** Correct lane is `REF_PASS`, not `PASS`. The electronics notes are unusually valuable, but incomplete fab outputs and BOM block immediate build confidence.
