## Ranked entries

### 1) [apiel/zicBox](https://github.com/apiel/zicBox) — **STRONG_PASS**

**Lane:** standalone groovebox / modular embedded-music application framework.

**Technical summary:** zicBox is a C++ Raspberry Pi/Linux music-application framework focused on grooveboxes and drum machines. The important find is not only the software framework; it is the family of hardware builds around it: ZicPixel, ZicGrid, and ZicXY. ZicPixel is presented as the polished entry build with pre-built OS image, enclosures, plug-and-play assembly path, and a compact workstation workflow around drums, samples, and synths. ZicGrid expands the control surface with RGB grid, large screen, and 12 encoders. ZicXY is the current/experimental 8-track hardware branch.

**Why it matters:** this is closer to a product platform than a one-off firmware dump. It gives reusable patterns for a custom standalone groovebox: Linux audio app, modular UI/audio/hardware abstraction, TypeScript/JSX configuration, small front panel, OS image distribution, and multiple hardware SKUs.

**Implementation highlights:**

- Modular architecture separates UI components, audio engines/effects, and hardware interfaces.
- Control/UI and audio processing are explicitly separated; README describes dedicated UI thread and per-track audio threads.
- ZicPixel exposes 8 tracks: 6 multi-engine tracks plus 2 sample tracks.
- Engines include drum, synth, and sample categories: kick, clap, bass, metallic, FM percussion, string, FM synth, wavetable, additive, supersaw, granular, AM, and time-stretch sample engines.
- Distribution path includes ready-to-flash OS images/release assets for the hardware variants.

**Hardware/electronics notes:** ZicPixel BOM evidence includes Raspberry Pi Zero 2 W, PCM5102A DAC, ST7789 170×320 SPI display, 4 Bourns PEC12R encoders, 12 low-profile RGB key switches/keycaps, pin headers, optional USB-C/power switch/battery controller/battery. ZicXY similarly uses Pi Zero 2 W, SPI display, PCM5102A DAC, 4 encoders, 13 switches, and optional USB-C/power hardware. Hardware modifiability is good but not KiCad-native: ZicPixel exposes EasyEDA project links for no-battery and battery variants, Gerber generation, and the instruction to clone the EasyEDA project to modify the PCB. ZicXY provides Gerbers/release path and assembly notes, but its README explicitly warns that it is early hardware and PCB/firmware compatibility may change.

**Platform relevance:** strong for a Raspberry Pi / Linux-based standalone sampler/groovebox, less directly reusable for Cortex-M DSP. The UI/hardware abstraction and release-image workflow are the reusable value.

**Adaptation ideas:**

- Treat ZicPixel as a low-cost groovebox MVP reference: Pi Zero 2 W + PCM5102A + small TFT + 4 encoders + key matrix.
- Fork the hardware approach into a KiCad-native two-board design: compute/audio board plus front-panel controller board.
- Reuse the modular audio-engine/plugin idea for a Daisy/RP2350 device with stricter real-time constraints.
- Use the ZicXY early hardware branch as a checklist of what not to freeze before pinout/firmware compatibility stabilizes.

**Quick engineering assessment:** high utility, high product-level adaptation value, medium hardware-source cleanliness. The main caution is that the PCB source is EasyEDA-linked rather than committed as KiCad/Eagle/Altium files; this is still modifiable, but not as repo-portable as a full in-tree KiCad project.

**Caveats / verification gaps:** hardware license was not separately verified beyond the repository GPLv3 license file. ZicXY is explicitly early-stage hardware. Battery behavior has a documented power-drop/reboot issue in the ZicPixel notes.

**Sources:** [main repo](https://github.com/apiel/zicBox), [ZicPixel hardware docs](https://github.com/apiel/zicBox/blob/main/hardware/ZicPixel/README.md), [ZicXY hardware docs](https://github.com/apiel/zicBox/blob/main/hardware/ZicXY/README.md), [license](https://github.com/apiel/zicBox/blob/main/LICENSE).

### 2) [zueblin/Polaron](https://github.com/zueblin/Polaron) — **STRONG_PASS**

**Lane:** standalone DIY digital drum machine.

**Technical summary:** Polaron is a Teensy 3.6-based DIY digital drum machine with 16-step sequencing, 6 instrument tracks, 16 patterns per track, project save/load to SD, parameter locks, different per-track pattern lengths, USB-MIDI clock sync or trigger input, and stereo 12-bit output.

**Why it matters:** it is an unusually complete older standalone build: real control surface, KiCad hardware source, documented BOM, build instructions, firmware path, and explicit hardware/software licenses. It is less modern than RP2350/Daisy/Teensy 4.x designs, but the product geometry and UI density are still very relevant.

**Implementation highlights:**

- 30 WS2812/SK6812 RGB LEDs and 30 pushbuttons give a dense pattern-entry surface.
- Four SN74HC165 shift registers handle button scanning.
- Two ALPS pots provide parameter control.
- SD card handles project persistence.
- Sync path supports USB-MIDI clock and trigger input.
- Build path uses Arduino IDE + Teensyduino.

**Hardware/electronics notes:** hardware source is strong: README states PCB was designed in KiCad 5.1.2, and the repository includes `Hardware/sequencer.kicad_pcb` and `Hardware/sequencer.sch`. Hardware BOM lists Teensy 3.6, LEDs, buttons, resistors, diode, transistor, shift registers, pots, audio jacks, DIP socket, and standoffs. Licenses are explicit: code MIT, hardware CC BY-SA 3.0.

**Platform relevance:** Teensy 3.6 is obsolete-ish compared with Teensy 4.1/RP2350, and the project depends on the Teensy 3.6 internal DAC, so it is not a drop-in Teensy 4 port. Still strong as a control-surface, sequencer, and standalone instrument mechanical/electrical reference.

**Adaptation ideas:**

- Port concept to Teensy 4.1 or RP2350 with external I2S DAC/codec.
- Reuse the 30-button/30-RGB-LED interaction model for a compact drum sequencer.
- Split into two boards: MCU/audio/power board plus front-panel LED/button matrix.
- Add modern USB host/device MIDI and DIN/TRS MIDI hardware.

**Quick engineering assessment:** very good hardware/source completeness, older MCU/audio architecture. The documented LED-PWM ground-loop issue is a useful real-world warning for USB-powered audio instruments.

**Caveats / verification gaps:** not compatible with Teensy 4.0/4.1 without redesign because it relies on the Teensy 3.6 internal DAC. README says it is not “pro audio” and reports a USB/audio-interface ground loop with LED PWM noise unless isolated.

**Sources:** [main repo](https://github.com/zueblin/Polaron), [hardware PCB source](https://github.com/zueblin/Polaron/blob/master/Hardware/sequencer.kicad_pcb), [hardware schematic source](https://github.com/zueblin/Polaron/blob/master/Hardware/sequencer.sch).

### 3) [Windfisch/analog-synth](https://github.com/Windfisch/analog-synth) — **PASS**

**Lane:** analog / digitally-assisted semi-modular synth hardware reference.

**Technical summary:** analog-synth is a low-cost semi-modular analog synthesizer project built around common op-amps and discrete parts, with STM32-based control. The planned architecture includes two 1 V/oct VCOs, optional DCO behavior, VCF, VCA, digital/analog envelopes, waveshaping/distortion, and USB/MIDI via STM32. Its useful twist is calibration-oriented design: the README explicitly trades perfect analog expo behavior for software measurement and compensation.

**Why it matters:** this is the closest find today to a Polykit-style educational hardware ecosystem, but less finished. It has analog synth boards, control-board direction, simulation, measurement tooling, firmware, and multiple KiCad artifacts. For product inspiration, it is more valuable as an engineering notebook/reference than as a ready-to-build instrument.

**Implementation highlights:**

- VCO development board and VCO simulation path.
- Voice supplement board with VCA, VCF, and utility functions.
- Main control board prototype with STM32 Blue Pill, DACs, and supply generation.
- Measurement firmware/tooling for recording VCO pitch deviation.
- Firmware build path around libopencm3.

**Hardware/electronics notes:** file search verified multiple KiCad PCB files in the repo, including VCA and VCO-related boards. README claims hardware boards and drafts under `hardware/`, plus simulation in KiCad/SPICE. Licensing states software, firmware, and schematics are GPLv3, except vendor simulation libraries.

**Platform relevance:** good for analog synth front ends and digitally-assisted calibration/control, less useful as a turnkey embedded-audio firmware target. The STM32F103 Blue Pill control architecture is old but conceptually useful for DAC-based pitch/CV compensation.

**Adaptation ideas:**

- Use the measurement/compensation path for low-cost VCO calibration.
- Compare VCO/VCF/VCA implementation against Polykit voice-card style hardware.
- Replace Blue Pill with RP2040/RP2350/STM32G4 and a precision DAC path.
- Use the repo as a teaching/reference baseline for analog voice-card bring-up.

**Quick engineering assessment:** good source-hardware reference, but not product-complete. It should not outrank ZicBox or Polaron because the README frames several features as planned and the project reads as a lab/prototype rather than a finished instrument.

**Caveats / verification gaps:** no complete enclosure/panel/build manual verified. Control-board source was not fully inspected beyond repo README and related fab/search evidence. Treat as adaptable reference, not buildable product.

**Sources:** [main repo](https://github.com/Windfisch/analog-synth), [hardware directory](https://github.com/Windfisch/analog-synth/tree/master/hardware), [VCA KiCad PCB](https://github.com/Windfisch/analog-synth/blob/master/hardware/vca/vca.kicad_pcb).
