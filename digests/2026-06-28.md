### 1) [FundamentalFrequency / LMN-3](https://github.com/FundamentalFrequency) — **STRONG_PASS**

**Technical summary:** LMN-3 is an open-source DAW-in-a-box project composed of build guide, DAW, MCAD, ECAD, firmware, emulator, and keycap repositories. The DAW runs on Raspberry Pi; the Teensy 4.1 controller firmware sends MIDI to the DAW; ECAD is KiCad; MCAD is FreeCAD.

**Why it matters:** strongest standalone/multi-board hardware-system reference today: editable PCB, editable enclosure, firmware, emulator, releases, and coherent product shape.

**Implementation highlights:** Raspberry Pi DAW; CMake/JUCE/Tracktion Engine build path; PlatformIO Teensy firmware; KiCad PCB/BOM/Gerbers; FreeCAD enclosure with DXF/STL releases; emulator for development without physical hardware.

**Hardware/electronics notes:** **Hardware modifiability: strong.** Editable KiCad 6 PCB source and editable FreeCAD enclosure source are available. Control hardware includes Teensy 4.1, EC11 encoders, keyboard switches, joystick, diode/control matrix parts. Dedicated audio codec/front-end hardware was not verified.

**Platform relevance:** Raspberry Pi, Teensy 4.1, PlatformIO, CMake/JUCE/Tracktion Engine, KiCad 6, FreeCAD, MIDI control surface, standalone groovebox/DAW appliance.

**Adaptation ideas:** Use its repo split as a product template; reuse Teensy control MCU + Pi audio host architecture; adapt FreeCAD/KiCad packaging discipline for a custom synth/groovebox.

**Quick engineering assessment:** **STRONG_PASS.** Not MCU-DSP-pure, but best match to current standalone hardware-first direction.

**Caveats / verification gaps:** No build/flash/assembly run; update freshness weaker than architecture value; Pi+DAW stack is heavier than MCU-only embedded audio; audio front end not reviewed.

**Sources:** [FundamentalFrequency](https://github.com/FundamentalFrequency), [LMN-3-DAW](https://github.com/FundamentalFrequency/LMN-3-DAW), [LMN-3-ECAD](https://github.com/FundamentalFrequency/LMN-3-ECAD), [LMN-3-Firmware](https://github.com/FundamentalFrequency/LMN-3-Firmware), [LMN-3-MCAD](https://github.com/FundamentalFrequency/LMN-3-MCAD).

### 2) [shanteacontrols / OpenDeck](https://github.com/shanteacontrols/OpenDeck) — **STRONG_PASS**

**Technical summary:** OpenDeck is a Zephyr-based MIDI/OSC controller platform with browser configuration, no user firmware development required, high-density I/O, many MCU targets, display/sensor support, and an official RP2040-based OpenDeck L board.

**Why it matters:** Excellent hardware/control-surface reference: useful for custom synth, groovebox, pedal, faderbank, or parameter-surface control planes.

**Implementation highlights:** Buttons, encoders, LEDs, pots, FSRs, Nextion/SSD1306 displays, sensors, 7/14-bit NRPN, latching buttons, encoder modes, MIDI-controlled outputs, per-component channels, Bluetooth MIDI, OSC on Ethernet-capable boards.

**Hardware/electronics notes:** **Hardware modifiability: strong enough for promotion.** KiCad project files and production Gerbers were verified via repository code search. Official L board: RP2040, 128 digital inputs, 64 digital outputs, 64 analog inputs, DIN MIDI, USB-C MIDI, touchscreen and OLED connectors. No audio path.

**Platform relevance:** RP2040, Pico/Pico 2, ESP32-S3, Teensy 4.x, STM32, nRF, Zephyr, USB/DIN/BLE MIDI, OSC, W5500/W6100 Ethernet, browser configurator.

**Adaptation ideas:** Use as the control plane for a separate audio engine; study browser configuration for avoiding firmware variants; reuse high-density I/O for a macro controller/faderbank.

**Quick engineering assessment:** **STRONG_PASS.** Controller-only, but very aligned with the updated hardware/control-surface scoring.

**Caveats / verification gaps:** No build/configurator test run; hardware schematic not reviewed electrically; official L board does not support OSC; hardware license not separately verified.

**Sources:** [OpenDeck](https://github.com/shanteacontrols/OpenDeck), [OpenDeck configurator](https://config.shanteacontrols.com), [OpenDeck hardware tree](https://github.com/shanteacontrols/OpenDeck/tree/master/sch/opendeck).

### 3) [jromanki / fpga-fm-synth](https://github.com/jromanki/fpga-fm-synth) — **PASS**

**Technical summary:** Hybrid FPGA/STM32 FM synthesizer. Tang Nano 20K FPGA implements polyphonic Verilog synth logic, DDS, SPI, I2S, mixer and PLL. STM32 BlackPill firmware handles UART MIDI, FreeRTOS tasks, voice allocation, MIDI decoding and SPI control transfer to FPGA.

**Why it matters:** Strong hardware/firmware split and more technically reusable than most FPGA synth sketches.

**Implementation highlights:** Verilog DDS voices, I2S, mixer, SPI parser, top-level module, testbenches; STM32CubeMX project with FreeRTOS, MIDI parser, dynamic voice assignment, Makefile; Python scripts for LUTs, MIDI parameter conversion and PLL settings.

**Hardware/electronics notes:** **Hardware modifiability: good.** Editable KiCad schematic and PCB source verified. DIN-5 MIDI connector evidence appears in schematic. Exact DAC/output analog stage not reviewed. No enclosure/control-surface polish verified.

**Platform relevance:** Tang Nano 20K/Gowin FPGA, STM32 BlackPill, STM32CubeMX, FreeRTOS, UART MIDI, SPI, I2S, Verilog, DDS FM synthesis, KiCad, Python tooling.

**Adaptation ideas:** Use STM32/FPGA split for real-time audio coprocessor work; port control protocol to RP2350/Daisy host; add OLED/encoder/preset front panel.

**Quick engineering assessment:** **PASS.** Strong architecture and editable source hardware; not STRONG_PASS because license, bring-up status and product packaging remain unclear.

**Caveats / verification gaps:** No HDL/STM32/hardware build run; top-level license not found; analog output/noise not reviewed; docs partly Polish.

**Sources:** [fpga-fm-synth](https://github.com/jromanki/fpga-fm-synth), [hardware/fpga-fm-synth-kicad](https://github.com/jromanki/fpga-fm-synth/tree/main/hardware/fpga-fm-synth-kicad).

### 4) [grantek / minisynth32](https://github.com/grantek/minisynth32) — **PASS**

**Technical summary:** 3D-printable Raspberry Pi MIDI synth appliance inspired by the Roland MT-32 and powered by mt32-pi. It adds a physical enclosure, PCM5102 DAC, OLED, encoder, front/rear PCBs, power I/O, and DIN/USB MIDI options.

**Why it matters:** Useful example of turning a Pi synth engine into a standalone hardware object, not merely “software running on a Pi”.

**Implementation highlights:** 50% MT-32-style printable shell, GY-PCM5102 I2S DAC, front PCB with switches/OLED, rear I/O PCB with power jack/switch, rotary encoder, DIN or Arduino-USB MIDI bridge, BOM and build guide.

**Hardware/electronics notes:** **Hardware modifiability: moderate-to-good.** Repository exposes KiCad PCB/schematic/project files, BOM and printable mechanical files. Audio uses commodity PCM5102 DAC board. Cheap MIDI cable SysEx reliability is explicitly called out.

**Platform relevance:** Raspberry Pi, mt32-pi, Munt/MT-32 appliance, PCM5102 I2S DAC, SSD1306 OLED, DIN MIDI, USB-MIDI bridge, 3D-printed enclosure, KiCad hardware.

**Adaptation ideas:** Use as a packaging reference for Pi-based synth/sampler appliances; replace mt32-pi with a custom sampler/synth engine; reuse front/rear PCB split.

**Quick engineering assessment:** **PASS.** Strong appliance packaging value, but lower DSP novelty because the core sound engine is upstream mt32-pi.

**Caveats / verification gaps:** No assembly/boot test run; core engine already known/published; audio depends on commodity DAC board; 10-button faceplate is partly cosmetic because only two buttons are functional.

**Sources:** [minisynth32](https://github.com/grantek/minisynth32), [mt32-pi](https://github.com/dwhinham/mt32-pi), [clumsyMIDI](https://github.com/gmcn42/clumsyMIDI).
