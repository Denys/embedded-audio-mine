## Ranked entries

### 1) [cardonabits/haxo-hw](https://github.com/cardonabits/haxo-hw) — **STRONG_PASS**

**Lane:** standalone source-hardware musical instrument / wind-controller.

**Technical summary:** Haxophone is an electronic saxophone-style instrument built as a Raspberry Pi-family HAT. The PCB is not only electronics but also part of the mechanical body; the system uses a sax-like key matrix, breath-pressure sensing, I2S audio amplifier/output, and a Raspberry Pi running a Rust driver (`haxo-rs`) plus FluidSynth.

**Why it matters:** This is a stronger hardware-first archetype than another dev-board synth: ergonomics, controls, PCB mechanics, 3D-printed parts, firmware/software, BOM, and assembly/manufacturing guidance are treated as one instrument design. It is especially useful as a pattern for custom expressive controllers, wind synths, PCB-as-enclosure concepts, and mechanically constrained instrument PCBs.

**Implementation highlights:**

- Raspberry Pi HAT architecture.
- Saxophone-style key matrix.
- Breath/pressure sensing.
- Integrated audio amplifier and 3.5 mm output.
- `haxo-rs` software path plus FluidSynth.
- Optional RP2040/MIDI-only direction via `haxo-ino` mentioned in the project docs.
- PCB acts as the physical structure, with side-key PCBs and right-angle bracket assembly.
- FreeCAD 3D models for mouthpiece/neck/thumb-rest/strap-hook-style mechanical parts.

**Hardware/electronics notes:**

- Custom KiCad schematic verified: `haxophone001.kicad_sch` title block shows Haxophone, rev 1.1.1, Cardona Bits.
- Search/file evidence also showed KiCad project/PCB/netlist/build assets and BOM/manufacturing outputs.
- Hardware license is CC BY-SA 4.0, explicitly allowing share/adapt including commercial use under the license terms.
- Audio synthesis is Linux/FluidSynth-backed rather than MCU-only; do not treat it as low-latency bare-metal DSP without testing.

**Hardware modifiability:** editable KiCad schematic/PCB/project present; BOM present; assembly docs present; FreeCAD mechanical source present; manufacturing docs present; permissive hardware license present.

**Platform relevance:** less directly Daisy/Teensy, but excellent for hardware-product lessons: instrument ergonomics, body-PCB design, manufacturable control surfaces, breath sensor integration, and open-source hardware packaging.

**Adaptation ideas:**

- Convert the sensor/key front end to a USB MIDI / BLE MIDI controller board.
- Replace Raspberry Pi/FluidSynth audio path with Teensy 4.1, Daisy Seed, ESP32-S3, or RP2350 synth engine.
- Reuse PCB-as-body and side-board mechanical architecture for a compact expressive synth controller.
- Extract the pressure-sensor and key-matrix handling into a generic wind-controller front end.

**Quick engineering assessment:** top-tier reference for source-hardware instrument design. Not the best DSP architecture reference, but unusually valuable for complete custom instrument packaging.

**Caveats / verification gaps:**

- Linux/RPi/FluidSynth path needs latency and boot-time testing if adapted into a performance product.
- More firmware-side verification should inspect `haxo-rs` and `haxo-ino` separately.
- Not a guitar pedal or desktop synth; it ranks because the hardware/control ergonomics are unusually complete.

**Sources:**

- [cardonabits/haxo-hw](https://github.com/cardonabits/haxo-hw)
- [cardonabits/haxo-rs](https://github.com/jcard0na/haxo-rs)
- [haxo-ino mention in haxo-hw README](https://github.com/cardonabits/haxo-hw#software)

### 2) [DMME-NL/RP2040-DSP-Public](https://github.com/DMME-NL/RP2040-DSP-Public) — **STRONG_PASS**

**Lane:** standalone digital multi-FX pedal / RP2040 audio processor.

**Technical summary:** RP2040-based 24-bit stereo multi-effect processor for guitar/instrument use. The project targets 48 kHz stereo processing, up to three simultaneous effects, six pots, rotary encoder, OLED, footswitches, tap tempo, VU visualization, expression inputs, external SPI RAM, and modular effect slots.

**Why it matters:** This is a useful lower-cost counterpoint to Daisy/Teensy pedal platforms. It shows a product-minded RP2040 pedal design with explicit CPU usage data, real UI constraints, delay/reverb SPI-RAM use, and practical analog caveats around ADC headroom.

**Implementation highlights:**

- RP2040 dual-core split: core 0 for real-time audio, core 1 for UI/pots/OLED.
- Fixed-point / lightweight math emphasis.
- External APS6404L SPI RAM for long delay lines.
- Effects listed: chorus, flanger, phaser, tremolo, delay, reverb, EQ, compressor, distortion, overdrive, fuzz, cabinet sim, preamp, WIP vibrato.
- CPU usage table at 250 MHz overclock gives practical budgeting signal.
- Persistent settings path via flash save.
- Hammond 1590DD form factor.

**Hardware/electronics notes:**

- README describes hardware version 1.2 and says the KiCad project, Gerbers, and BOM are in the repository, with PCBWay assembly packages for mainboard/daughterboard.
- Audio path: PCM1808 stereo ADC module and PCM5102 stereo DAC module.
- Input voltage: 9–12 V DC.
- Known caveat: PCM1808 inputs are not attenuated and may clip with high-output pickups; README suggests modifying the ADC input RC/series resistance.
- Later PCM3060 versions are explicitly not fully tested in this repo state.

**Hardware modifiability:** KiCad/Gerbers/BOM claimed by README and PCBWay build links present; direct EDA file parse was not verified because the connector returned an empty guessed schematic path. Treat as source-package-promoted but still requiring local checkout before fabrication.

**Platform relevance:** high for custom pedal work: RP2040 is cheap, available, and attractive for fixed-slot guitar effects if the analog front end is solved properly.

**Adaptation ideas:**

- Rework the input stage with switchable instrument/line attenuation and anti-alias filtering.
- Replace module ADC/DAC with a single codec or PCM3060 revision once validated.
- Use the dual-core/UI split and effect-slot model as an RP2040 reference for a novice-friendly multi-FX pedal.
- Mine CPU numbers to choose safe combinations for chorus/reverb/delay/preamp stacks.

**Quick engineering assessment:** strong pedal architecture reference; probably not as clean as Daisy for DSP headroom, but much more interesting for low-cost, self-contained pedal experiments.

**Caveats / verification gaps:**

- MIDI and expression pedal are noted as not implemented in the README.
- Hardware source should be locally checked before fabrication; connector did not verify schematic/PCB contents.
- PCM3060 variant is not fully tested.
- High-output pickup clipping caveat is significant for a guitar product.

**Sources:**

- [DMME-NL/RP2040-DSP-Public](https://github.com/DMME-NL/RP2040-DSP-Public)
- [RP2040-DSP PCBWay profile from README](https://www.pcbway.com/project/member/?bmbno=88DFECEC-9511-40)

### 3) [centrevillage/ideal-groove-box](https://github.com/centrevillage/ideal-groove-box) — **PASS**

**Lane:** groovebox hardware architecture reference / STM32H7 control-and-audio platform.

**Technical summary:** Ideal Groove Box is an older but hardware-rich groovebox repository. The current README says the project restarted on Discord in December 2024 and that the repository will be reorganized, but the hardware tree still contains valuable KiCad/Eeschema material: main board, core module, and audio-board directions.

**Why it matters:** The project has the kind of dense embedded-audio hardware architecture that is easy to miss if ranking only polished READMEs. It is useful as a schematic mine for STM32H7 groovebox/control-surface work: codec, SAI routing, SDMMC, USB HS ULPI, FRAM, LED driver, display/control signals, and separate audio-board paths.

**Implementation highlights:**

- STM32H753VITx core-module schematic verified.
- PCM3060 on main board schematic verified.
- IS31FL3731 LED driver verified.
- MB85RS2MT FRAM verified.
- SDMMC, SAI, USART, USB FS, USB HS ULPI, SWD, display/control chip-select signals visible in the schematic.
- `audio-board-wm8731` PCB path surfaced in search.

**Hardware/electronics notes:**

- `hardware/pcb/projects/main/main.sch` is KiCad/Eeschema source, titled `IGB Main`, rev `v0.1`.
- `hardware/pcb/projects/core_module4/core_module4.sch` contains STM32H753 and control/audio/storage/USB signal labels.
- The architecture suggests a product-level groovebox/control-surface direction, but the repository state is explicitly not clean.

**Hardware modifiability:** editable KiCad/Eeschema schematic source verified; PCB path found for audio board; BOM path found; firmware/build/license not verified; repo reorg caveat applies.

**Platform relevance:** strong as a schematic/reference source for STM32H7 groovebox work, less useful as a ready-to-build project today.

**Adaptation ideas:**

- Extract STM32H753 + PCM3060 + SAI + SDMMC + FRAM blocks as a starting architecture for a modern groovebox/sampler.
- Compare the UI/control matrix and LED-driver approach against Polaron, zicBox, Pocketsequencer, and OpenDeck.
- Re-spin with a modern codec/USB-C/power tree and clean firmware repo separation.

**Quick engineering assessment:** rank as PASS only because hardware evidence is real and valuable; do not treat as a current turnkey build.

**Caveats / verification gaps:**

- README says the project restarted elsewhere and the repo will be reorganized.
- Firmware/build path not verified.
- License not verified.
- Board readiness/production history not verified.
