## Ranked entries

### 1) [DADDesign-Projects/OSCAR_P01A01 + OSCAR ecosystem](https://github.com/DADDesign-Projects/OSCAR_P01A01) — **STRONG_PASS**

**Technical summary.** OSCAR is an open hardware/software framework for digital guitar-effect pedals. The top-level repo pulls together hardware submodules, software, and flasher tooling. The processor board is STM32H743-based with external QSPI flash, SDRAM, USB, TRS/USB MIDI, encoders, switches, TFT, STLink/debug, and loader support. The audio board adds PCM3060 stereo codec, PGA2310 analog dry path/wet-dry control, separated analog/digital domains, 12 V input, and multiple LDOs.

**Why it matters.** This is closer to a product architecture than a single stompbox PCB: separated processor/audio boards, firmware framework, UI, external memory, flasher path, and mechanical CAD direction. It is a better reference for a reusable pedal/synth hardware platform than most one-board Daisy/Teensy carriers.

**Implementation highlights.** `OSCAR_P01A01` uses submodules for `OSCAR_AUDIO_01`, `OSCAR_PROC_01`, `Software_OSCAR_P01A01`, flasher loader, flasher server, and Python flasher server. The QSPI flasher/loader path is especially interesting because it can transfer assets/executables and load an ELF from QSPI at power-up.

**Hardware/electronics notes.** Processor board evidence includes `OSCAR_Proc.kicad_pcb`, `.kicad_pro`, `.kicad_sch`, hierarchical sheets, PDF, STEP, fab/lib folders, and KiCad 9 README claims. Audio board evidence includes `OSCAR_Audio.kicad_pcb`, `.kicad_pro`, `.kicad_sch`, analog/digital/power sheets, PDF, STEP, fab/lib folders, PCM3060, PGA2310, isolated domains, and LDO notes.

**Platform relevance.** Strong reference for STM32H7 audio-effect appliances, memory-heavy DSP, MIDI-controlled pedals, UI + preset architectures, and modular processor/audio board partitioning.

**Adaptation ideas.** Reuse the partitioning concept for a desktop DSP synth/effects box: processor core, swappable codec/audio front-end, UI board, storage/flasher subsystem, and optional analog dry/bypass path. For Denys-style product exploration, this is a strong architecture seed for a higher-end pedal/synth workstation rather than a weekend build.

**Quick engineering assessment.** High value. Treat as architecture/productization reference first, fabrication candidate second. The platform is more ambitious and better structured than most hobby pedal PCBs, but it needs normal bring-up skepticism: power sequencing, codec clocking, ground partition, SDRAM/QSPI timing, UI latency, and firmware/framework maturity should be reviewed before copying.

**Caveats / verification gaps.** No formal release package was found. License split is somewhat mixed: top repo badge says Apache 2.0 while processor/audio boards show MIT. Hardware is open and editable, but a dedicated manufacturing-release checklist was not verified in this run.

**Hardware modifiability.** Editable KiCad 9 source present for processor and audio boards; schematic present; PCB source present; PDF/STEP present; FreeCAD mechanical path claimed; firmware/flasher repos present.

**Sources.** [OSCAR_P01A01](https://github.com/DADDesign-Projects/OSCAR_P01A01), [OSCAR_PROC_01](https://github.com/DADDesign-Projects/OSCAR_PROC_01), [OSCAR_AUDIO_01](https://github.com/DADDesign-Projects/OSCAR_AUDIO_01), [Software_OSCAR_P01A01](https://github.com/DADDesign-Projects/Software_OSCAR_P01A01), [DAD_FORGE](https://github.com/DADDesign-Projects/DAD_FORGE).

### 2) [JordanAceto/micro_ox](https://github.com/JordanAceto/micro_ox) — **PASS**

**Technical summary.** `micro_ox` is an analog monosynth with a digital control path. It is a stripped-down version of the Josh Oxford Ribbon Synth, removes the integrated ribbon controller, and adds MIDI/CV input direction. Hardware is split into VCO, VCF/VCA, modulation, and power/input-output boards connected by IDC headers.

**Why it matters.** This is the closest find today to the Polykit-style archetype: not just firmware, not just Eurorack, but a multi-board analog synth ecosystem with digital control, front-panel thinking, firmware, explicit hardware/software licenses, and real prototype notes.

**Implementation highlights.** The project exposes circuit-board subdirectories, firmware, front-panel, jack-panel, and separate hardware/software license files. The circuit-board README says each major system component has files needed to edit schematic and PCB layout with KiCad plus build/troubleshooting docs.

**Hardware/electronics notes.** The repo description and topics identify analog signal path + digital controls, SSI2130 VCOs and SSI2140 VCF, MIDI, STM32, Rust, synth, and KiCad. The circuit-board README gives current draw estimates: main VCO about 70 mA/+12 V and 60 mA/-12 V, VCF/VCA 40/40 mA, modulation 50/20 mA, total about 160 mA/+12 V and 120 mA/-12 V.

**Platform relevance.** Strong analog/digital synth reference for semi-standalone instruments, multi-board architecture, MIDI/CV front ends, STM32 control, and analog synth IC integration.

**Adaptation ideas.** Mine it for board partitioning, IDC interconnect strategy, analog control allocation, power budget, firmware/control separation, and documentation of kludges. It could inform a desktop monosynth or voice-card/control-board ecosystem.

**Quick engineering assessment.** High-interest but not top-ranked because the author explicitly says the first prototype needs PCB kludges and documentation is incomplete. Still, that honesty is useful: it makes the repo a better engineering reference than polished but gerber-only projects.

**Caveats / verification gaps.** First prototype is under evaluation; jack panel/body are not started; docs are incomplete; PCB kludges may be required. Do not fabricate without walking through each board-specific README and `pcb_kludges` folder.

**Hardware modifiability.** Editable KiCad source claimed per major board; schematic/PCB source claimed; hardware license CC-BY-4.0 verified at repo level; software MIT verified at repo level; enclosure/body incomplete.

**Sources.** [micro_ox](https://github.com/JordanAceto/micro_ox), [micro_ox circuit_boards](https://github.com/JordanAceto/micro_ox/tree/main/circuit_boards).

### 3) [DADDesign-Projects/Asynchronous-SPDIF-Mixer](https://github.com/DADDesign-Projects/Asynchronous-SPDIF-Mixer) — **PASS**

**Technical summary.** STM32H743-based hardware/software mixer for synchronizing and mixing up to three asynchronous S/PDIF streams into one 48 kHz output. It compensates drift between sources using interpolation and supports USB-MIDI control plus a Python control panel. Mix settings are saved as flash presets.

**Why it matters.** It is not a synth, but it is a rare embedded-audio project with real digital-audio clock-domain substance. For product ideas, the useful part is the architecture: multi-source digital audio input, drift tracking, interpolation, MIDI control, preset persistence, and custom STM32H7 hardware.

**Implementation highlights.** Repo includes CubeIDE firmware structure, `.ioc`, STM32H743 linker scripts, USB device middleware, C/C++ code, a remote mixer Python directory, and a `KiCad` hardware folder.

**Hardware/electronics notes.** Custom KiCad board is claimed for the S/PDIF mixer. The repo-level file tree shows the `KiCad` folder and CubeIDE project structure, but I did not deeply parse individual schematic/PCB sheets in this run.

**Platform relevance.** Strong reference for embedded digital-audio utilities, S/PDIF routing, asynchronous sample-rate/clock-drift handling, MIDI-controlled mixers, and STM32H7 audio firmware.

**Adaptation ideas.** Reuse the drift-compensation/control model for a standalone digital audio router, MIDI-controllable effects insert, synth submixer, USB/S/PDIF utility box, or test fixture for embedded audio boards.

**Quick engineering assessment.** Promoted because it fills a different lane than synth/pedal clones. It has lower synth/hardware glamour than OSCAR or micro_ox, but higher algorithmic/audio-systems value.

**Caveats / verification gaps.** Hardware source is repo-level verified through `KiCad` folder and README, but not sheet-by-sheet inspected. Exact receiver/transmitter ICs and clocking topology were not confirmed in this run.

**Hardware modifiability.** KiCad hardware folder present; custom-board schematic/PCB path repo-level verified; firmware source present; `.ioc` present; MIT license verified.

**Sources.** [Asynchronous-SPDIF-Mixer](https://github.com/DADDesign-Projects/Asynchronous-SPDIF-Mixer).
