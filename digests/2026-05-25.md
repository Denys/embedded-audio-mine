## 1. Daily digest markdown

### 1) [`kooliha/Ouroboros_Loop_Station`](https://github.com/kooliha/Ouroboros_Loop_Station) — **STRONG_PASS**
A genuinely buildable Daisy project, not just a sketch dump: a DIY **5-track stereo looper** with **33 seconds per track at 48 kHz**, per-track speed and pan, multi-input front end, through-hole hardware, gerbers/BOM/enclosure files, and ready-to-flash firmware in-repo. The strongest adaptation value is the hardware-first interaction model: zero-menu live control, direct layer buttons, and explicit “hold button + turn knob” alternate functions. The repo also got a meaningful usability bump on **November 9, 2025** with ready-to-flash firmware and flashing docs, and the Daisy forum thread adds hardware caveats and board revisions.  
Sources: GitHub README and commit history: <https://github.com/kooliha/Ouroboros_Loop_Station>, Daisy forum thread from **August 7, 2025**: <https://forum.electro-smith.com/t/ouroboros-loop-station/8678>

### 2) [`craigyjp/Teensy-Hybrid-TDM-Synth`](https://github.com/craigyjp/Teensy-Hybrid-TDM-Synth) — **PASS**
One of the better “steal the architecture” Teensy finds: **8 voices**, **3 DCOs per voice**, **CS42448 TDM multi-out**, then out into **individual analog 4-pole filters**, plus an **FV-1 effects section**. This is exactly the kind of repo that opens up hybrid digital/analog synth topology ideas instead of just another VA patch list. The hidden arpeggiator control reuse and per-encoder secondary behaviors are also good UI patterns. Most relevant update: arpeggiator behavior/persistence changes landed on **December 15, 2025**.  
Sources: GitHub README + commits: <https://github.com/craigyjp/Teensy-Hybrid-TDM-Synth>, project thread posted **October 20, 2025**: <https://www.sequencer.de/synthesizer/threads/a-new-hybrid-synth.177040/>

### 3) [`lucblender/lx-deciim`](https://github.com/lucblender/lx-deciim) — **PASS**
This clears the novelty bar easily. It is a Daisy-based **dual-channel bitcrusher Eurorack module** that does not just reduce resolution from the LSB upward; it lets you selectively disable arbitrary bits and replace them with **CV-derived trigger states**. That makes it more of a bit-level audio logic instrument than a normal crusher. Adaptation value is high for anyone exploring digital degradation, CV-audio crossover design, or unusual control metaphors on Daisy hardware.  
Sources: GitHub README: <https://github.com/lucblender/lx-deciim>, project page: <https://www.lucas-bonvin.com/lx-deciim>

### 4) [`newdigate/teensy-variable-playback`](https://github.com/newdigate/teensy-variable-playback) — **REF_PASS**
Not a product, but a very practical Teensy building block. It adds **variable-rate sample playback** objects on top of the Teensy Audio Library, supports SD/array playback paths, interpolation, and both Teensy and Linux-side testing/dev workflows. This is the kind of foundation that unlocks samplers, loopers, pitchable playback, and file-based instruments without forcing each project to reinvent resampling. It also had a real release event: **v1.1.0** was published on **February 15, 2025**.  
Sources: GitHub README + releases: <https://github.com/newdigate/teensy-variable-playback>, library index with release dates: <https://www.arduinolibraries.info/libraries/teensy-variable-playback>

### 5) [`eTextile/Synth`](https://github.com/eTextile/Synth) — **REF_PASS**
This is the most unusual control/UI pick today. It combines a **Teensy 4.0**, a **16×16 textile FSR matrix** with interpolation, browser-based visual mapping, JSON-uploaded layouts, USB-MIDI, and onboard audio I/O. It is more controller-instrument architecture than classic synth firmware, but the adaptation value is real: visual mapping workflows, configurable gestural surfaces, and USB-connected editor/device patterns. It also had fresh activity on **May 24, 2026**, including hardware MIDI-in forwarding and handler fixes.  
Sources: GitHub README + latest commits: <https://github.com/eTextile/Synth>
