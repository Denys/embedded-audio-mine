# Embedded Audio Mine — Daily digest — 2026-05-22

## 1. Daily digest

### 1) [`bkshepherd/DaisySeedProjects`](https://github.com/bkshepherd/DaisySeedProjects) — **PASS**
A compact but high-value Daisy collection, especially for the **Looper** and **Midi** projects. The Looper is the standout because it moves beyond toy examples: external SDRAM audio buffering, OLED waveform display, clickless looping, USB mass-storage file copy/import/export, MIDI sync, tempo calculation, saturation/drive, and a documented hardware control map. The Midi project is also useful because it demonstrates routing USB MIDI input to hardware UART output and makes a concrete linker-script point: building in SRAM can break DMA on Daisy.  
Sources: [repo README](https://github.com/bkshepherd/DaisySeedProjects/blob/main/README.md), [Looper README](https://github.com/bkshepherd/DaisySeedProjects/blob/main/Looper/README.md), [Midi README](https://github.com/bkshepherd/DaisySeedProjects/blob/main/Midi/README.md)

### 2) [`m0xpd/Daisy-Multiverse`](https://github.com/m0xpd/Daisy-Multiverse) — **PASS**
A rare Daisy project that is interesting more for its architecture than for a single effect: it combines the Daisy Seed with an **8×8 Adafruit Trellis**, OLED display, and external stereo hardware to host multiple synth/effect “applications” behind a common UI/hardware layer. The repo includes several build modes and applications: string synth, Plaits-based synths, looper, Karplus–Strong, and related experiments. Good reference material for people building multi-app embedded instruments rather than one-off pedals.  
Risk: some demos depend on custom external hardware and repo-local bootloader/library setup.  
Sources: [repo README](https://github.com/m0xpd/Daisy-Multiverse/blob/main/README.md), [project docs](https://github.com/m0xpd/Daisy-Multiverse/tree/main/docs)

### 3) [`reese-wilson/DaisyBios`](https://github.com/reese-wilson/DaisyBios) — **REF_PASS**
A focused Daisy bootloader/BIOS reference rather than an instrument. The useful idea is a persistent bootloader that can load programs from SD card, switch between “Daisy programs,” and work around limits that appear when programs are SDRAM-heavy. It is a good reference if you are thinking about multi-firmware devices, patch/program launchers, or SD-based deployment workflows on Daisy.  
Risk: it is explicitly a BIOS/bootloader experiment, not a polished end-user product.  
Sources: [repo README](https://github.com/reese-wilson/DaisyBios/blob/main/README.md), [Daisy forum thread](https://forum.electro-smith.com/t/daisy-bios-run-programs-from-an-sd-card/2102)

### 4) [`kerm1t/DaisySeed`](https://github.com/kerm1t/DaisySeed) — **PASS**
A large personal Daisy lab with practical modules for **braids**, **granular**, **GuitarML neural amp models**, **Waveshare OLED bring-up**, **external SDRAM**, **WM8731 codec**, and the **LEDscape** 16-output gate/sequencer idea. It is messy but rich: the value is in concrete integration examples for displays, SDRAM, codecs, ML inference, and CV/gate style I/O around the Seed.  
Risk: not organized as a single polished product and likely requires selective extraction.  
Sources: [repo](https://github.com/kerm1t/DaisySeed), [repo README](https://github.com/kerm1t/DaisySeed/blob/main/README.md)

### 5) [`tilmanlarndt/DaisyPlayground`](https://github.com/tilmanlarndt/DaisyPlayground) — **REF_PASS**
A useful Daisy reference shelf rather than a product. It includes **stmlib ports**, a **CloudSeed** port, oscillator/effect experiments, and multiple seed/patch/synth-oriented tests. The standout value is as a grab-bag of porting patterns and algorithm experiments for DaisySP/libDaisy users.  
Risk: experimental playground structure, so expect to extract pieces rather than build a finished firmware.  
Sources: [repo](https://github.com/tilmanlarndt/DaisyPlayground), [project directories](https://github.com/tilmanlarndt/DaisyPlayground/tree/master)
