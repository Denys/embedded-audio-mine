### 1) [`rheslip/2HPico-Eurorack-Module-Hardware`](https://github.com/rheslip/2HPico-Eurorack-Module-Hardware) + [`rheslip/2HPico-DSP-Sketches`](https://github.com/rheslip/2HPico-DSP-Sketches) — **STRONG_PASS**

**Technical summary:** RP2350 / Raspberry Pi Pico 2 Eurorack hardware family covering 2HP and 4HP modules, including a DSP variant with audio ADC/DAC and companion Arduino-Pico sketches for delay, reverb, chorus, flanger, pitch shifter, granular, ladder filter, sampler, and looper.

**Why it matters:** This is a rare useful mix of PCB-level Eurorack constraints and firmware examples. It covers compact mechanical constraints, codec/front-end choices, CV/audio coupling decisions, and real-time RP2350 DSP partitioning.

**Implementation highlights:**

- 2HPico can generate CV or audio from a PT8211 path scaled to Eurorack levels.
- 2HPico DSP uses PCM1808 audio ADC and PCM5102A audio DAC.
- 4HPico DSP adds stereo audio in/out, two CV inputs, OLED, and encoder UI.
- Core split is explicitly described: core 0 handles UI/control, core 1 handles DSP and I2S output.
- Practical caveats are documented: DC-input jumper behavior, AC-coupled PCM5102A output limitation, PT8211 part-quality risk, and scope-pin DSP-load monitoring.

**Platform relevance:** RP2350 / Pico 2, RP2040-adjacent audio, Eurorack DSP, compact codec/front-end design, Arduino-Pico, DaisySP-derived DSP on non-Daisy hardware.

**Adaptation ideas:**

- Use the hardware notes as a compact Eurorack codec/CV/audio front-end reference.
- Port selected sketches to Daisy Field/Pod or Teensy for performance comparison.
- Reuse the “scope pin shows DSP-core load” debug pattern for real-time overrun visibility.

**Quick engineering assessment:** Best item today. It is not just source code; it is a hardware/firmware co-design reference with current 2026 board/sketch activity and explicit bring-up caveats.

**Sources:** [hardware repo](https://github.com/rheslip/2HPico-Eurorack-Module-Hardware), [DSP sketches](https://github.com/rheslip/2HPico-DSP-Sketches), [2HPico sketches](https://github.com/rheslip/2HPico-Sketches)

### 2) [`newdigate/teensy-polyphony`](https://github.com/newdigate/teensy-polyphony) — **PASS**

**Technical summary:** Teensy Audio Library sampler layer for multi-polyphonic audio samples. It depends on `teensy-variable-playback`, supports sample/voice abstractions, and includes examples using MIDI note events, resampled array playback objects, envelopes, mixers, and I2S output.

**Why it matters:** `newdigate/teensy-variable-playback` was already published on 2026-05-25, but this is a separate abstraction layer: voice allocation, sample mapping, note triggering, and sampler model structure. That makes it useful as the “instrument layer” above the lower-level variable-rate playback primitive.

**Implementation highlights:**

- Uses Teensy Audio Library objects rather than a custom full audio engine.
- Supports polyphonic sample triggering via MIDI note on/off.
- Uses `audiovoice`, `audiosample`, `samplermodel`, `polyphonic`, and `arraysampler` abstractions.
- README history notes a 2025 refactor to generic `audiovoice<T>` and `audiosample<T>`.

**Platform relevance:** Teensy 4.x / Teensy Audio, sampler engines, MIDI-triggered sample playback, library-level voice allocation.

**Adaptation ideas:**

- Use as a reference for sampler voice management before writing a Daisy sampler.
- Compare Teensy Audio graph-style composition against a hand-written Daisy audio callback.
- Extract the model/voice/sample separation for a file-backed looper/sampler UI.

**Quick engineering assessment:** Useful, but not independent enough for STRONG_PASS because it leans on the already-published `teensy-variable-playback` foundation. Still valid under anti-repeat because this repo itself was only previously a HOLD/watchlist item, not a published digest entry.

**Sources:** [repo](https://github.com/newdigate/teensy-polyphony)

### 3) [`JordanAceto/micro-pico`](https://github.com/JordanAceto/micro-pico) + [`JordanAceto/VCF_plug_in_boards`](https://github.com/JordanAceto/VCF_plug_in_boards) — **PASS**

**Technical summary:** Hardware-dominant tiny analog monosynth centered on two SSI2130 VCOs, minimoog-style ADS envelope generators, modulation LFO, SSI2162 VCA, swappable VCF port, and multiple patch points. The companion VCF board repo defines a common plug-in filter-card format with modular-level signal expectations and DAC-friendly cutoff/feedback CV ranges.

**Why it matters:** Not embedded DSP, but directly useful for embedded-audio hardware exploration. It is a clean analog voice-card pattern that could pair with MCU-generated CV, MIDI-to-CV, preset recall, calibration tooling, or hybrid Daisy/Teensy/RP2350 control.

**Implementation highlights:**

- Two SSI2130 VCOs with sine, triangle, saw, pulse, and sync options.
- Final linearized SSI2162 VCA.
- Aux FM, PWM CV, VCF cutoff CV, VCA CV, white-noise, and internal signal patch points.
- VCF plug-in cards share a common mechanical/electrical format and expect Eurorack-style power and signal levels.
- VCF cutoff/feedback CV range is chosen around a small unipolar DAC-friendly range.
- The main `micro-pico` README states the synth is safe to build.

**Platform relevance:** SSI2130, SSI2140, SSI2162, analog voice cards, Eurorack CV/audio, MCU-controlled analog synth expansion.

**Adaptation ideas:**

- Pair the VCF card concept with a Daisy/Teensy/RP2350 digital control board.
- Use the DAC-control range as a filter cutoff/resonance control reference.
- Treat it as an analog voice target for OXI One sequencing through a MIDI/CV bridge.

**Quick engineering assessment:** Strong hardware-learning value and better partitioning than many DIY analog synth repos. Firmware value is low, but the mixed-signal adaptation value is high.

**Sources:** [micro-pico](https://github.com/JordanAceto/micro-pico), [VCF plug-in boards](https://github.com/JordanAceto/VCF_plug_in_boards)

### 4) [`raspy135/Qun-synthesizer`](https://github.com/raspy135/Qun-synthesizer) — **PASS**

**Technical summary:** ESP32-LyraT analog-modeling synthesizer engine for Nunomo/QUN hardware. The project combines synth engine, sequencer, looper, MIDI routing, UI modes, patch flow, and external audio/CV considerations.

**Why it matters:** ESP32 audio projects often stop at toy synth or I2S demo level. This one is closer to a complete embedded instrument with enough system-level detail to be useful even if you do not build the exact hardware.

**Implementation highlights:**

- Built around ESP32-LyraT, originally smart-speaker hardware.
- MIDI path is explicitly constrained: TRS-A/UART-style MIDI, BLE MIDI, and MIDI UART rather than standard USB-MIDI.
- Engine includes envelopes, FM, granular/sampler mode, LFO, VCF, clipping algorithms, and delay/chorus/flanger.
- Looper records up to 30 seconds, synchronized to the sequencer, with three tracks and stereo panning.
- UI includes mode/sub-mode selection and catch behavior to avoid parameter jumps.

**Platform relevance:** ESP32-LyraT, ESP32 synth firmware, MIDI UART/BLE MIDI, compact instrument UI, looper/sequencer integration.

**Adaptation ideas:**

- Mine the catch-mode UI idea for small-screen instruments.
- Use the MIDI UART limitations as a hardware-selection warning for ESP32 synth projects.
- Compare ESP32-LyraT headroom against Daisy/Teensy/RP2350 for instrument-class DSP.

**Quick engineering assessment:** Good whole-device reference. Less attractive than Daisy/Teensy/RP2350 for high-headroom DSP, but better than most ESP32 synth repos for instrument integration.

**Sources:** [repo](https://github.com/raspy135/Qun-synthesizer)

### 5) [`Farmer2K5/daisy-fast-stft`](https://github.com/Farmer2K5/daisy-fast-stft) — **REF_PASS**

**Technical summary:** Header-oriented C++ FFT/STFT/ISTFT framework for Daisy Seed using CMSIS-DSP. It covers RFFT wrappers, streaming STFT, inverse STFT, windowing, spectral conversions, spectral operations, and feature extraction such as centroid, flux, rolloff, spread, and flatness.

**Why it matters:** Spectral DSP on Cortex-M7 is easy to get wrong. This repo is useful as an architecture reference for buffer handling, COLA reconstruction, mag/phase versus complex-domain processing, and feature extraction before writing your own freeze, morph, pitch, or adaptive spectral effect.

**Implementation highlights:**

- Daisy Seed / Cortex-M7 target.
- CMSIS-DSP real FFT wrapper.
- STFT and ISTFT with overlap-add reconstruction.
- Mag/phase and complex-domain processing modes.
- Examples for high-cut spectral processing, phase modulation, offline resynthesis, feature extraction, and spectral morphing.
- Explicitly marked experimental/WIP, so it is a reference candidate rather than a drop-in dependency.

**Platform relevance:** Daisy Seed, Cortex-M7, CMSIS-DSP, spectral FX, freeze/morph/pitch-shift groundwork, feature extraction.

**Adaptation ideas:**

- Use as a scaffold for Daisy Field spectral effects with OLED feature visualization.
- Combine with SDRAM delay lines for freeze/reverb/granular experiments.
- Port selected abstractions to Teensy 4.x and compare CMSIS-DSP behavior.

**Quick engineering assessment:** Correct lane is REF_PASS, not PASS. It is not mature enough to blindly depend on, but it is a compact, useful STFT design reference.

**Sources:** [repo](https://github.com/Farmer2K5/daisy-fast-stft)
