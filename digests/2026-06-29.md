### 1) [LouDnl / USBSID-Pico](https://github.com/LouDnl/USBSID-Pico) — **STRONG_PASS**

**Technical summary:**

USBSID-Pico is an RP2040/RP2350 board for driving one or two MOS SID chips or SID-compatible hardware emulators from a computer, phone, WebUSB player, ASID-capable player, or USB MIDI controller. Firmware support includes CDC/WebUSB playback, USB MIDI synth use, Cynthcart-derived special firmware, embedded USBSID-Player modes, release builds, firmware manuals, and a separate configuration tool.

**Why it matters:**

This is one of the better hardware-first finds because it is not just a nostalgia board. It is a complete small audio hardware product around a difficult mixed-signal IC family:

```text
Pico / Pico 2 host
→ SID voltage/clock/audio support
→ dual socket / stereo routing
→ USB/WebUSB/MIDI firmware
→ browser/config tool workflows
→ documented PCB revisions and caveats
```

The useful engineering lesson is the support envelope around the sound chip: 5 V plus 9/12 V SID rails, clock generation, socket configuration, audio filtering, stereo/mono routing, firmware variants, configuration tooling, and ground-loop/audio-noise caveats.

**Implementation highlights:**

- Supports Raspberry Pi Pico/Pico W and Pico 2/Pico 2 W, covering RP2040 and RP2350 targets.
- Interfaces one or two MOS SID chips or replacements such as SIDKick-Pico, ARMSID, FPGASID, and SwinSID.
- Firmware features include custom CDC protocol, WebUSB, MIDI/ASID input, USB MIDI device operation, Cynthcart special firmware, and embedded USBSID-Player for PSID/RSID/PRG/P00 playback.
- Firmware can be built with Pico SDK 2.1.1 plus TinyUSB; release/build/status badges and releases are documented.
- v1.3 board supports mixed 9 V / 12 V SID socket voltage, three filtered SID regulators, PIO-generated 1 MHz clock, stereo/mono switching, C64-style audio filter, and expansion pins.
- v1.5 development direction adds improved voltage/audio filtering, ESD diode on audio port, extra SID rail filter capacitors, soft pull-down on headphone jack, automatic per-socket 9/12 V and filter/shunt/digiboost configuration, and a volume daughterboard path.

**Hardware/electronics notes:**

**Hardware modifiability: mixed but still strong enough for promotion.** v1.0 has open KiCad project and Gerber files, schematic, iBOM, CC BY-SA hardware license, and OSHWA certification. v1.3 has schematic, iBOM, Gerbers and board manuals, but the README states the v1.3 KiCad project is “not yet” available and the v1.3 license is CC BY-NC-ND, which blocks derivative hardware work. v1.5 is not yet released and hardware license is still TBD.

The v1.3/v1.5 electronics notes are the valuable part: separate SID voltage rails, 5 V step-up, 9/12 V mixed-SID support, audio filter modeled on C64 schematics, optional 6581 resistor, EXT-IN pulldown option, and documented hum/ground-loop behavior. This is not a clean low-noise audio design benchmark, but it is a very useful practical SID bring-up reference.

**Platform relevance:**

RP2040, RP2350, Pico/Pico 2, TinyUSB, Pico SDK, MOS6581, MOS6582, MOS8580, SIDKick-Pico, FPGASID, ARMSID, WebUSB, USB MIDI, ASID, Cynthcart, SID playback, chiptune hardware.

**Adaptation ideas:**

- Use the board/manual structure as a template for a retro-chip audio board with browser configuration.
- Study the mixed 9 V / 12 V socket handling before designing any multi-SID or multi-voice derivative.
- Reuse the WebUSB + USB MIDI + embedded player split for other chip-synth boards.
- Treat the ground-loop warning as a reminder to decide early whether the device is USB-powered audio gear, standalone battery gear, or isolated line-level hardware.

**Quick engineering assessment:**

**STRONG_PASS.** Excellent hardware/product depth and practical caveats. The ranking is based on system utility and hardware bring-up value, not on clean editability of the newest board revision. For derivative hardware, v1.0 is the modifiable baseline; v1.3/v1.5 are references unless licensing/source status changes.

**Caveats / verification gaps:**

- No firmware build or board test was run.
- v1.3 source-hardware modifiability is restricted by missing KiCad source and CC BY-NC-ND licensing.
- v1.5 is not released; its hardware license is TBD.
- Real SID chips are scarce and can be damaged; the project itself warns use is at your own risk.
- MIDI support is described as still in beta / in development in parts of the documentation.

**Sources:**

- [USBSID-Pico repository](https://github.com/LouDnl/USBSID-Pico)
- [USBSID-Pico Configtool](https://github.com/LouDnl/USBSID-Pico-Configtool)

### 2) [rafaelmartins / db-synth](https://github.com/rafaelmartins/db-synth) — **STRONG_PASS**

**Technical summary:**

`db-synth` is a MIDI-controlled mono digital synthesizer built on AVR DB microcontrollers. It uses the AVR128DB28 or AVR64DB28 in DIP-28, opto-isolated MIDI input, MIDI thru, SSD1306 OLED, internal 10-bit DAC at 48 kHz, and two internal opamps configured as unity-gain buffer plus second-order reconstruction filter. Firmware is bare-metal C with oscillator, ADSR, amplifier, and filter pipeline.

**Why it matters:**

This is the cleanest small-source-hardware synth today. It is not flashy, but it is unusually complete and inspectable:

```text
DIP AVR DB MCU
→ internal DAC + internal opamps
→ MIDI input/thru
→ OLED status UI
→ CMake bare-metal firmware
→ KiCad PCB + OpenSCAD enclosure
```

For hardware adaptation, this is useful because it exercises underused AVR DB peripherals in an audio context: internal DAC, opamps, EEPROM, USART MIDI, I2C OLED, and timer-polled 48 kHz loop.

**Implementation highlights:**

- Hardware: AVR128DB28 / AVR64DB28, 6N137 optocoupler MIDI input, MIDI thru output, OLED I2C, 5 V power, audio out connector.
- Audio path: internal 10-bit DAC, 2.5 V reference, OPAMP0 unity buffer, OPAMP1 second-order low-pass reconstruction filter.
- Firmware: bare-metal C, 48 kHz polled main loop using TCB0 at 24 MHz / 500 cycles.
- DSP path: band-limited wavetable oscillator, ADSR envelope, velocity/amplifier scaling, first-order IIR low-pass/high-pass filter, DAC clamp/output.
- Build: AVR GNU Toolchain, CMake 3.25+, Ninja/Make, generated ELF/HEX/fuse/map outputs.
- Flashing: UPDI with fuse HEX first, firmware HEX second; rolling automated builds are available.
- Non-blocking OLED update and incremental EEPROM writes avoid blocking the audio pipeline.

**Hardware/electronics notes:**

**Hardware modifiability: strong.** KiCad source files are under `pcb/`, schematic PDF, interactive BOM and Gerbers are linked, hardware is CERN-OHL-S-2.0, firmware is BSD-3-Clause, and OpenSCAD enclosure source is under `3d-models/`.

Electronics value is in the minimalist signal chain: the AVR DB internal DAC and opamps reduce external audio parts, while the 6N137 MIDI input keeps a proper isolated MIDI input. It is not hi-fi by modern codec standards, but as a compact MIDI monosynth platform it is a clean, modifiable reference.

**Platform relevance:**

AVR128DB28, AVR64DB28, AVR DB internal DAC/opamps, UPDI, CMake, bare-metal C, fixed-point DSP, MIDI DIN, 6N137, SSD1306, EEPROM presets, OpenSCAD enclosure.

**Adaptation ideas:**

- Use as a small MIDI-controlled voice card or desktop drone/synth engine.
- Replace the MIDI-only control model with a compact pot/encoder panel using the same core board.
- Port its generated-table approach to RP2040/RP2350 or STM32 for higher-resolution DAC/I2S output.
- Study whether AVR DB internal opamps are good enough for low-cost synth voice prototypes.

**Quick engineering assessment:**

**STRONG_PASS.** The project is small, but the hardware/source/license/build evidence is unusually clean. It ranks high because it is easy to inspect and modify, not because it is the most powerful synth.

**Caveats / verification gaps:**

- No build/flash/test run was performed.
- 10-bit DAC and AVR DB performance limit sound quality and DSP complexity.
- No dense physical control surface; it is mainly MIDI-controlled with OLED feedback.
- Analog reconstruction filter topology was not reviewed against measured noise/THD.

**Sources:**

- [db-synth repository](https://github.com/rafaelmartins/db-synth)
- [db-synth hardware documentation](https://rafaelmartins.com/p/db-synth/hardware/)
- [db-synth firmware documentation](https://rafaelmartins.com/p/db-synth/firmware/)
- [db-synth rolling release](https://github.com/rafaelmartins/db-synth/releases/tag/rolling)

### 3) [Tympan / Tympan Rev E Hardware + Tympan Library](https://github.com/Tympan/Tympan_Rev_E_Hardware) — **PASS**

**Technical summary:**

Tympan Rev E is an open Teensy 4.1-based audio board design with electronics and case files. Unlike a simple Teensy audio shield, Rev E incorporates the Teensy 4.1 into a custom design. The companion Tympan Library provides Arduino/Teensyduino examples and audio-processing support derived from the Teensy Audio Library.

**Why it matters:**

This is not a synth project in itself, but it is a serious standalone programmable audio I/O platform. It is useful as a reference for custom Teensy-based audio products where the control MCU, audio I/O, enclosure, and user-facing board behavior are integrated rather than stacked as dev boards.

**Implementation highlights:**

- Rev E hardware repo contains electronics and case designs for a Tympan Rev E v2 board.
- The design is based on Teensy 4.1 and integrates it into the Tympan board rather than using a daughter-card approach.
- Repository contains an enclosure area, main board design directory, Blender/case assets, schematic PDF, PJRC Teensy 4.1 schematic reference, and MIT license.
- Tympan Library documents Rev E as Teensy 4.1 and provides setup guidance for Arduino IDE / Teensyduino.
- Library examples include audio pass-through and basic gain; the hardware includes a blue volume knob used in example interaction.
- The suggested USB type is Serial + MIDI + Audio, making it a practical audio/MIDI device test platform.

**Hardware/electronics notes:**

**Hardware modifiability: good.** The hardware repo exposes electronics and case design files plus schematic PDF, and the top-level license is MIT. Exact CAD format/source completeness was not exhaustively inspected, but the repository is clearly intended as hardware-source evidence rather than Gerber-only fabrication output.

The main value is mixed-signal audio product architecture: a custom Teensy 4.1 board with audio I/O, enclosure, battery/portable-device style assumptions, and a maintained library/workflow. It is a better fit as an audio product platform or measurement/prototyping base than as an immediate synth module.

**Platform relevance:**

Teensy 4.1, Arduino IDE 1.8.x, Teensyduino, USB Serial + MIDI + Audio, Teensy Audio Library lineage, programmable audio I/O, portable embedded audio platform, enclosure design.

**Adaptation ideas:**

- Use Rev E as a reference for integrating Teensy 4.1 directly into a custom audio board.
- Compare its board/enclosure structure with Daisy-based custom hardware before committing to a platform.
- Use the library examples as bring-up smoke tests for pass-through, gain, serial control, and audio routing.
- Adapt the platform concept into a field recorder, hearing-test box, audio analyzer, or compact synth/effect prototype.

**Quick engineering assessment:**

**PASS.** Strong enough hardware-source/audio-platform value to publish, but it is ranked below synth-specific hardware because the project is a programmable audio board rather than a complete music instrument.

**Caveats / verification gaps:**

- No schematic-level review of codec/audio front end was performed.
- No hardware build, firmware upload, or audio measurement was run.
- The Tympan Library setup notes reference older Arduino IDE / Teensyduino versions, so current toolchain friction is possible.
- Not a standalone synth/groovebox by itself.

**Sources:**

- [Tympan Rev E Hardware](https://github.com/Tympan/Tympan_Rev_E_Hardware)
- [Tympan Library](https://github.com/Tympan/Tympan_Library)
- [Tympan forum](https://forum.tympan.org/)

### 4) [polykit / polykit-x-monosynth + polykit-x-voice-card](https://github.com/polykit/polykit-x-monosynth) — **PASS**

**Technical summary:**

Polykit X1 is an analog semi-modular, patchable monosynth interface that works with the Polykit-X voice card. The voice card contains an AS3340 VCO, AS3310 envelope generator, AS3372E four-pole VCF / dual input mixer / VCA / panning VCA, analog switches, op-amps, CV/pin interface, tuning procedure, and BOM. The interface board adds LFO, wavefolder, two-channel mixer, attenuator, buffered multiple, offsets, power supply, front panel, and 3D printable case.

**Why it matters:**

This is mostly analog rather than embedded, but it is strong enough to rank under the current hardware-first bias. The useful pattern is the voice-card/interface split:

```text
voice card
→ calibrated analog VCO/VCF/VCA/ADSR core
→ 36-pin signal/control interface
→ semi-modular control/patch panel
→ case/front-panel hardware
```

That architecture is relevant if the target is a hybrid synth: digital controller/sequencer/preset brain plus analog voice card.

**Implementation highlights:**

- Voice card has saw/triangle/pulse VCO, multiple VCAs, external input, envelope-controlled VCA, filter frequency/resonance modulation, inverted modulation paths, PWM, FM, hard/soft sync, and stereo output panning.
- Filter section provides 8 responses via pole-mixing: 4P/2P low-pass, high-pass, band-pass, 3P all-pass + 1P low-pass, and notch.
- 36-pin interface documents ground, ±12 V, ±5 V, pitch CV, PWM, FM, sync, ADSR CVs, gate/trigger, level CVs, filter controls, external input, and stereo outputs.
- Tuning procedure covers 1 V/oct calibration using tune/scale/HFT trimmers.
- Interface board adds LFO waveform blend, wavefolder, mixer, attenuator, buffered multiple, offsets, power supply, patching, front panel and case files.
- BOMs list AS3340, AS3310, AS3372E, TL072/TL074, 4016, CD4051, regulators, controls, switches, jacks, and passives.

**Hardware/electronics notes:**

**Hardware modifiability: good but license unclear.** The voice-card README explicitly states schematics and KiCad PCB layout are in the repo. The monosynth interface README states it contains schematics, PCB layout and front panel; Gerbers and front panel files are linked. The repo-level license was not found in this run, so commercial or derivative assumptions should be downgraded.

Electronics value is high: this is not a generic op-amp utility board. The voice card is a complete analog subtractive voice with SSI/CEM-style blocks, pole-mixing filter responses, calibrated 1 V/oct VCO, envelope, sync, FM, CV control and stereo panning. The interface board shows how to turn the card into a playable semi-modular desktop instrument.

**Platform relevance:**

AS3340 VCO, AS3310 ADSR, AS3372E VCF/VCA/mixer/panning, TL072/TL074, CD4051, 4016, analog semi-modular synth, CV/gate, 1 V/oct, front panel, 3D printed case, hybrid voice-card architecture.

**Adaptation ideas:**

- Use the 36-pin voice-card interface as a model for a digitally controlled analog voice card.
- Add an RP2350/Teensy/Daisy control board for preset recall, MIDI/CV conversion, modulation matrix, and calibration assist.
- Study the AS3372E pole-mixing filter approach against SSI2140/SSI2144 alternatives.
- Reuse the interface/voice-card split for a small desktop synth rather than Eurorack.

**Quick engineering assessment:**

**PASS.** It is outside the embedded-firmware centerline, but the analog hardware value is high and directly useful for hybrid synth design. It stays below the first three because source license is not verified and no firmware/build path exists.

**Caveats / verification gaps:**

- No license file was found during this run.
- No schematic-level review, SPICE simulation, or hardware build verification was performed.
- Mostly analog; no embedded firmware unless extended with a digital controller.
- AS3372E/AS3310/AS3340 sourcing and substitute risk should be checked before planning a build.

**Sources:**

- [polykit-x-monosynth](https://github.com/polykit/polykit-x-monosynth)
- [polykit-x-voice-card](https://github.com/polykit/polykit-x-voice-card)
