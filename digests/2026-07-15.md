### 1) [friedpies/kelpie-pocket-synth](https://github.com/friedpies/kelpie-pocket-synth) — **PASS**

**Lane:** Standalone MIDI subtractive synthesizer

#### Technical summary

Kelpie is a compact mono/polyphonic digital subtractive synth built around a Teensy 3.2-class Cortex-M4 and SGTL5000 codec. It has dual oscillators, noise, resonant filtering, envelopes and LFO, controlled by 16 pots, four illuminated buttons and MIDI CC. DIN MIDI input, quarter-inch line output, stereo headphone output and USB power make it a self-contained desktop instrument.

#### Why it matters

The project combines the electronics, firmware, enclosure and assembly thinking needed to move from development board to product. Its most reusable element is the direct, legible control architecture: the front panel is dense enough to be musical without becoming a multiplexing experiment, while the audio path and MIDI interface remain conventional and modifiable.

#### Implementation highlights

- PlatformIO/Arduino C++ firmware for monophonic and polyphonic operation.
- SGTL5000 codec/DAC audio path and DIN MIDI input.
- Sixteen knobs, four LED buttons and mapped MIDI CC 102–119.
- Separate system and control electronics with an explicit parts library and manufacturer links.
- FDM and resin-print enclosure work, stencil tooling and repeated prototype assembly.
- Three complete prototypes documented; a second hardware revision and external user-feedback unit were built.

#### Hardware and electronics notes

**Hardware modifiability:** editable Autodesk Eagle schematic/PCB source is present; the parts library supports BOM export; Fusion 360 enclosure source and printable variants are present. Build photographs and multiple assembled revisions are documented. A final revision-locked production BOM, regenerated Gerbers and formal calibration/production-test specification were not verified.

The SGTL5000/Teensy generation is now the main risk. A derivative should check current module availability, codec lifecycle, USB/MIDI ESD, regulator headroom, output DC protection and codec clock/ground coupling. Sixteen analog controls also merit ADC-noise, settling and control-to-audio feedthrough measurements. The MIT licence is explicit at repository root, but a hardware-specific licence would remove ambiguity for physical derivatives.

#### Platform relevance

- **Very high:** compact standalone synth and controller architecture.
- **High:** editable enclosure/control-surface reference.
- **High:** direct product adaptation potential.
- **Medium:** modern sourcing without replacing the Teensy 3.2-era compute module.

#### Adaptation ideas

1. Port the DSP and control scan to Teensy 4.1, STM32H7/Daisy or RP2350 while preserving the panel layout.
2. Add preset storage, USB MIDI class support and a small display only if it does not compromise immediacy.
3. Replace the codec/module pair with a current MCU + codec board and publish measured noise, headroom and latency.
4. Convert the enclosure into a parametric family for mono, poly and effects variants.
5. Add fixture-driven tests for every pot, LED, MIDI byte and audio channel.

#### Quick engineering assessment

**Promote, but respin before production.** The project is unusually complete for a personal build and is directly reusable. Treat the existing Eagle design as a validated architectural reference, then modernise the compute/codec and regenerate a controlled manufacturing package.

#### Caveats / verification gaps

- The repository has not shown recent development; available evidence is mostly from 2019–2020.
- The author mentioned additional desired revisions, so the latest source should not be assumed production-final.
- No current audio measurements, EMC results or thermal/supply tests were found.
- Modern availability of the exact Teensy 3.2/SGTL5000 combination must be checked before committing a derivative.

### 2) [picoTracker alternate PCB + canonical firmware](https://github.com/ijnekenamay/picotracker_alt-pcb) — **PASS**

**Lane:** Handheld tracker, sampler and MIDI sequencer

#### Technical summary

This is a two-repository ecosystem: an editable alternate handheld carrier in [ijnekenamay/picotracker_alt-pcb](https://github.com/ijnekenamay/picotracker_alt-pcb) and the active [xiphonics/picoTracker firmware](https://github.com/xiphonics/picoTracker). The carrier uses an RP2040 Pico LiPo module, ILI9341 display, PCM5102 DAC module, SD breakout, Kailh keys, MIDI optocoupler, stereo amplifier and two PCB halves that also form the enclosure.

The firmware provides eight tracks, 256 chains, 128 phrases, 32 tables, sample/MIDI/SID/OPAL instruments, stereo 16-bit/44.1 kHz output, SD storage and MIDI I/O. Release v2.3.1 was published on 2026-03-25, and repository activity continued in May 2026.

#### Why it matters

The project is a credible path from an open tracker engine to a buildable handheld device. Unlike many tracker ports, it includes physical controls, display, storage, MIDI, audio output, battery-oriented compute and a practical enclosure strategy. The ecosystem also illustrates a useful pattern: keep active application firmware separate from derivative carrier boards.

#### Implementation highlights

- Eight-channel tracker with sample, MIDI, SID and FM-style OPAL instruments.
- Editable KiCad carrier with schematic/PCB source, BOM, Gerbers and production-marked MIDI fix.
- Two-PCB enclosure, 3D-printed back panel and build photographs/video.
- PCM5102 DAC, SD storage, display, keys, headphone/speaker amplification and MIDI input.
- Canonical firmware is BSD-3-Clause; alternate hardware repository is MIT.
- Active firmware release and maintenance evidence in 2026.

#### Hardware and electronics notes

**Hardware modifiability:** editable KiCad source is present, with schematic/PCB project, Gerbers, BOM and enclosure STL. The back panel is printable but a parametric mechanical source was not verified. Build evidence is present. The design relies on several breakout modules rather than integrating the DAC, display, storage and power circuitry directly.

The breakout approach lowers entry cost but creates stack height, connector reliability, ground-return and sourcing risks. PCM5102 module implementations vary, so reconstruction filtering, output muting, analogue rail quality and jack protection should be audited on the exact selected module. The RP2040 firmware documents performance limits under eight simultaneous tracks, and sample space is constrained by flash copying.

#### Platform relevance

- **Very high:** portable sampler/tracker and MIDI sequencer.
- **High:** active open firmware with derivative hardware ecosystem.
- **Medium-high:** modifiable handheld mechanics and controls.
- **Medium:** production adaptation, because the carrier is module-heavy.

#### Adaptation ideas

1. Integrate the DAC, SD interface, power path and MIDI circuitry into a single modern carrier revision.
2. Move to RP2350 or a higher-memory MCU while retaining firmware compatibility and the control layout.
3. Add measured headphone level, output noise, SD-current transients and battery-runtime data.
4. Publish a revision-locked approved-parts list for the display and PCM5102 modules.
5. Create a desktop control-surface variant with full-size MIDI and balanced audio.

#### Quick engineering assessment

**Promote as an ecosystem.** The earlier firmware-identification and MIDI-readiness gaps are resolved. It is a strong prototype/derivative base, though a product should consolidate the breakout modules and validate the complete analogue/power path.

#### Caveats / verification gaps

- The alternate carrier is not the canonical hardware sold by Xiphonics.
- Exact compatibility between the current firmware release and every alternate-board revision was not independently built.
- RP2040 sample memory and concurrent-track performance limits remain real.
- No formal EMC, battery safety or audio-performance test report was found.

#### Sources

- [Alternate hardware repository](https://github.com/ijnekenamay/picotracker_alt-pcb)
- [Canonical firmware repository](https://github.com/xiphonics/picoTracker)
- [picoTracker engineering notebook](https://democloid.com/)

### 3) [MeeBlip/meeblip-triode](https://github.com/MeeBlip/meeblip-triode) — **REF_PASS**

**Lane:** Legacy standalone MIDI monosynth reference

#### Technical summary

MeeBlip triode is a compact monophonic MIDI synthesizer with editable Eagle system and control boards, firmware source and explicit open-hardware terms. The firmware history documents band-limited wavetable transitions, raw lower-octave waveforms, front-panel scanning, envelope/filter curve changes and MIDI-clock fixes through version 1.20.

#### Why it matters

Triode is a clean reference for a small commercial-grade synth split into system and control boards. It demonstrates how a modest processor, direct controls and simple analogue support circuitry can become a focused instrument. The explicit CC BY-SA 4.0 hardware licence and GPLv3 firmware/docs are materially clearer than the implicit reuse terms on many old DIY designs.

#### Implementation highlights

- Separate editable Eagle control-board and system-board schematics and PCBs.
- PDF schematics for both boards.
- Monophonic MIDI firmware with band-limited tables and front-panel scanning.
- Explicit hardware, firmware and documentation licensing.
- Mature product lineage rather than an unbuilt CAD exercise.

#### Hardware and electronics notes

**Hardware modifiability:** editable Eagle .sch and .brd files are verified for both boards; schematic PDFs are present. No current KiCad conversion, enclosure/panel CAD, revision-locked BOM, pick-and-place package or modern production-test document was verified.

The main engineering value is the board partition and control/audio integration, not its exact legacy MCU or component choices. Before reuse, inspect supply protection, MIDI input compliance, DAC/PWM reconstruction, output headroom and obsolete parts. Convert the design to a maintained EDA format only after validating the original netlist and board revision.

#### Platform relevance

- **High:** simple standalone MIDI synth architecture.
- **High:** clearly licensed hardware reference.
- **Medium:** modern derivative after component and toolchain migration.
- **Low:** drop-in present-day manufacturing without reconstruction work.

#### Adaptation ideas

1. Recreate the two-board architecture in KiCad with current MCU, USB-C and tested MIDI circuitry.
2. Preserve the immediate front panel while adding patch storage and firmware update support.
3. Use the original firmware tables as regression references for a modern fixed-point implementation.
4. Publish measured oscillator aliasing, filter response, noise and control zippering before release.

#### Quick engineering assessment

**Reference and modernise.** The source and licensing are real, but this is a legacy design rather than a current fabrication package. It earns promotion for reusable hardware architecture, not for turnkey production readiness.

#### Caveats / verification gaps

- Repository activity and hardware revision history are old.
- No contemporary BOM/AVL, enclosure source or production-test fixture was found.
- The exact shipped-product revision should be reconciled against repository CAD before fabrication.
- Current component availability and regulatory performance were not assessed.
