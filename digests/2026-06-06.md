## 1. Eight4aWish / eurorack_modules — STRONG_PASS

Repository:

```text
https://github.com/Eight4aWish/eurorack_modules
```

Companion electronics repo:

```text
https://github.com/Eight4aWish/eurorack_electronics
```

### Technical summary

Multi-target Eurorack firmware monorepo covering:

- Teensy 4.1
- Raspberry Pi Pico 2 W / RP2350
- Daisy Seed
- ESP32
- Arduino Nano ESP32 / ESP32-S3
- Ksoloti Big Genes / STM32F429

The repo includes several concrete module targets:

- `teensy-move`
- `pico2w-oc`
- `daisy-mfx`
- ESP32 clock/link utilities
- experimental web/CV-controlled module work
- Ksoloti Elements port

### Why it matters

This is the strongest find today because it is not just one firmware sketch. It is a practical multi-platform Eurorack firmware lab with useful patterns for:

- calibrated CV
- MIDI clock
- OLED UI
- audio passthrough
- embedded effects
- DAC expanders
- web control
- codec/ADC/DMA handling

### Implementation highlights

`teensy-move`:

- Teensy 4.1 controller and sound source
- CV/gate outputs
- DAC expander channels
- drum triggers
- chord/drone synth
- SGTL5000 passthrough
- USB MIDI + Serial
- MIDI clock
- static calibration arrays

`pico2w-oc`:

- Pico 2 W Eurorack utility
- SSD1306 OLED
- ADS1115 inputs
- MCP4728 quad DAC
- patches for Clock, Quant, Euclid, Env, QuadLFO, Scope, Calib, and Diag

`daisy-mfx`:

- Daisy Seed multi-FX
- Reverb and Delay banks
- CV takeover
- tap-tempo
- patch-change wet fade
- shimmer warm-up
- OLED sleep/wake
- 48 kHz audio path

`ksoloti-elements`:

- STM32F429 + ADAU1961 Mutable Instruments Elements port
- 36 resonator modes
- OLED UI
- CV assignment
- V/OCT
- FM
- gate/velocity
- visible resource accounting

### Hardware/electronics notes

Useful hardware references appear across the repo:

- SGTL5000 audio codec
- MCP4822 / MCP4728 DAC use
- ADS1115 analog input
- bipolar CV outputs
- Schmitt-triggered clock/reset paths
- ADAU1961 codec bring-up
- calibrated V/OCT-style output mapping

### Adaptation ideas

- Use `teensy-move` as a MIDI-to-CV/chord-drone reference for OXI-driven hybrid hardware.
- Compare `pico2w-oc` MCP4728 calibration against Pico/RP2350 utility-module plans.
- Lift `daisy-mfx` CV takeover and patch-change wet-fade patterns into Daisy Pod/Field code.
- Use the Ksoloti Elements port as an STM32F4/codec comparison point against Daisy or Teensy Mutable DSP ports.

### Assessment

**Best item today.** Dense, current, and reusable.

Main caveat: maturity varies by subproject. Verify the companion electronics repo before copying any analog/CV front end.

## 2. CyberDuck79 / Mutables_Daisies — PASS

Repository:

```text
https://github.com/CyberDuck79/Mutables_Daisies
```

Plaitsy subproject:

```text
https://github.com/CyberDuck79/Mutables_Daisies/tree/main/plaits
```

### Technical summary

Daisy Patch / Patch.Init-oriented porting framework for selected Mutable Instruments modules.

The current concrete port is `Plaitsy`, a Daisy Patch port inspired by Plaits with:

- common menu UI
- configurable I/O
- SD-card presets
- MIDI support
- audio-rate modulation
- configurable CV outputs
- ladder filtering
- limited polyphony

### Why it matters

The important architecture is the hardware-virtualization layer:

```text
Mutable Instruments DSP core
→ libDaisy hardware abstraction
→ screen/encoder UI
→ configurable modulation
→ SD-card presets
```

This is directly useful for complex Daisy modules where the physical control count is lower than the original Mutable module.

### Implementation highlights

- common UI library for parameter editing
- I/O mapping
- SD-card preset recall
- SD user-data loading for:
  - 6-op FM banks
  - wavetables
  - waveterrain data
- Python tools for:
  - custom wavetable generation
  - waveterrain generation
  - SysEx conversion
- MIDI trigger/pitch/velocity modulation
- MIDI passthrough
- Warps-style audio input processing:
  - crossfade
  - folding
  - ring modulation
  - XOR
  - compression
  - FM
  - vocoder-like processing
- CV outputs usable as:
  - envelope
  - AD envelope
  - LFO
  - envelope follower

### Hardware/electronics notes

Daisy Patch is the main target because the screen, encoder, and I/O make this kind of “virtual module panel” practical.

Patch.Init support is mentioned as a future direction, but it is not the current main target.

### Adaptation ideas

- Reuse the common UI/preset approach for complex Daisy modules.
- Use the SD user-data workflow for wavetable or FM-bank loading.
- Compare this “preserve DSP core” strategy against direct DaisySP rewrites.
- Use CV outputs as modulation outputs instead of always treating outputs as audio.

### Assessment

Strong **PASS**.

Not `STRONG_PASS` because the broader Mutable Instruments roadmap is still future work; the concrete available port is mainly Plaitsy.

https://github.com/tommyyork/resynthesis/blob/main/Resynthesis.cpp

Daisy Patch.Init spectral/granular resynthesis firmware.

Incoming audio is processed as overlapping FFT grains with:

- phase propagation
- V/OCT pitch control
- spectral flattening
- bright/dark tilt
- sparsity
- phase diffusion
- overlap-add resynthesis

### Why it matters

This is useful as a **reference**, not as trusted production code.

The valuable parts are:

- CV-addressable spectral processing
- explicit offline/hardware distinction
- V/OCT harmonic tests
- CV sweep tests
- panel-generation workflow
- detailed control mapping

### Implementation highlights

- overlapping FFT-grain analysis/resynthesis
- spectral pitch and timbre controls
- dry/wet crossfade
- wet-gain smoothing
- loudness compensation
- soft clipping
- compressor / MAX COMP stage
- OpenOCD/GDB debug target
- panel preview generation
- block-diagram generation
- V/OCT and CV regression tests

### Hardware/electronics notes

Target hardware is Daisy Patch.Init.

The panel-generation work may be useful beyond this specific effect, but the mechanical assumptions appear project-specific.

### Adaptation ideas

- Use the V/OCT harmonic tests as a template for pitched spectral processors.
- Reuse CV sweep tests for regression testing Daisy effects.
- Lift the dry/wet + compressor + soft-clip output chain for experimental spectral modules.
- Adapt the panel-generation scripts for repeatable Eurorack documentation/panel artwork.

### Assessment

Correct lane: **REF_PASS**.

The architecture is interesting, but implementation correctness should be treated as unverified until compiled, profiled, and tested on hardware.

## 4. JerrySievert Patch.Init mini-algorithms — PASS

Projects:

```text
https://github.com/JerrySievert/PADSynth
https://github.com/JerrySievert/Pulsar
https://github.com/JerrySievert/PitchShiftedReverb
```

### Technical summary

Small Daisy Patch SM / Patch.Init algorithm set:

- `PADSynth`: PAD synthesis using FFT-built wavetables
- `Pulsar`: Curtis Roads-style pulsar synthesis
- `PitchShiftedReverb`: DaisySP pitch shifter into stereo reverb

### Why it matters

These are small, understandable, buildable Patch.Init algorithms.

They are useful because each repo isolates one idea cleanly:

```text
one algorithm
+ clear CV mapping
+ simple build flow
+ make program-dfu
```

### Implementation highlights

`PADSynth`:

- Gaussian-profiled harmonics
- FFT-generated wavetables
- evolving stereo pads
- double-buffered wavetable crossfade over 100 ms

`Pulsar`:

- windowed sinusoidal bursts
- formant ratio control
- envelope-shape control
- V/OCT offset
- modulation CVs
- gate-reset behavior

`PitchShiftedReverb`:

- pitch shifting
- stereo reverb
- CV modulation for:
  - reverb time
  - pitch shift
  - damping
  - dry/wet mix

### Hardware/electronics notes

Assumes Daisy Patch SM / Patch.Init I/O.

No custom analog front end; value is firmware-level algorithm isolation.

### Adaptation ideas

- Use `PADSynth` as a seed for evolving pad work on Daisy Field.
- Port `Pulsar` into a drum/percussion voice.
- Combine pitch-shifted reverb with spectral CV sweep testing.
- Use the minimal control-table README style for small Daisy algorithms.

### Assessment

Solid **PASS**.

Not broad enough for `STRONG_PASS`, but more reusable than many larger sketch dumps.

## 5. ijfarrell / PlanterExamples — REF_PASS

Repository:

```text
https://github.com/ijfarrell/PlanterExamples
```

### Technical summary

WIP examples and hardware abstraction for the Anachrome Electronics Planter Eurorack module.

Planter is a 14HP Daisy Patch SM interface/extender with:

- six knobs
- three toggle switches
- one momentary button
- two gate inputs
- two gate outputs
- four CV inputs
- two bipolar CV outputs
- stereo audio I/O

### Why it matters

This is not primarily a DSP repo.

The value is the hardware/control-surface envelope: it shows a more realistic Patch SM Eurorack interface than bare Patch.Init.

### Implementation highlights

- hardware abstraction in `planter.h` / `planter.cpp`
- examples included
- libDaisy and DaisySP submodule flow
- Patch SM bootloader notes
- front-panel USB-C programming path
- example DFU flashing workflow

### Hardware/electronics notes

The declared I/O set is strong for Eurorack DSP prototyping:

```text
stereo audio
+ 4 CV inputs
+ 2 bipolar CV outputs
+ 2 gate inputs
+ 2 gate outputs
+ 6 knobs
+ switches
+ button
```

### Adaptation ideas

- Use the Planter I/O envelope as a reference for custom Patch SM panels.
- Compare its 14HP control density against Patch.Init and full-size Daisy Patch.
- Port one of the small Patch.Init algorithms above to this richer control surface.
- Reuse the front-panel programming notes as a deployment checklist.

### Assessment

Correct lane: **REF_PASS**.

Ranked because the hardware/control envelope is useful and source-visible. Kept below the algorithm repos because the repo is WIP and full hardware design completeness was not verified.
