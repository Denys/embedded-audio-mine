## 1) [emeb / dspod](https://github.com/emeb/dspod) — **STRONG_PASS**

**Technical summary:**

`dspod` is a small ecosystem of audio DSP boards. The root README lists a Eurorack carrier plus daughterboards for CV1800B Linux SoC, RP2350, ESP32-S3, STM32H7R3, STM32U3C5, and iCE40UP5K FPGA. The carrier provides Eurorack power, ST7789 LCD, CV interfaces, stereo audio I/O, trigger/gate I/O, and an encoder. The STM32U3C5 daughterboard adds NAU88C22 codec audio I/O, PSRAM, PDM mic support, Si5351 clocking, firmware projects, and bench-tested integration with audio/CV/LCD/encoder working.

**Why it matters:**

This is the best engineering find today because it is not just firmware and not just a single target board. It is a reusable modular architecture:

```text
Eurorack carrier
→ audio/CV/gate/UI front end
→ swappable compute daughterboards
→ STM32 / RP2350 / ESP32-S3 / FPGA / Linux SoC experiments
→ comparable audio-DSP bring-up envelope
```

For embedded-audio product thinking, the carrier/daughterboard split is the high-value pattern: one analog/UI/power front end, many compute experiments.

**Implementation highlights:**

- Root repo defines a multi-board ecosystem with `dspod_module` carrier and daughterboards for CV1800B, RP2350, ESP32-S3, STM32H7R3, STM32U3C5, and iCE40UP5K.
- Eurorack carrier provides front panel, +5 V and ±12 V power, 320×170 ST7789 IPS LCD, four CV inputs with offset pots, stereo ±7 V audio inputs and outputs, trigger/gate input and output, and encoder with pushbutton.
- Carrier design materials are in KiCad 9 format with schematic and PCB layout.
- STM32U3C5 daughterboard includes STM32U3C5RI Cortex-M33, USB-C, PSRAM, NAU88C22 stereo codec, PDM mic input, Si5351 clock generator, 4-channel muxed ADC, stereo line I/O, and SWD/debug paths.
- Firmware projects exist for subsystem driver testing; the board has been assembled, bench tested, and integrated with the carrier with audio I/O, CV input, LCD, and encoder control functional.
- DSP evidence is unusually specific: a stereo phase-vocoder spectral freeze using 512-point real FFTs uses about 700 µs from a 1333 µs I2S buffer-processing budget.

**Hardware/electronics notes:**

The useful hardware pattern is the carrier, not only the U3C5 daughterboard. The carrier normalizes Eurorack power, CV/audio scaling, gate buffering, display, and encoder UI. The U3C5 daughterboard then makes an interesting low-power DSP experiment around the STM32U3 HSP vector coprocessor. The repo also documents clock-quality concerns: internal MSI phase noise is called out as not ideal for audio, so the design provides a Si5351 external clock path. That is the kind of engineering caveat that is usually missing from hobby audio repos.

**Platform relevance:**

STM32U3C5, STM32H7R3, RP2350, ESP32-S3, iCE40UP5K, CV1800B, Eurorack, NAU88C22 codec, PDM microphone, ST7789 UI, SAI/I2S DMA, PSRAM, spectral DSP.

**Adaptation ideas:**

- Use the carrier/daughterboard split as a reference for testing Daisy Seed, Pico 2, ESP32-S3, or STM32H7 on the same Eurorack front end.
- Mine the U3C5 HSP notes for deciding whether a low-power M33 + accelerator is actually worth it against H7/RP2350 for audio.
- Reuse the spectral-freeze timing budget as a sanity check for real-time FFT effects on small MCUs.
- Study the CV/audio ±7 V front-end assumptions before adapting to pedal-level audio.

**Quick engineering assessment:**

**STRONG_PASS.** It has hardware files, firmware, bench evidence, real I/O, UI, and unusually honest performance/caveat notes. License status still needs verification before commercial derivative use.

**Caveats / verification gaps:**

- No build or hardware test was run in this digest.
- Top-level license was not clearly verified in this run.
- Detailed analog front-end schematic review was not performed.
- U3C5 HSP looks promising but not a drop-in H7 replacement; the 16 kB HSP-local memory limit is material for FFT-heavy DSP.

**Sources:**

- Root project structure: [emeb/dspod](https://github.com/emeb/dspod).
- Carrier and daughterboard evidence: GitHub README files and project docs in [emeb/dspod](https://github.com/emeb/dspod).

## 2) [apfaudio / eurorack-pmod](https://github.com/apfaudio/eurorack-pmod) — **STRONG_PASS**

**Technical summary:**

`eurorack-pmod` is an open-hardware Eurorack module that connects FPGA development boards to a Eurorack audio/CV front end. It uses an AK4619 codec path for four inputs and four outputs, supports DC-coupled audio/CV use, exposes a PMOD interface, and ships Verilog DSP examples including pitch shifting, filter, touch-CV, sampler, digital echo, VCA, VCO, and bitcrusher. The repo includes KiCad hardware, fab Gerbers/BOM, gateware drivers, calibration tooling, and CI-tested builds.

**Why it matters:**

This is the strongest non-MCU find. The previously published digest already covered downstream Teensy/Daisy TDM bridges, but the root platform is different enough to rank: it is the reusable audio/CV front-end and FPGA gateware baseline.

```text
AK4619 codec + Eurorack levels
→ PMOD bridge
→ FPGA dev board
→ Verilog DSP cores
→ calibration memory
→ VCV / simulation / open CAD path
```

**Implementation highlights:**

- OSHWA certification confirms project `DE000135`, with hardware/software/documentation under CERN-OHL-S-2.0.
- Repo README describes it as open hardware for FPGA-based Eurorack audio synthesis.
- R3.3/R3.5 notes include 3HP format, 4-in/4-out DC-coupled channels, 192 kHz / 32-bit sampling support, jack insertion detection, EEPROM calibration, output LEDs, touch sensing on unused jacks, output mute JFETs, and improved analog-domain regulation.
- Example cores include pitch shift, resonant low-pass filter, touch-CV, clock divider, WAV sampler, sequential switch, digital echo, VCA, VCO, and bitcrusher.
- Build flow uses Yosys/OSS CAD Suite and `make`; CI covers builds.
- Hardware/fab directories contain KiCad design files, Gerbers, and BOM.

**Hardware/electronics notes:**

This is a serious front-end pattern: AK4619 multi-channel codec, DC-coupled Eurorack range, calibration EEPROM, jack detection, LEDs, and mute staging. The calibration path matters because DC-coupled CV/audio I/O is only useful if offset/gain error is managed, especially for V/oct-ish use.

**Platform relevance:**

FPGA audio, iCE40, ECP5, GateMate experimental path, PMOD, AK4619, Eurorack, Verilog DSP, VCV simulation, hardware front-end for digital modular experiments.

**Adaptation ideas:**

- Use as the audio/CV front-end benchmark for a custom RP2350 or Daisy multichannel board.
- Port simple cores conceptually to C++ on Daisy/Teensy to compare FPGA vs MCU latency and determinism.
- Use its calibration architecture as a model for DC-coupled CV accuracy.
- Study mute-stage and analog regulator revisions before designing your own codec board.

**Quick engineering assessment:**

**STRONG_PASS.** Strong hardware, licensing, documentation, and DSP examples. Not a beginner build, but very high adaptation value.

**Caveats / verification gaps:**

- Repository notes say some Verilog docs still refer to R3.3 while R3.5 is shipping; compile flags matter.
- FPGA dev board is external; this is not standalone by itself.
- No gateware build was run.

**Sources:**

- GitHub repository: [apfaudio/eurorack-pmod](https://github.com/apfaudio/eurorack-pmod).
- OSHWA certification page and Hackaday article.

## 3) [mattybrad / drumkid2](https://github.com/mattybrad/drumkid2) — **PASS**

**Technical summary:**

`drumkid2` is a Raspberry Pi Pico-based Eurorack aleatoric drum machine. The repo README says it contains both Pico code and PCB files. The manual describes a sample-based rhythm engine driven by probability controls, CV inputs, trigger outputs, clock I/O, two audio outputs at 44.1 kHz, SD-card sample kits, live edit, and step edit.

**Why it matters:**

This is a good hidden practical device rather than a DSP toy. The algorithmic value is the performance mapping: probability, density, cluster, crop, crush, pitch/reverse, velocity range, magnet, swing, and channel-drop controls are mapped directly to knobs/CV for a playable Eurorack drum module.

**Implementation highlights:**

- Runs on Raspberry Pi Pico; repo contains code and PCB files.
- Manual documents four-sample rhythm generation with random insertion/removal logic.
- Parameters include chance, zoom, cluster, crop, crush, pitch/reverse, velocity, velocity range, magnet, swing, drop-random, and drop-all.
- I/O includes clock in/out, four per-channel trigger outputs, four CV inputs, and two 44.1 kHz audio outputs.
- CV inputs add to knob values, clamp at ±5 V for most parameters, and pitch allows extra range.
- Editing model supports live edit and step edit; beats can be saved.

**Hardware/electronics notes:**

The hardware value is the dense Eurorack control surface and mixed audio/trigger/CV I/O. The manual implies a performance-oriented panel: many knobs, clock, triggers, CV modulation, sample kits, and stateful editing. This is directly relevant to drum-machine or sampler module design.

**Platform relevance:**

Raspberry Pi Pico, Eurorack sampler/drum machine, SD-card samples, 44.1 kHz audio output, CV/trigger/clock integration.

**Adaptation ideas:**

- Port the random-beat model into a Daisy/Pico standalone desktop drum box with MIDI clock.
- Lift the probability/cluster/magnet control mapping for generative sequencer firmware.
- Use the CV summing/clamping behavior as a UI reference for Eurorack parameter modulation.
- Compare Pico audio path/noise with RP2350 + I2S DAC for a cleaner successor.

**Quick engineering assessment:**

**PASS.** Strong device concept, source + PCB claim, detailed manual, and dense control model. It stays below STRONG_PASS because build artifacts/license/PCB details were not deeply inspected.

**Caveats / verification gaps:**

- No firmware build was run.
- License was not verified.
- PCB files were not opened in detail.
- Audio output topology needs inspection before assuming fidelity or output-level compliance.

**Sources:**

- GitHub repository: [mattybrad/drumkid2](https://github.com/mattybrad/drumkid2).
- Manual: [`docs/manual.md`](https://github.com/mattybrad/drumkid2/blob/main/docs/manual.md).

## 4) [alexlafetra / stepchild](https://github.com/alexlafetra/stepchild) — **PASS**

**Technical summary:**

`stepchild` is a Raspberry Pi Pico-based generative MIDI instrument and experimental songwriting sequencer. It has hardware files for main/CV/step-sequencer boards, BOM, rack-mount MIDI breakout, Eurorack faceplate, case STLs, silkscreen graphics, and software called ChildOS. Functionally it offers step sequencing, CC automation, envelope data, live MIDI looper, arpeggiator, CV output, program-change sequencing, MIDI console, 4 MIDI outputs, 1 MIDI input, TRS/DIN MIDI, and USB MIDI.

**Why it matters:**

It is not an audio synth, but it is a strong embedded music-device reference: dense MIDI routing, CV bridge, filesystem, editor workflow, and a physical standalone/rack-mount form factor. It is particularly relevant if the target is a MIDI/CV utility or sequencer rather than a sound generator.

**Implementation highlights:**

- Hardware v0.9.2 includes main, CV, and step-sequencer breakout PCBs plus BOM.
- Case files include top/bottom shell, battery and Eurorack compartment clips, and silkscreen graphics.
- Software can be flashed using Arduino IDE or PlatformIO/VS Code.
- ChildOS contains sequencer, looper, automation function generator, 16 instrument slots, and 24 FX slots for user C++ extensions.
- LittleFS is used for saved songs/sequences; Java companion tool can download saved files and convert `.child` files to MIDI.

**Hardware/electronics notes:**

The interesting hardware detail is not audio; it is routing and control density. The device exposes four MIDI outputs and one MIDI input through both TRS and DIN, plus USB MIDI and CV output. The repo also has rack-mount/Eurorack-related hardware, battery/euro compartment clips, and a switchable +3.3 V / +12 V hardware note.

**Platform relevance:**

Raspberry Pi Pico, USB MIDI, TRS/DIN MIDI, CV output, LittleFS, embedded sequencer UI, Eurorack/rack-mount control device.

**Adaptation ideas:**

- Use as a MIDI-router/sequencer UI reference for OXI/Hydrasynth/desktop synth integration.
- Reuse the LittleFS + companion-converter idea for pattern exchange.
- Study the multi-port MIDI routing model before designing a dedicated MIDI/CV utility.
- Consider replacing non-audio generation with embedded synth voices or a USB-host path.

**Quick engineering assessment:**

**PASS.** Strong hardware/software package and UI ambition. It is outside pure audio DSP but inside the MIDI/CV device lane.

**Caveats / verification gaps:**

- Physical design uses CC BY-NC-SA, so commercial derivative use is restricted.
- No hardware build or firmware flash was performed.
- Exact CV output range/precision needs schematic inspection.

**Sources:**

- GitHub repository: [alexlafetra/stepchild](https://github.com/alexlafetra/stepchild).

## 5) [tonystuart / music-device-lab](https://github.com/tonystuart/music-device-lab) — **REF_PASS**

**Technical summary:**

`music-device-lab` is an experimental ESP32 standalone music-device lab. It is less polished than the ranked hardware platforms, but the value is in the accumulated bring-up record: wavetable/SoundFont-style synthesis, LVGL/touch menu system, music editor, auto-harp performance mode, ESP32 Audio Kit, VS1053, CS4344 I2S DAC, MAX9814 microphone, ILI9341/XPT2046 touch display, MPR121 capacitive touch sensors, and multiple PCB/wire-wrap prototype revisions.

**Why it matters:**

This is a good “engineering scars” entry. It documents what worked and what failed across several ESP32 instrument prototypes: breakout-board adapter PCBs, LED/switch polarity mistakes, Bluetooth latency, FluidSynth constraints, noisy wire-wrapped audio, and the eventual move toward ESP32 Audio Kit/AC101/I2S amplifier hardware.

**Implementation highlights:**

- Project objective is a standalone electronic music instrument.
- Building blocks include wavetable synthesis, LVGL hierarchical touch menu UI, music editor, auto-harp-inspired performance mode, and reusable libraries.
- Music Machine v01 integrates ESP32, TFT touch display, VS1053 MIDI/audio codec board, and two MPR121 modules for 24 capacitive touch inputs.
- v02 tests a 100×100 mm PCB with 40 surface-mount tactile switches and 40 LEDs; notes capture BLE MIDI, Bluetooth audio latency, FluidSynth CPU/memory constraints, tactile-force problems, and LED polarity bring-up error.
- v04 documents CS4344 I2S DAC + MAX9814 microphone experiments and explicitly calls out excessive audio noise from breadboard/wire-wrap/breakout construction.
- v05/v06 move toward ESP32 Audio Kit / ESP32-A1S / AC101 codec and I2S amplifier hardware, with touch keyboard and auto-harp-inspired interaction.

**Hardware/electronics notes:**

The most useful part is the negative evidence. The repo explicitly says breakout-board/wire-wrap approaches are fine for digital but can be noisy for audio, with 60 Hz hum and CPU/video transients observed. That is a useful sanity check when considering quick ESP32 audio prototypes.

**Platform relevance:**

ESP32, ESP32 WROVER, ESP32 Audio Kit, ESP32-A1S, AC101 codec, VS1053, CS4344 I2S DAC, MAX9814 mic, MPR121 capacitive touch, ILI9341/XPT2046 display, LVGL-style UI.

**Adaptation ideas:**

- Mine the auto-harp layout idea for a compact MIDI controller/synth.
- Treat v04 noise notes as a warning against breadboard/wire-wrap audio paths.
- Reuse the SoundFont-style wavetable + touch UI pattern with a cleaner codec carrier.
- Compare ESP32 Audio Kit constraints against RP2350 + external DAC for a small standalone synth.

**Quick engineering assessment:**

**REF_PASS.** It is not a clean buildable product, but it has unusually useful iteration notes and hardware/software architecture ideas.

**Caveats / verification gaps:**

- Not a polished release/build package.
- Firmware build path was not verified.
- License was not verified.
- Hardware design files were not deeply inspected.

**Sources:**

- GitHub repository: [tonystuart/music-device-lab](https://github.com/tonystuart/music-device-lab).
