## 1. Daily digest markdown

### 1) [`clevelandmusicco/HothouseExamples`](https://github.com/clevelandmusicco/HothouseExamples) — **STRONG_PASS**
Freshest meaningful Daisy find today. On **May 7, 2026**, Cleveland Music Co. announced four new fully commented analog-pedal-style examples plus precompiled binaries in release [`v26.05.1`](https://github.com/clevelandmusicco/HothouseExamples/releases/tag/v26.05.1): Amnesia Delay, EchoKing, Glowjob Photon Vibe, and TriPhase Theorem. The repo already has scaffolding scripts, dev-container support, and a flasher path, so this is unusually close to “flash, learn, steal ideas.”  
Sources: [Daisy forum post](https://forum.electro-smith.com/t/hothouseexamples-updated-with-new-examples-and-binaries/9146), [repo README](https://github.com/clevelandmusicco/HothouseExamples/blob/main/README.md), [release](https://github.com/clevelandmusicco/HothouseExamples/releases/tag/v26.05.1)

### 2) [`bk40-home/Jteensy8000`](https://github.com/bk40-home/Jteensy8000) — **PASS**
A strong PJRC-forum discovery from **May 21, 2026**: a Teensy 4.1 synth that began as a JT-4000 clone and grew into a JP-8000-flavored instrument with OB-Xa and VA filter-bank work, supersaw-related audio changes, USB host/audio support, and a browser-based editor. It is not polished, but the adaptation value is high because the interesting parts are modular and stealable: custom filters, waveform mods, supersaw work, and synth control architecture.  
Risk: still rough, thin docs, and the repo currently lacks a README.  
Sources: [PJRC thread](https://forum.pjrc.com/index.php?threads/jteensy8000-clone-of-a-clone-with-extra-filters.77776/), [repo](https://github.com/bk40-home/Jteensy8000)

### 3) [`windysynth/windy1`](https://github.com/windysynth/windy1) — **PASS**
This one was updated on **May 13, 2026** and is more interesting than a generic Teensy synth: it is a **USB host synth for wind controllers** with patch editing compatibility via the Vyzex EWI4000S editor. The reusable ideas are the controller-specific UI/patch flow, power-down pop mitigation, and PSRAM-aware delay handling.  
Risk: it depends on a forked Teensy Audio library and a forked `hexefx_audiolib_F32`, so portability is not zero-effort.  
Sources: [repo README](https://github.com/windysynth/windy1/blob/main/README.md), [repo](https://github.com/windysynth/windy1)

### 4) [`postcode-x/Daisy_SPC`](https://github.com/postcode-x/Daisy_SPC) — **REF_PASS**
A nicely weird Daisy Seed project from **April 1, 2026**: an **SNES SPC player** using the `snes_spc` emulator, built for **QSPI flash mode**, with an explicit embedded-asset pipeline for converting `.spc` files into `song.h`. Not a broad product template, but a good reference for emulator-on-Daisy layout, QSPI deployment, and self-contained media embedding.  
Risk: expects a specific `DaisyExamples/seed` placement and requires manual asset preparation before it will build.  
Sources: [repo README](https://github.com/postcode-x/Daisy_SPC/blob/main/README.md), [repo](https://github.com/postcode-x/Daisy_SPC)

### 5) [`ARM-software/CMSIS-DSP`](https://github.com/ARM-software/CMSIS-DSP) — **FOUNDATION_UPDATE**
Manufacturer/core infrastructure item, included only because the **v1.17.0 release on February 4, 2026** is materially useful for embedded audio work. The standout bits are buffer-size helper APIs for transforms plus fixes around Helium-targeted filtering and FFT-adjacent correctness. This is not a digest “feature project,” but it is worth tracking if you are doing Cortex-M spectral work or maintaining your own STFT/FFT stack.  
Sources: [release v1.17.0](https://github.com/ARM-software/CMSIS-DSP/releases/tag/v1.17.0), [repo README](https://github.com/ARM-software/CMSIS-DSP/blob/main/README.md)
