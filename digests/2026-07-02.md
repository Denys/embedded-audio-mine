### 1) [LTVA1/STM32CrapSynth](https://github.com/LTVA1/STM32CrapSynth) — **PASS**

**Technical summary:**

`STM32CrapSynth` is a deliberately rough but technically interesting hybrid hardware/software synthesizer built around an STM32F303RE, four AD9833 waveform generators, an MM5437 noise generator, and an LTC1063 low-pass-filter concept. The repo includes a KiCad board project, CMSIS-register-level firmware, a PC-side serial sender, and a Furnace tracker fork path for emulation/export.

**Why it matters:**

This is not a polished product platform, but it is valuable as a hardware-synthesis experiment with unusually concrete implementation notes. It exposes several useful design patterns and failure modes:

```text
tracker / command stream
→ PC export / serial sender
→ STM32F303 command executor
→ AD9833 + PWM/DAC/noise channels
→ analog summing / attenuation / filter path
→ 3.5 mm audio output
```

The engineering value is partly in the caveats: wrong jack footprint, damaged filter, partial board ownership, external command flash, and mixed AD9833/PWM/DAC/noise signal paths. These are exactly the kinds of constraints hidden by prettier synth repos.

**Implementation highlights:**

- Hardware/software synth based on STM32F303RE, four AD9833 waveform generators, MM5437 noise generator, and LTC1063 low-pass-filter path.
- `board` directory is described as the KiCad project for the top PCB.
- Firmware is written directly against CMSIS register definitions, with no HAL/LL/SPL dependency.
- PC-side CLI program sends data to the MCU; the repo also links a Furnace tracker fork with emulation and export support.
- Device is described as eight audio channels summed to a standard 3.5 mm output.
- Phase-reset behavior uses MCU timers plus USART/UART peripherals configured as timer-like periodic interrupt sources.
- External flash stores command dumps executed at a timed rate.

**Hardware/electronics notes:**

The hardware is interesting because it combines chip-based waveform generation, MCU-generated PCM/PWM channels, digital command playback, analog attenuation, and noise generation rather than being another codec-board DSP sketch. The top board uses muxes to select between MCU PWM and AD9833 signals into attenuator paths. Noise generation can use either its own internal oscillator or an MCU-generated external clock/control path. The author explicitly notes that a wrong jack footprint required a wire-to-jack adapter and that the intended filter path was damaged, so this is engineering-reference material rather than a board to copy blindly.

**Hardware modifiability:**

- Editable CAD/source: **KiCad top-board source claimed in repo structure**.
- Schematic/PCB source: **likely present under `board`, not deeply parsed in this run**.
- Full-system source: **partial**. The author states the whole device has three PCBs, but only the top PCB was designed by the repo author.
- Fabrication-only status: **not just Gerbers**, but full modifiability is incomplete because lower boards are not under equivalent evidence.
- License: **not verified**.

**Platform relevance:**

STM32F303RE, AD9833, MM5437, LTC1063, CMSIS bare-metal firmware, Furnace tracker export/emulation, mixed digital/analog sound-generation hardware.

**Adaptation ideas:**

- Reuse the command-stream/export concept for a hardware wavetable/chiptune synth controlled by SD/flash playback.
- Replace AD9833 blocks with RP2350/Daisy/STM32 DDS or codec-based voices and keep the tracker-export architecture.
- Mine the mux/attenuator/noise-reset ideas for a semi-digital drum voice board.
- Treat the wrong-footprint/filter-failure notes as a bring-up checklist for mixed-signal synth prototypes.

**Quick engineering assessment:**

**PASS.** It is not production-clean, but it has rare educational value: real hardware, firmware, command tooling, explicit failures, and a nontrivial hybrid synthesis architecture. It outranks cleaner-looking but hardware-thin repos because the circuit/system evidence is more concrete.

**Caveats / verification gaps:**

- No firmware build or board-file parse was run.
- License was not verified.
- Only the top PCB is clearly attributable to this repo.
- The filter path is known problematic/damaged.
- Audio fidelity/output-stage suitability is unknown.

### 2) [elephark/TeensyPoly41](https://github.com/elephark/TeensyPoly41) — **PASS**

**Technical summary:**

`TeensyPoly41` is a Teensy 4.1-based hardware synth PCB derived from the older TeensyPoly6 concept. The value is the control-surface hardware: a single 2-layer board with pots, switches, buttons, muxes, state LEDs, and a rotary MIDI-channel selector mounted directly on the PCB.

**Why it matters:**

For custom synth hardware, a dense control PCB is often more reusable than the DSP code. This project is a useful pattern for a compact standalone synth panel where the Teensy handles synthesis while the front PCB handles human I/O directly, without ribbon-heavy panel wiring.

```text
Teensy 4.1
→ mux-heavy control scan
→ pots / switches / buttons / LEDs
→ MIDI channel selector
→ Teensy Audio-derived synth direction
```

**Implementation highlights:**

- Uses Teensy 4.1 instead of the discontinued Teensy 3.5 used by the predecessor.
- Single 2-layer PCB carries pots, switches, and buttons directly.
- Heavier use of multiplexers: eight instead of one, reducing pin pressure.
- Adds controls for full ADSR envelopes on amp and filter.
- Adds state/debug LEDs.
- Adds rotary selector for MIDI channel.
- GitHub page exposes KiCad project, PCB, and schematic files.

**Hardware/electronics notes:**

This is a hardware/control-surface find, not a fully verified synth product. The useful part is the physical interaction layer: direct-mounted controls, mux architecture, LEDs, and channel selection. This is highly adaptable to a Hydrasynth-like/desktop polysynth control surface, a Teensy 4.1 voice board, or a Daisy/STM32 replacement if the scanning architecture is kept but the DSP engine changes.

**Hardware modifiability:**

- Editable CAD/source: **yes, repo page exposes KiCad project files**.
- Schematic present: **yes, repo page exposes `.kicad_sch`**.
- PCB source present: **yes, repo page exposes `.kicad_pcb`**.
- BOM/build guide: **not verified**.
- Firmware: **not verified in this repo; likely depends on/derives from TeensyPoly6 concept**.
- License: **not verified**.

**Platform relevance:**

Teensy 4.1, Teensy Audio-style synths, muxed analog/digital control scanning, direct-mounted synth panel PCB, ADSR/filter controls, standalone hardware UI.

**Adaptation ideas:**

- Use the board as a reference for a custom Teensy/Daisy poly-synth control surface.
- Port the scan/control model to RP2040/RP2350 or STM32 if Teensy availability/cost is a concern.
- Split the control PCB from the audio/DSP board for cleaner product architecture.
- Compare against OpenDeck/16n-style control surfaces for dense parameter entry.

**Quick engineering assessment:**

**PASS, hardware-biased.** It ranks because editable hardware source appears present and the control-surface design is directly reusable. It is weaker than a complete firmware+hardware instrument because the firmware, BOM, and license evidence are thin.

**Caveats / verification gaps:**

- No board-file parse was run.
- Firmware path was not verified.
- License was not verified.
- BOM/build/bring-up notes were not found in this pass.

**Sources:**

- [elephark/TeensyPoly41](https://github.com/elephark/TeensyPoly41)
- [albnys/TeensyPoly6](https://github.com/albnys/TeensyPoly6)

### 3) [mzuelch/CATs-Eurosynth](https://github.com/mzuelch/CATs-Eurosynth) — **PASS**

**Technical summary:**

`CATs-Eurosynth` is a large KiCad-based Eurorack analog-synth hardware repository. It contains original/remodeled modules, production Gerber directories, KiCad corrections, custom libraries, panel/front-panel data, and a mix of working/WIP modules including VCAs, VCFs, ADSR, mixers, clocking, sample-and-hold, precision adders, and adapted MFOS/YuSynth/Haraldswerk/CGS/HAGIWO circuits.

**Why it matters:**

This is not the preferred standalone embedded-audio archetype, but it is a strong reusable hardware reference library. For analog front-end/product work, it offers a broad set of module-level circuit patterns, KiCad libraries, panel conventions, and production notes.

**Implementation highlights:**

- Repository is explicitly for analog synth Eurorack-compatible modules.
- Gerber directories are described as production data used for the author’s own prototypes.
- Corrections for finished boards marked “working” are made in KiCad.
- Hardware license is CC BY-NC-SA 4.0 unless otherwise specified.
- Code licensing is split: AVR projects GPL-3.0, STM32F projects MIT.
- Custom KiCad libraries are documented for symbols, footprints, and 3D shapes.
- Published module list includes working and WIP mixers, clock dividers, VCAs, ADSR, VCFs, sample/hold, precision adder, rectifier, switch, cases, and adapted classic synth circuits.

**Hardware/electronics notes:**

The technical value is breadth and modifiability. It is useful for mining analog building blocks around synth voice/control circuits rather than copying a complete embedded instrument. The downside is exactly the current scoring caveat: it is Eurorack/analog-first, not a standalone embedded audio device, and the NC hardware license limits commercial adaptation.

**Hardware modifiability:**

- Editable CAD/source: **yes, KiCad files and custom libraries are central to the repo**.
- Schematic/PCB source: **yes for many modules, though not individually parsed in this run**.
- Gerbers: **yes, production Gerber directories explicitly described**.
- BOM/assembly: **not uniformly verified across modules**.
- Enclosure/panel source: **front-panel/layout data present by repo description**.
- License: **hardware CC BY-NC-SA 4.0 unless specified; commercial derivative use is constrained**.

**Platform relevance:**

Eurorack analog hardware, VCA/VCF/ADSR/mixer/clock/sample-hold utility circuits, AVR/STM32 side projects, KiCad custom-library management, panel/layout conventions.

**Adaptation ideas:**

- Mine VCA/VCF/ADSR and utility circuits for hybrid analog/digital desktop synth prototypes.
- Reuse KiCad library conventions and panel mechanics as a reference, not as final CAD.
- Use working module status as a rough filter before deeper schematic review.
- Cross-check classic-circuit adaptations against original MFOS/YuSynth/HAGIWO sources before copying.

**Quick engineering assessment:**

**PASS.** Strong source-hardware library, but lower-ranked because it is not standalone and not primarily embedded audio. Useful as a circuit/panel reference, with license caveats.

**Caveats / verification gaps:**

- No individual module schematic was reviewed deeply.
- Many modules are WIP or rework; “working” labels must be checked per module.
- NC hardware license constrains reuse.
- It is analog/Eurorack-heavy, so adaptation to standalone products needs architectural filtering.

**Sources:**

- [mzuelch/CATs-Eurosynth](https://github.com/mzuelch/CATs-Eurosynth)
