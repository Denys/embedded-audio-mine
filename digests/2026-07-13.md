### 1) [buranelectrix/lunchbeat-PCB](https://github.com/buranelectrix/lunchbeat-PCB) — **PASS**

**Technical summary.** Lunchbeat is a compact 1-bit groovebox based on an ATmega328P. The repository explicitly separates firmware from hardware and states that the hardware directory contains schematics, PCB design, the complete KiCad project, and a project-specific parts library.

**Why it matters.** It is old and deliberately minimal, but it passes the most important hardware-first test: the design is actually editable rather than merely buildable from Gerbers. It is a clean reference for ultra-low-cost rhythmic instruments, direct MCU audio generation, small control surfaces, and compact single-board product packaging.

**Implementation highlights.** ATmega328P firmware in C; 1-bit audio architecture; dedicated PCB implementation rather than breadboard-only construction; source KiCad project and used-parts library; explicit licence split between firmware and hardware.

**Hardware/electronics notes.** The project claims complete schematic and PCB source. Exact analog output filtering, power topology, control scanning, and current component availability should be re-audited before reuse because of age.

**Hardware modifiability.** **Editable KiCad project present; schematic present; PCB source present; parts library present; firmware source present.** BOM/manufacturing outputs and enclosure source were not independently verified in this pass.

**Platform relevance.** Strong for tiny drum machines, pocket sequencers, educational instruments, and proof-of-concept product hardware where BOM cost and simplicity outrank audio fidelity.

**Adaptation ideas.** Replace ATmega328P with RP2350 or STM32G4; retain the simple control-panel concept; add I2S DAC/codec, USB MIDI, microSD sample playback, and a two-layer board designed for automated assembly.

**Quick engineering assessment.** High source value, low modernity. Good architecture reference and easy derivative base; poor fit for high-fidelity DSP without a substantial redesign.

**Caveats / gaps.** Old MCU, intentionally low-resolution audio, unknown present-day fabrication validation, and no verified enclosure/mechanical package.

**Sources.** [Repository](https://github.com/buranelectrix/lunchbeat-PCB) · [Project site](http://www.buranelectrix.com)

### 2) [kschzt/harp](https://github.com/kschzt/harp) — **REF_PASS**

**Technical summary.** HARP is an open protocol and reference implementation for integrating physical synths, drum machines, and effects with DAWs as recallable plugin-like devices. It covers state hashing, sample-accurate automation, UMP events, dedicated audio transport, offline rendering through hardware, multitimbral routing, reconnect/recovery behavior, diagnostics, and VST3/AU/CLAP shells.

**Why it matters.** The embedded-audio value is architectural rather than PCB-centric. HARP directly addresses one of the least-solved product problems in hardware instruments: reliable DAW recall and automation without proprietary vendor integration. The repository claims real-hardware validation on Raspberry Pi 4B, Ableton/REAPER workflows, CI, fuzzing, deterministic renders, and measured latency.

**Implementation highlights.** Versioned specification with machine-readable CDDL; portable C11 core; Raspberry Pi reference device; USB FunctionFS gadget transport; TCP simulation transport; content-addressed state; plugin shells for VST3, AU, and CLAP; multi-output and audio-FX modes; conformance harness and real-device CI.

**Hardware/electronics notes.** The current reference device is a Raspberry Pi, not a dedicated open audio PCB. Therefore HARP should be mined as protocol/product infrastructure, not mistaken for a source-hardware instrument.

**Hardware modifiability.** **Custom schematic/PCB source not verified and apparently not central to the project.** Software/spec source is extensive. Licensing is stated as Apache-2.0 for code and CC-BY-4.0 for documentation/spec material.

**Platform relevance.** Highly relevant to future standalone synths, multi-FX processors, grooveboxes, and pedals that need robust DAW integration, patch recall, automation, and deterministic rendering.

**Adaptation ideas.** Implement a constrained HARP device endpoint on STM32H7/Linux-capable CM4/CM5 hardware; expose pedal/synth parameters through the schema; add firmware-image identity and hardware-revision identity to preset bundles; pair with USB Audio Class or Ethernet AVB-style transport.

**Quick engineering assessment.** Exceptional systems-engineering reference, weak hardware-mining match. The protocol and conformance approach are more valuable than the current Pi reference instrument.

**Caveats / gaps.** No independent verification of all latency and determinism claims in this run; ecosystem adoption is still minimal; embedded MCU feasibility requires scope reduction.

**Sources.** [Repository](https://github.com/kschzt/harp)

### 3) [RealTimeAudioLab/RTAL-EAI-001-WELLENFORMER](https://github.com/RealTimeAudioLab/RTAL-EAI-001-WELLENFORMER) — **REF_PASS**

**Technical summary.** WELLENFORMER is presented as a six-voice digital wavetable synthesizer with dual wavetable oscillators, noise, resonant filtering, envelopes, stereo chorus/delay/reverb, SD storage, touchscreen control, preset memory, MIDI implementation, and an integrated graphical wavetable editor.

**Why it matters.** It is a useful product-definition reference for reducing front-panel BOM and assembly complexity through a software-defined touchscreen UI while preserving a self-contained hardware-instrument workflow.

**Implementation highlights.** Six voices; dual wavetable oscillators; direct waveform drawing and interpolation; SD-backed wavetable storage; MIDI note/velocity/bend/modulation/program/CC/clock support; touchscreen-led UI architecture.

**Hardware/electronics notes.** The repository declares `hardware/`, `firmware/`, documentation, MIDI, preset, and wavetable directories, but direct editable CAD, schematic, PCB, BOM, and manufacturing files were not verified through the available repository search interface.

**Hardware modifiability.** **Not verified.** Hardware imagery and a hardware directory are present at README level, but no editable EDA source was confirmed. This is the decisive reason it remains `REF_PASS`, not `PASS`.

**Platform relevance.** Useful for touchscreen synths, compact desktop instruments, and reduced-BOM control surfaces.

**Adaptation ideas.** Implement on STM32H7/MP1, i.MX RT1170, or CM4/CM5 plus dedicated codec; retain one or two tactile encoders for performance-critical parameters; add USB host/device MIDI and a clear manufacturing package.

**Quick engineering assessment.** Coherent instrument concept, insufficient source evidence. Worth monitoring, not yet a reliable derivative-hardware base.

**Caveats / gaps.** MCU, codec, sample rate, latency measurements, PCB source, BOM, enclosure source, licence, and reproducible build path were not verified.

**Sources.** [Repository](https://github.com/RealTimeAudioLab/RTAL-EAI-001-WELLENFORMER)
