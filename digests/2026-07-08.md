## Ranked entries

### 1) [shorepine/tulipcc + AMYboard](https://github.com/shorepine/tulipcc) — **STRONG_PASS**

**Technical summary**  
Tulip CC is an ESP32-S3 portable programmable music computer: touchscreen/display, MicroPython, AMY synthesis engine, USB keyboard/mouse/MIDI support, TRS MIDI, Wi-Fi, filesystem flash, and instant Python-prompt workflow. AMYboard is the more music-focused headless sibling/extension: ESP32-S3 + AMY synth engine, TRS/USB MIDI, stereo analog line I/O, S/PDIF in/out, ±10 V CV I/O, microSD, and I2C accessory/control expansion.

**Why it matters**  
This is closer to a real portable instrument platform than a demo board. It combines standalone use, browser editing, Python programmability, patch/sketch workflow, MIDI, CV, S/PDIF, storage, and a source-hardware build path. It also gives a strong alternative archetype to Linux/Raspberry Pi grooveboxes: a microcontroller-native, fast-boot, programmable music computer.

**Implementation highlights**

- Tulip runs MicroPython + AMY + LVGL on ESP32-S3.
- AMY engine is a 120-voice stereo synth path with FM, PCM/sampler, additive/partial synthesis, filters, Karplus-style material, sequencer-oriented workflow, and patch/sketch control.
- AMYboard exposes MIDI in/out, USB gadget MIDI, stereo line in/out, S/PDIF in/out, CV in/out, microSD, I2C accessory port, Eurorack 10HP mounting, and browser-based patch/sketch editing.
- Tulip CC build docs provide four paths: web/native first, breadboard, breakout board, or integrated SMT board.
- Integrated Tulip board v4r9 has display FPC, USB-C power/charge/flash, USB keyboard, audio/headphone jacks, MIDI in/out, power switch, and Grove/Stemma header.

**Hardware / electronics notes**

- **Modifiability:** editable KiCad project and schematic for Tulip CC v4r9 verified in repo.
- **Schematic present:** `docs/pcbs/tulip4_board_v4r9/tulipcc.kicad_sch` verified, title block `Tulip Creative Computer V4 R9A`.
- **PCB/project source present:** `docs/pcbs/tulip4_board_v4r9/tulipcc.kicad_pro` verified; board doc links KiCad files and BOM.
- **BOM:** linked in board build doc as `tulipcc-bom.xlsx`.
- **AMYboard source caveat:** AMYboard user/connector/power docs are strong, but AMYboard PCB source path was not separately parsed in this run.
- **License:** root Tulip license is MIT; submodules/third-party components carry their own licenses.

**Platform relevance**

Very strong reference for a portable synth/groovebox/control computer: fast boot, local editor, web editor, MIDI/CV/audio/S/PDIF bridge, MicroPython scriptability, and an ESP32-S3 hardware target that can be produced cheaply.

**Adaptation ideas**

- Use AMYboard as a compact synth voice/audio-CV expander controlled by a custom front panel.
- Reuse the Tulip CC pattern for a “programmable pedal/synth notebook” with a simple editor and direct hardware I/O.
- Study AMYboard’s browser/control API path as a model for WebMIDI/WebSerial patch editing.
- Extract the I2C accessory idea for detachable encoders, displays, macro panels, or a pedal controller surface.

**Quick engineering assessment**

Best ranked item today. It is not a conventional synth PCB in the Polykit analog sense, but its total product-surface value is high: real hardware, real UI, software stack, web workflow, MIDI, audio, CV, storage, and build options. The main verification gap is the AMYboard hardware source path; Tulip CC integrated-board KiCad source is verified.

**Caveats / verification gaps**

- AMYboard PCB source was not separately parsed; documentation and product/user hardware details were verified.
- The Tulip stack includes submodules and third-party dependencies; root MIT does not automatically simplify every subcomponent license.
- The exact audio analog path quality needs schematic-level review before copying the design.

### 2) [adwuard/xSynth-go](https://github.com/adwuard/xSynth-go) — **PASS**

**Technical summary**  
Portable FPGA-based synth/DSP processor around the Digilent CMOD A7 35T. The project targets interaction with the XFM2 FM synth while also positioning the baseboard as a general FPGA DSP/synth platform. The completed baseboard exposes MIDI in, MIDI thru/out, line in/out, USB-C power, UART/MIDI control, and FPC expansion for future UI/USB-MIDI/microSD hardware.

**Why it matters**  
Most hobby synth hardware is MCU, Raspberry Pi, or analog. This is a rare open FPGA audio/DSP baseboard with explicit line input, line output, MIDI, expansion headers, and XFM2 compatibility. It is useful as a bridge between synth hardware and custom FPGA DSP cores.

**Implementation highlights**

- CMOD A7 35T Artix-7 FPGA module as the compute core.
- XFM2 compatibility target.
- 3.5 mm line input and output.
- Type-A TRS MIDI input and MIDI thru/out.
- USB-C power.
- FPC pinouts for UI controller, USB MIDI, screen/keyboard controls, and future microSD.
- Altium source project exists for RevB baseboard; RevA base DSP PCB marked completed.

**Hardware / electronics notes**

- **Modifiability:** Altium project source verified: `.PrjPcb` points to `Sheet1.SchDoc`, `BaseBoard.PcbDoc`, schematic/PCB libraries, and generated DRC output.
- **Schematic/PCB source:** source project is present, but binary/Altium schematic contents were not text-parsed beyond the project manifest.
- **BOM:** README links BOM.
- **Audio path:** line-in reference from Digilent Pmod I2S2; line-out reference from Adafruit UDA1334A, per README.
- **License:** not verified; no root `LICENSE` was found in this pass.

**Platform relevance**

Good reference if future projects move toward FPGA audio: deterministic synthesis cores, custom FM/physical modeling experiments, parallel DSP, and low-latency hardware I/O. It also complements MCU projects by giving a realistic baseboard pattern for FPGA module integration.

**Adaptation ideas**

- Use the CMOD A7 + audio/MIDI baseboard as a sandbox for FPGA FM, wavetable, spectral, or delay-line DSP.
- Replace the planned UI board with a small RP2040/STM32/ESP32-S3 panel controller.
- Treat the FPC expansion strategy as a way to keep the FPGA/audio baseboard reusable across multiple front-panel concepts.

**Quick engineering assessment**

Very interesting but not yet mature enough for `STRONG_PASS`: hardware is source-based, but validation and UI are still incomplete. The FPGA lane is valuable enough to rank despite those gaps.

**Caveats / verification gaps**

- RevA validation is explicitly still on the TODO list.
- UI controller board, USB MIDI device, and microSD are future supports, not verified complete functions.
- License not verified.
- Depends on a Digilent FPGA module and XFM2-related ecosystem, not a fully self-contained MCU synth.

**Sources**

- [adwuard/xSynth-go README](https://github.com/adwuard/xSynth-go)
- [xSynth-go hardware source folder](https://github.com/adwuard/xSynth-go/tree/main/hardware)

### 3) [AidanHockey5/MegaMIDI](https://github.com/AidanHockey5/MegaMIDI) — **PASS**

**Technical summary**  
MIDI-compatible Sega Genesis/Megadrive hardware synthesizer using real YM2612/YM3438-family FM and SN76489 PSG sound chips rather than emulation. It supports USB MIDI, DIN MIDI, SD-card OPM patch loading, VGM-to-OPM patch conversion tooling, EEPROM favourites, PlatformIO/Teensyduino firmware, KiCad hardware files, and precompiled HEX releases.

**Why it matters**  
This is a strong retro-chip synth reference: real chip voice allocation, patch import tooling, USB/DIN MIDI integration, non-emulated FM character, and a playable hardware product surface. It is not modern codec/DSP hardware, but the chip+firmware+patch-tooling combination is highly reusable as an architecture pattern.

**Implementation highlights**

- Real YM2612/YM3438 + SN76489 sound generation path.
- USB MIDI and traditional DIN MIDI support.
- `.opm` patch file workflow plus included VGM-to-OPM conversion tooling.
- Seven favourite buttons storing patches in EEPROM.
- PlatformIO/Teensyduino firmware path.
- Precompiled firmware HEX releases.
- KiCad 5 schematic/PCB source verified.

**Hardware / electronics notes**

- **Modifiability:** KiCad project and `.kicad_pcb` verified.
- **PCB source:** `YM2612_MIDI_SMD.kicad_pcb` parsed with 112 modules, 127 nets, 1602 tracks.
- **Schematic:** README links schematic image; KiCad `.pro` also verified.
- **Audio path:** sound-chip outputs and analog output nets visible in PCB net list (`PSG_OUT`, `MOL`, `MOR`, `L_OUT`, `R_OUT`).
- **License:** GitHub page reports AGPL-3.0, but README also asks credit and says “please do not resell”; treat commercial reuse as legally ambiguous until license text is reviewed.

**Platform relevance**

Useful for chip-synth products, MIDI sound modules, patch librarians, and sample/patch conversion pipelines. Less relevant for modern high-fidelity audio I/O or DSP-pedal hardware.

**Adaptation ideas**

- Reuse the SD-card patch library + favourites workflow in a small hardware synth.
- Study the VGM/OPM conversion toolchain for importing retro patches into a modern FM engine.
- Use the dual USB/DIN MIDI path and EEPROM favourites as a small instrument UX reference.

**Quick engineering assessment**

Strong enough for PASS because source hardware, firmware, and releases all exist. Demoted below Tulip/xSynth because it relies on increasingly special retro ICs, uses older KiCad, and has ambiguous reuse terms.

**Caveats / verification gaps**

- Vintage sound-chip availability and counterfeit risk are practical concerns.
- README wording around resale conflicts with simple “open source” reuse expectations.
- Modern manufacturability and power/noise margins were not audited.

### 4) [monome/norns-shield](https://github.com/monome/norns-shield) — **PASS**

**Technical summary**  
Minimal open-source DIY Raspberry Pi shield providing hardware compatibility with the norns ecosystem: CS4270/CS4271 audio codec, 3.5 mm stereo line input/output, OLED, three pushbuttons, three encoders, BOM/CAD/Eagle source files, schematic PDF, and GPL-3.0 repo license.

**Why it matters**  
This is not a hidden new project, but it remains a very useful hardware reference for compact Pi-based audio instruments: codec + display + encoders/buttons + mechanical constraints + norns compatibility. It also provides an example of how a small hardware layer can unlock a large instrument ecosystem.

**Implementation highlights**

- Three hardware versions: 191106, 210330, and 211028.
- 210330 revision recommended by README for new builds.
- 211028 switches codec due to semiconductor shortage and adds op amps/passives.
- BOM, CAD, Eagle, images, license, README, and schematic PDF present.
- Eagle `.sch` and `.brd` source files for 210330 verified.

**Hardware / electronics notes**

- **Modifiability:** editable Eagle schematic and board files verified.
- **Schematic/PCB source:** `eagle/norns-shield-210330.sch` and `eagle/norns-shield-210330.brd` parsed as Eagle 7.6 XML.
- **Codec:** CS4270 or CS4271 depending on revision.
- **UI:** OLED, 3 encoders, 3 buttons.
- **License:** GPL-3.0 root license.

**Platform relevance**

Good if studying a minimal Pi-based audio instrument front end, especially display/encoder ergonomics and “small board + large software ecosystem” product strategy.

**Adaptation ideas**

- Use the codec/UI/mechanical minimalism as a reference for a small Linux audio box.
- Compare against pedalboard-hw, Zynthian, and Tulip to choose the right embedded host pattern.
- Mine norns interaction conventions for a future sampler/looper/generative instrument.

**Quick engineering assessment**

Hardware source and ecosystem value are strong, but it ranks fourth because it is well-known, no longer directly supported by monome, and is a shield rather than a fresh standalone hardware platform.

**Caveats / verification gaps**

- README says monome no longer provides direct support, kits, leftover boards, or repair service.
- No dedicated headphone output or battery indication.
- Pi 4 mechanical/noise caveats are explicitly documented.

**Sources**
