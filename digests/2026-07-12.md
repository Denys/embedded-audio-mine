# Embedded Audio Mine — 2026-07-12

## Executive summary

Today’s strongest result is **[gligli/overcycler](https://github.com/gligli/overcycler)**: a complete six-voice hybrid polysynth with editable KiCad 8 hardware, a populated JLCPCB BOM/CPL package, enclosure/panel CAD, LPC1778 firmware, MIDI, preset storage, and per-voice analog filter/VCA electronics. It was previously only a watchlist mention; today’s deeper source inspection justifies promotion.

Second is **[dkonigsberg/nestronic](https://github.com/dkonigsberg/nestronic)**, a highly integrated two-board standalone NES game-music synthesizer/alarm-clock architecture combining a real RP2A03/NES APU domain with ESP32 control, complete KiCad source, firmware, and unusually detailed enclosure/mechanical files. It is demoted from `STRONG_PASS` because no repository-wide licence was verified.

Third is **[ice458/pico_synthesizer](https://github.com/ice458/pico_synthesizer)**, a compact modern RP2350/Pico 2 multitimbral synth with editable KiCad 9 source, USB MIDI, a 40 kHz real-time audio path, drum playback, effects, and a CMake/Pico SDK build. It is promising, but the board package is materially less complete than the first two.

## Ranked entries

### 1) [gligli/overcycler](https://github.com/gligli/overcycler) — **STRONG_PASS**

**Lane:** standalone hybrid polysynth / multi-voice analog-digital instrument.

**Technical summary.** Overcycler is a six-voice hybrid synthesizer using digital single-cycle/wavetable oscillator generation under an LPC1778 control platform and a discrete per-voice analog signal path. The production BOM directly identifies six SSI2144 filters, three LM13700 dual OTAs, six MCP4922 dual DACs, an AD5674R 16-channel DAC, TLV2556 ADC, W25Q512 serial flash, DIN MIDI with 6N139 isolation, USB with ADuM3160 isolation, and dedicated isolated DC/DC rails. The source tree includes the instrument PCB, a separate voice schematic, PSU schematic, SPICE models, production BOM/CPL/Gerbers, and several enclosure/panel variants.

**Why it matters.** This is much closer to the Polykit archetype than the earlier shallow review suggested. It joins a reusable analog voice architecture, digitally managed calibration/control, production outputs, firmware, presets, MIDI, UI, and enclosure work in one coherent repository. Unlike many “hybrid synth” repositories, the hardware is not merely a block diagram or Gerber dump.

**Implementation highlights.**

- LPC1778FBD144 Cortex-M3 controller with firmware source, Makefile, bootloader/linker files and a checked-in binary.
- Six SSI2144 analog filters and LM13700-based VCA/control stages.
- MCP4922 DAC bank plus AD5674R for high-density analog control generation.
- TLV2556 ADC for control acquisition.
- W25Q512 external serial flash for presets/assets.
- DIN-5 MIDI input with 6N139 optocoupler; USB-B interface with ADuM3160 isolation.
- LCD and keyboard/control-board connectors, analog audio jacks, dedicated PSU and isolated converter parts.
- Recent firmware maintenance includes a MIDI program-change/UI refresh correction; a build manual was added in late 2024.

**Hardware/electronics notes.** The voice source is explicitly titled “Voice for OverCycler 3” and uses KiCad 8. The JLCPCB production BOM is unusually useful because it exposes exact device choices, quantities, footprints and LCSC identifiers. There are separate KiCad panel/enclosure projects and generated Gerbers. This is source hardware, not fabrication-only evidence.

**Hardware modifiability.** **Editable CAD/source present:** KiCad project, voice schematic, PSU schematic, main PCB path, symbol/footprint libraries and enclosure/panel KiCad projects. **Manufacturing present:** BOM, CPL and Gerbers. **Firmware present:** full source, build files and binary. **Mechanical:** editable panel/enclosure PCB projects. **Licence:** root GPLv3, but the licence is software-oriented rather than a hardware-specific CERN-OHL declaration.

**Platform relevance.** Excellent reference for a modern hybrid synth, especially voice calibration, high-density DAC control, isolated USB/MIDI, and integrating analog voice electronics with preset-capable embedded control.

**Adaptation ideas.**

1. Preserve the six SSI2144/LM13700 voice topology while replacing LPC1778 with STM32H7/G4 or RP2350 plus a modern USB-C MIDI/audio interface.
2. Split the present monolithic board into a serviceable control/backplane plus two-voice or single-voice cards.
3. Add per-voice current/temperature telemetry and automated V/oct/filter calibration stored in external flash.
4. Rework the enclosure/control board around a higher-resolution display, encoders and direct panel-board interconnect while retaining the analog core.

**Quick engineering assessment.** Best candidate today for direct architecture mining. The source and production evidence are strong enough to reproduce and modify, but a commercial derivative should first clarify hardware licensing and review component lifecycle, especially SSI2144 availability and the older LPC1778 platform.

**Caveats / verification gaps.** No hardware-specific licence was found. The current revision still deserves an independent ERC/DRC, analog noise/crosstalk audit, DAC-control settling analysis and thermal/calibration review before fabrication. The project is mature but not recent enough to assume every BOM item remains preferred.

### 2) [dkonigsberg/nestronic](https://github.com/dkonigsberg/nestronic) — **PASS**

**Lane:** standalone embedded sound device / chip-synth appliance / product-mechanical reference.

**Technical summary.** Nestronic is a self-contained game-music synthesizer and alarm clock built around two computational domains: a real RP2A03/NES CPU/APU section for sound generation and an ESP32 control/UI section. The main board and input board are supplied as KiCad projects with schematics and layouts; the repository also contains the RP2A03 and ESP32 firmware, enclosure models, front-panel geometry, hardware fastener specifications and print settings.

**Why it matters.** The value is not nostalgia alone. It demonstrates a clean partition between a specialized sound-generation subsystem and a modern supervisory MCU, with a dedicated input board and a real enclosure package. That architecture maps well to modern products using an FPGA/audio DSP/voice card beside a UI/network MCU.

**Implementation highlights.**

- Hierarchical main schematic with separate “NES CPU” and “ESP32 Microcontroller” sheets.
- Rev-B two-layer main PCB with 144 modules, 121 nets and 1,744 tracks.
- Separate input/control PCB.
- ESP32 firmware for UI, storage, RTC/alarm and file playback/control.
- RP2A03-side code for native NES audio execution.
- SD/MMC and display/UI stack, with later fixes to display brightness and NSF bank-switch caching.
- Detailed 3D-print and assembly notes, including heat-set insert sizes, screw specifications, panel offsets and material/process settings.

**Hardware/electronics notes.** The root schematic names the RP2A03 speaker output and ESP32 interconnect explicitly. Source fields include manufacturer and supplier part numbers rather than generic values only. The PCB and schematic are older KiCad formats but remain editable.

**Hardware modifiability.** **Editable CAD/source present:** hierarchical KiCad schematics, main PCB and input PCB. **BOM evidence:** component metadata is embedded in the schematics; README claims complete BOM support, though a clean exported BOM was not separately verified. **Mechanical:** STL/model resources, DXF references and detailed print/fastener notes. **Firmware:** ESP32 and RP2A03 source. **Licence:** not verified at repository root.

**Platform relevance.** Strong reference for a dual-processor instrument, retro-chip or FPGA sound engine, front-panel daughterboard, local speaker/display appliance, and tightly integrated mechanical design.

**Adaptation ideas.**

1. Replace the RP2A03 section with an FPGA multi-engine chip-synth core while keeping the ESP32 supervisory architecture.
2. Convert the input board to a generic encoder/key/display panel with a documented board-to-board protocol.
3. Add USB MIDI/TRS MIDI and line-level balanced output to move from alarm-clock appliance to desktop instrument.
4. Reuse the mechanical documentation discipline: defined inserts, screw lengths, panel datum offsets and print parameters.

**Quick engineering assessment.** Excellent product-integration reference and more mechanically complete than most hobby synth repositories. Less useful as a direct commercial fork because the licence is missing and the ESP-IDF/legacy KiCad stack is old.

**Caveats / verification gaps.** No clear repository-wide licence. Main design dates from 2018 despite mechanical updates in 2025. The genuine NES APU path has sourcing/legal/product-positioning limitations, and a modern redesign would need power, EMC, audio-output and firmware-toolchain requalification.

### 3) [ice458/pico_synthesizer](https://github.com/ice458/pico_synthesizer) — **PASS**

**Lane:** low-cost standalone/sound-module digital polysynth.

**Technical summary.** This Pico 2 project targets 16 MIDI channels and up to 20 voices with sine, saw, triangle, square and noise oscillators, ADSR envelopes, pitch bend/CC handling, PCM drums, master reverb, panning and DC removal. The build uses Pico SDK 2.1.1, CMake and TinyUSB; audio is generated at 40 kHz through a PIO serial-audio program while the RP2350 is overclocked to 380 MHz.

**Why it matters.** It is a useful compact reference for extracting a modern low-cost multitimbral engine and wrapping it in custom hardware. The combination of editable KiCad 9 hardware, USB MIDI, PIO audio and table-generation tooling is better than the usual breadboard-only Pico synth.

**Implementation highlights.**

- RP2350/Pico 2 target with Pico SDK 2.1.1 and GNU/CMake build.
- Up to 20 voices and 16 MIDI channels.
- USB MIDI via TinyUSB plus UART debug.
- 40 kHz fixed-rate synthesis callback and PIO serial-audio output.
- 380 MHz system-clock configuration and 1.30 V core-voltage setting.
- PCM/ADPCM drum assets, wavetable and pitch/pan table generators.
- Editable KiCad 9 two-layer PCB with BCK/DIN/WS serial-audio nets, TRS audio jack and NJU77552/NJM4558-class analog output stage.
- MIT software licence.

**Hardware/electronics notes.** The board source is genuine and parseable, but the audio-converter implementation is not documented clearly in the README. The schematic exposes serial-audio nets and an analog output stage; connector/module dependencies require a manual design review before treating it as a self-contained BOM-complete product.

**Hardware modifiability.** **Editable CAD/source present:** KiCad 9 project, schematic and two-layer PCB. **Firmware present:** C source, Pico SDK/CMake files, PIO audio and TinyUSB descriptors. **BOM:** not exported/verified. **Enclosure/panel:** not verified. **Manufacturing package:** Gerber plotting is configured, but release Gerbers/CPL/assembly docs were not verified. **Licence:** MIT at repository root, with hardware licence scope not separately stated.

**Platform relevance.** Good starting point for a cheap desktop MIDI module, educational synth, embedded General-MIDI-like engine or low-cost voice board paired with a richer control surface.

**Adaptation ideas.**

1. Move audio to a verified PCM5102A/CS4344/WM8731-class codec circuit with proper clocks, reconstruction filtering and measured output performance.
2. Add microSD/QSPI patch storage, TRS MIDI IN with optoisolation, OLED/encoder UI and preset management.
3. Replace the timer-driven sample callback with DMA-buffered audio and quantify worst-case voice/effect load.
4. Keep the engine as a voice-card firmware target and place controls/MIDI/power on a separate product board.

**Quick engineering assessment.** Worth mining for firmware architecture and low-cost hardware, but not yet product-grade. The overclocked fixed-timer audio path, absent released BOM and unclear converter/module boundary keep it below the older but much more complete Nestronic package.

**Caveats / verification gaps.** No enclosure, assembly guide, formal performance measurements or clear validation report. A 380 MHz RP2350 configuration needs margin testing across voltage, temperature and silicon. USB MIDI and audio timing coexist in the main loop without an explicit real-time budget in the docs.
