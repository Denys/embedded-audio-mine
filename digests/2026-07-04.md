## Ranked entries

### 1) [Chrismettal/PedalDev](https://github.com/Chrismettal/PedalDev) — **STRONG_PASS**

**Technical summary**  
A modular open-hardware stompbox development system built around a reusable two-board architecture. The lower board handles I/O, bypass/switching, power filtering, reverse-polarity protection, optional buffering, LED/anti-pop support, and test hooks. The upper board carries the individual effect circuit. The repository also includes specific effect boards, generic protoboards, front panels, mechanical/drill templates, and a detailed assembly flow.

**Why it matters**  
This is not just one pedal PCB. It is a reusable hardware platform for rapidly spinning compact stompbox designs in a Hammond 1590B-style mechanical envelope. For embedded/audio-device mining, the real value is the reusable lower-board architecture, upper-board template, front-panel workflow, production-file discipline, and practical build notes.

**Implementation highlights**

- Two-board stack: lower I/O/power/switching board + effect-specific upper board.
- Lower board includes footswitch/status LED, input/output jacks, power input/filtering, FET reverse-polarity protection, optional TL07x buffer, anti-pop bleeders, and debug/test hooks.
- Upper board templates include reusable schematic content, LCSC-oriented part-number workflow, and variants such as `UpperRaw`, `FrontRaw`, and `Proto-Simple`.
- Production path includes KiCad projects, schematic/PCB source, BOM, Gerbers, PCBA placement files, front panels, and 3D-printable mechanical aids.
- Build docs include mechanical order-of-operations, enclosure drilling, board/control alignment, and JLCPCB assembly assumptions.

**Hardware/electronics notes**

- **Editable CAD/source present:** yes — multiple KiCad project files are present under `pcb/*`.
- **Schematic present:** yes — multiple `.kicad_sch` files verified.
- **PCB source present:** yes — `.kicad_pcb` paths verified for templates/front panels; README claims complete project folders for designs.
- **BOM/production files:** README claims BOM, Gerbers, and PCBA placement files in project folders.
- **Mechanical source:** FreeCAD/3D-printable drilling template and enclosure workflow documented.
- **License:** CC BY-SA 4.0.

**Platform relevance**  
Highly relevant for pedal hardware, compact audio products, analog front-end packaging, stompbox I/O/power infrastructure, and mechanical/productization patterns. Less directly relevant for digital synth firmware, but excellent as a reusable hardware chassis pattern for future DSP pedal or hybrid analog/digital boards.

**Adaptation ideas**

- Replace analog upper board with Daisy Seed, Teensy 4.x, RP2350, or STM32H7 DSP upper board while keeping lower I/O/switching/power mechanics.
- Convert `Proto-Simple` into a universal CV/audio experiment board with buffered expression/CV input.
- Use the lower-board concept as a clean reusable bypass/power/I/O module for small audio products.
- Reuse front-panel/drill-template approach for low-volume synth/pedal kits.

**Quick engineering assessment**  
Top-ranked because it is source-hardware-heavy, productizable, mechanically thought through, and template-based. It is less “embedded DSP” than ideal, but the source hardware quality and platform reuse outweigh that caveat.

**Caveats / verification gaps**

- Mostly analog stompbox ecosystem, not a standalone synth or DSP board by itself.
- Some specific effect boards are explicitly WIP or broken/debugging.
- Production files are README-claimed and file-path-supported, but not every Gerber/BOM file was individually inspected in this run.

**Sources**

- <https://github.com/Chrismettal/PedalDev>
- <https://github.com/Chrismettal/PedalDev/tree/main/pcb>
- <https://github.com/Chrismettal/PedalDev/tree/main/3d>

### 2) [ohdsp/DSP-ADAU1452](https://github.com/ohdsp/DSP-ADAU1452) — **PASS**

**Technical summary**  
Open-hardware ADAU1450/ADAU1451/ADAU1452 DSP core board for the OHDSP platform. It provides 4 I2S/TDM-capable input connectors and 4 output connectors, optical/coaxial S/PDIF I/O on ADAU1451/1452 builds, I2C/SPI programming headers for USBi/freeUSBi-style programming, master/slave SPI expansion connectors, and space for self-boot EEPROM.

**Why it matters**  
This is a useful, cleanly documented reusable DSP core board rather than a single finished instrument. It is especially valuable as a reference for SigmaDSP-based audio boxes, standalone effects processors, active crossovers, multi-channel synth FX, and modular audio-DSP hardware.

**Implementation highlights**

- ADAU145x SigmaDSP core with self-boot capability.
- 4 digital audio input connectors and 4 output connectors supporting I2S/TDM/left-right-justified modes.
- Optical and coaxial S/PDIF input/output options for ADAU1451/ADAU1452.
- I2C/SPI programming connector compatible with Analog Devices USBi-to-EZ-Board style tools and freeUSBi-like alternatives.
- Master/slave SPI connectors for use with other OHDSP boards.
- Repository structure includes BOM, schematic PDFs, PCB drawings, Gerbers, drill files, and original KiCad design files.

**Hardware/electronics notes**

- **Editable CAD/source present:** README states original KiCad schematic and PCB design files are included.
- **Schematic present:** PDF schematic and KiCad schematic source claimed.
- **PCB source present:** KiCad PCB source claimed.
- **BOM/production files:** BOM in CSV/LibreOffice/XML formats; Gerber/drill files; PDF/SVG drawings.
- **License:** TAPR Open Hardware License.

**Platform relevance**  
Strong reference for reusable DSP/audio-core hardware. It is less compelling as a direct synth/groovebox find because it has no built-in UI/control surface, but it is very relevant as a core board for a product-level audio processor.

**Adaptation ideas**

- Pair with a Teensy/RP2350/STM32 UI board over SPI/I2C for a programmable pedal or desktop effects box.
- Use as a multi-channel digital insert processor or Eurorack/mixer auxiliary DSP module.
- Build a SigmaStudio-programmable fixed-function synth FX/filter box.
- Mine the OHDSP ecosystem for matching ADC/DAC/power boards and compose a complete modular audio stack.

**Quick engineering assessment**  
Promoted because the documentation and source-hardware discipline are much better than most small audio repos. It is a clean core-board reference, but not a complete self-contained instrument.

**Caveats / verification gaps**

- No standalone UI/control surface in this repo.
- SigmaStudio/freeUSBi workflow is powerful but less hackable than fully open firmware on MCU/DSP targets.
- Related OHDSP ADC/DAC/power boards deserve a separate ecosystem inspection before treating this as a full product stack.

**Sources**

- <https://github.com/ohdsp/DSP-ADAU1452>
- <https://github.com/ohdsp/KiCad-Libs>
- <https://github.com/ohdsp/ADC-PCM4202>
- <https://github.com/ohdsp/DAC-ADAU1966>

### 3) [Papproni/stm_audio_board_v3_dsp_board](https://github.com/Papproni/stm_audio_board_v3_dsp_board) — **PASS**

**Technical summary**  
A KiCad hardware repository for an STM32H723-based digital effects pedal DSP board. It has a hierarchical schematic structure covering power, MCU, footswitch, connectors, output stage, codec, filters, input stage, display interface, potentiometers, tap tempo, and audio connectors. The BOM indicates a relatively ambitious board with dual STM32H723ZGTx MCUs, SDRAM, SPI flash, USB hub, audio op-amps, isolated DC/DC modules, six pots, switches, display/footswitch headers, input/output jacks, and three loop send/return paths.

**Why it matters**  
The docs are weak, but the hardware density is high. This is useful as a reference for STM32H7 pedal/instrument hardware partitioning: codec + MCU + display + pots + footswitch + loop routing + isolated power. It is closer to a custom digital pedal platform than many firmware-only finds.

**Implementation highlights**

- Hierarchical KiCad schematic with separate sheets for power, MCU, codec, input/output, filters, display, footswitch, connectors, and potentiometers.
- BOM with LCSC part numbers and production-oriented footprints.
- Dual STM32H723ZGTx listed in BOM, plus SDRAM, SPI flash, and FE1.1s USB hub.
- Multiple 6.3 mm TRS audio jacks including input, output, and three loop send/return paths.
- Six potentiometers, switches, display connector, footswitch connector, ST-Link headers, and audio op-amp stages.
- MIT-licensed repository.

**Hardware/electronics notes**

- **Editable CAD/source present:** KiCad schematic source verified.
- **Schematic present:** yes — many `.kicad_sch` sheets verified.
- **PCB source present:** **not verified** — attempted fetch of the likely `.kicad_pcb` path returned empty content, and search did not surface a populated PCB source file.
- **BOM/production files:** CSV BOM verified with component designators, footprints, and LCSC part numbers.
- **Firmware/build path:** not verified.
- **License:** MIT, per repository metadata/page.

**Platform relevance**  
Useful as an STM32H7 effects-pedal hardware reference. Especially interesting for audio loop routing, dual-MCU partitioning experiments, and physical control/display integration. It should not be treated as fabrication-ready until PCB and firmware are verified.

**Adaptation ideas**

- Extract the audio jack/loop-routing and control-surface partitioning into a cleaner single-MCU DSP pedal board.
- Rebuild the concept around Daisy Seed/STM32H7/Teensy 4.x with a verified codec and known firmware path.
- Reuse the BOM as a quick starting point for connectors, isolated DC/DC, audio op-amp stages, and UI parts.
- Audit the dual-MCU architecture: decide whether it is necessary or overcomplicated for a real product.

**Quick engineering assessment**  
Promoted for hardware density and schematic/BOM value, not for build readiness. It is a good mine, but lower-confidence than the top two due missing README, missing firmware, and unverified PCB source.

**Caveats / verification gaps**

- No README found.
- No firmware path verified.
- PCB file content was not verified; likely absent, empty, or not indexed.
- Architecture may be overcomplicated; dual STM32H723s need justification.
