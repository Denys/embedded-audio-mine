### 1. RP2350 Audio Integrity & Productization Sprint

**Verified:** PRA32-U2 v2.20.0 is a four-voice RP2350 synth with 48 kHz / 24-bit I2S, USB + UART MIDI, prebuilt UF2, a Web MIDI editor, and explicit hardware/toolchain compatibility notes. v2.19.0 reports latency improvement from 5.3 ms to 2.7 ms. The README also documents a PWM-audio discontinuity roughly every 80 ms and a Waveshare Pico-Audio revision compatibility issue.

**Inference:** small audio-device developers need a bounded qualification service covering I2S clocking, DMA/PIO scheduling, USB/MIDI contention, mute/pop, DAC choice, analogue output, clock/overclock policy and long-run dropout detection.

**Estimate:** CHF 1.2–2.5k fixed audit, CHF 2.5–5.5k remediation, CHF 15–50k/year plausible specialist revenue if packaged rather than sold as generic embedded consulting.

**Risks:** overclock assumptions, Arduino-Pico churn, DAC/module variance, incomplete analogue measurements, and confusing average throughput with worst-case audio integrity.

**7-day action:** create `RP2350-AUDIO-QUAL-001` and one reproducible Pico 2 + PCM5102A benchmark covering latency, dropout count, mute/pop, USB-MIDI stress, idle FFT/spurs, level/headroom and 30–60 minute soak.

### 2. Eurorack CV/Gate Front-End Qualification Pack

**Verified:** BirdsBoard uses RP2350A + PT8211 and publishes a Eurorack hardware/firmware architecture with four -5 V..+5 V CV inputs and a gate input; hardware is CERN-OHL-S v2 and firmware LGPL-3.0. The current Ghost In Translation Drone repository uses Pico 2/RP2350, but its `hardware/` directory still contains only a placeholder while firmware source + UF2 are present.

**Inference:** there is a clean service niche around bipolar CV scaling, ADC protection, gate hysteresis, calibration, anti-alias/settling, digital feedthrough, ESD/fault cases and repair/test points.

**Estimate:** CHF 1–2k audit, CHF 1.8–3.5k audit+measurement, CHF 3–7k reference design.

**Risks:** inconsistent Eurorack voltage conventions, protection leakage/error, calibration masking topology mistakes and ground/noise problems.

**7-day action:** define `CVIO-REF-A`: four bipolar CV inputs, two gate inputs and two CV outputs with an explicit error/clamp/calibration budget.

### 3. Cross-Target DSP Parity CI Pack

**Verified:** Daisypatcher v0.5.6 was published 2026-08-18. Its node model pairs a WebAudio worklet with a C++ emitter, and its documented test stack includes snapshot, contract, feature, compile and audio-parity checks between the emulator path and compiled Daisy firmware run on host.

**Inference:** this is productizable as a vendor-neutral service: portable DSP core -> host renderer -> embedded adapter -> golden vectors -> CI tolerances. It complements, rather than repeats, the prior desktop-twin idea by selling **parity evidence** as the deliverable.

**Estimate:** CHF 1.5–3k setup, CHF 3–6k full parity CI, CHF 200–700/month maintenance.

**Risks:** compiler/FP differences, poor tolerance design, licensing mistakes and treating functional parity as proof of real-time timing.

**7-day action:** put one delay block through host + Daisy builds and generate golden WAV + parameter trace + pass/fail tolerances.

### 4. Sampler Storage & Power-Loss Reliability Sprint

**Verified:** VAMP appeared on 2026-08-19 as a Daisy Seed 3 portable sampler/synth project. The repository contains KiCad PCB/schematic, BOM, Production and Firmware directories, and GPLv3 licensing. The author explicitly states that the physical sampler is still needed to validate the in-development firmware/looper.

**Inference:** boutique samplers and loopers have a recurring reliability gap around SD/QSPI/SDRAM partitioning, sustained write stalls, filesystem recovery, brownout/power-loss handling and coexistence of assets, presets and firmware updates.

**Estimate:** CHF 1.2–2.5k audit, CHF 2.5–6k integration, CHF 0.8–2k test fixture.

**Risks:** SD-card variance, rare corruption paths, write-latency tails and test duration.

**7-day action:** create `SAMPLER-STORAGE-001` with randomized power cuts during 1/5/10-minute recordings and slow/fast SD-card stress.

### 5. Bounded Local-AI DSP Graph Assistant Integration

**Verified:** Daisypatcher's assistant edits the graph rather than source code, validates proposed edits against the node catalog, and supports local Ollama by default with optional cloud providers.

**Inference:** the useful commercial angle is not "AI writes DSP". It is a constrained engineering assistant that proposes only schema-valid graph mutations and cannot bypass deterministic validation.

**Estimate:** CHF 2–4k PoC, CHF 4–10k product integration, CHF 200–800/month maintenance.

**Risks:** syntactic validity is not sonic or real-time validity; privacy/cloud issues; AGPL obligations if Daisypatcher application code is incorporated rather than used as architectural reference.

**7-day action:** build a 10-node local `SynthHarnessGraphAssistant` schema and an adversarial test set whose invalid edits must always be rejected.
